## 7. Codex / ChatGPT 开工规则

每次开始或继续开发：

1. 先读本看板；
2. 再读相关业务规则和工程规则；
3. 读取当前 main、开发分支和 PR 的真实状态，不按聊天记录猜代码；
4. 判断任务属于 P0/P1/P2；
5. 做 Build vs Reuse；
6. 优先解决当前 P0，不擅自扩 scope；
7. 可自动验收的内容必须补自动测试；
8. 每完成一个相对完整阶段，都自动判断是否应该合并 main；
9. 完成后更新本看板和必要的技术决策记录。

## 8. 自动判断是否应该合并 main

出现以下任一情况必须主动判断当前 PR 是否应收口：

- 一个相对完整产品阶段开发完成；
- PR 已明显变大，继续叠加会增加回归风险；
- 自动测试、Frontend QA、Preview 已具备完整验收条件；
- 准备开始边界清晰的新功能；
- 产品负责人连续要求“继续”时，不能只无限堆代码。

原则上同时满足以下条件时，应主动提示：**“当前 PR 已达到可合并状态，建议合并 main。”**

1. 当前阶段范围完整，无必须同 PR 完成的阻断项；
2. 后端 / 单元测试通过；
3. Frontend QA 通过；
4. Preview Deploy 成功；
5. Preview 核心业务无阻断回归；
6. 无已知高风险数据、权限、安全或生产配置问题；
7. 后续工作可以自然拆到新 PR。

如果未达到门槛，必须明确说明还差哪一项。

达到门槛后只**建议**合并；不得自行合并。必须收到产品负责人明确“可以合并 / 合并 main / 上线”等授权后才执行。合并后继续核对 main QA、正式部署和 Production 健康检查。
