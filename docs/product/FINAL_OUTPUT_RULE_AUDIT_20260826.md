> 范围：一句话 IP、推荐昵称、推荐简介。目的：重写唯一 Owner 后，逐条核对当前最高有效需求，禁止以当前代码反推需求。

## 1. 一句话 IP / Slogan

Owner：`web/ip-policy-core.js::headline()`。

已核对并锁定：

- 单一 canonical `proposal.headline`；IP 方案顶部与两平台简介复用同一值。
- 禁止姓名/昵称进入 slogan。
- 禁止 `｜` / `|` 标签墙。
- 禁止 `XX是我的标签 / XX是我的专业底色 / 做一个让人记得住的人`。
- 禁止 `本科，MDRT` 等学历/荣誉字段墙。
- 只使用真实证据；数字必须能在原资料中找到。
- 无证据禁止 `0人脉 / 擅长 / 懂XX / 专家 / 导师 / 顾问 / 多年 / 长期`。
- 增加强事实竞争：数字经历 > 转型/跨界 > 荣誉 > 学历/资质 > 稳定评价 > 生活身份 > 兴趣。
- `primaryGoal` 作为候选排序上下文：增员更重经历/转型/荣誉，拓客可适当提高真实家庭身份，但不强制把业务词塞进 slogan。
- fallback 只在真实事实内做自然组合，不再按固定字段顺序机械拼接。

## 2. 推荐昵称

Owner：`web/nickname-policy-v1.js`。

已核对并锁定：

- 执行顺序：人工首选 → 人工备选 → 受控自然候选 → DeepSeek 受控兜底。
- 人物锚点事实来源：客户/身边人高频真实称呼 → 本人明确希望使用的称呼 → 已有昵称稳定人物锚点 → 长期英文名 → 本名/自然两字以上姓名片段。
- 高频称呼同频时继续按公开自然度、亲和力、记忆/输入成本等排序，不只按数据库原顺序。
- 二字姓名禁止无证据截单字；三字以上自然两字片段仅低优先级兜底。
- 过往职业、学历、城市、荣誉不作为新昵称生成路线。
- 当前持续生活身份、真实兴趣、鲜明反馈可作为记忆点；不得编造。
- 成熟原昵称若自然、合规、有特色、有用户记忆，优先保护；万能尾缀惩罚不得误伤成熟原昵称。
- 万能模板不作为批量默认路线；纯姓名/真实称呼路线不占满 3–5 个推荐位。
- 新生成/人工预设/原昵称进入推荐前统一去 Emoji、特殊符号、装饰字符和末尾装饰标点；明确覆盖 `洢萱卍 → 洢萱`。
- 全英文不作为首选，但长期真实英文人物锚点允许作为最后兜底，不再一刀切全部删除。
- 推荐理由只解释昵称为什么好，不展示产品负责人、人工验收、排序权或 AI fallback 内部逻辑。
- `product-rules-v29.js` 只做原昵称审查展示，并明确提示特殊符号/Emoji、纯英文等问题；不写 `proposal.nicknameOptions`。
- 保留“AI 推荐仅供参考，本人长期喜欢且有特殊含义的昵称可能更适合”的用户提示。

## 3. 推荐简介

Owner：`web/ip-policy-core.js::buildBios()` / `bioBody()` / `complianceFooter()`。

已核对并锁定：

- 每个平台只一套最终推荐版：小红书 1 套；视频号/抖音共用 1 套。
- 正文围绕三个维度：我是谁 / 我的优势 / 我能提供什么价值；各维度允许 1–3 行。
- 只用 A/B/C 级真实证据，模糊领域词不得升级为职业经历。
- 本人明确 strengths/traits/personality、多人客户反馈、个人介绍中的明确事实均可进入资产；客户评价只显示结论，不显示系统解释前缀。
- 兴趣只从明确 hobbies/interests 或个人介绍中直接出现的受控兴趣提取，不把“内容支线”自动升级成本人兴趣。
- 取消旧机械数量上限：不再 `interests.slice(0,2)`、`honors.slice(0,2)`、`traits.slice(0,2)`；只受每维度 1–3 行、真实性、价值和平台空间约束。
- 跨行语义去重与强事实优先：数字/明确事实优于长期/多年模糊概括；不同资质/荣誉不因同领域误删。
- 明确时间精度：`7年多 / 7年+ → 7年+`；只有原资料明确“多年”才写多年；无时间证据不创造长期/多年。
- 单行有效宽度优先 12–20，21–25 只在语义完整时允许，25 绝对上限。
- 同一行只合并同一核心维度；不为了填满一行跨维度拼接。
- `packDimension()` 使用最多 3 行的合法分区和长度平衡评分；当有足够真实素材时优先拆成更多合格正文行，避免把所有优势压成一行。
- 如果真实素材不足以形成 12 字等效有效行，宁可少于 3 行，也不加空话/无证据标签。
- Emoji 按行内容语义选择：学历、荣誉、经历、茶/咖啡、运动、阅读、家庭身份、服务价值分别使用匹配视觉锚点；同一简介不重复，`👤` 禁止用于简介。
- `proposal.headline` 位于人物正文之后、固定合规声明之前，并保留独立 Emoji；简介不二次改写 headline。
- 小红书和视频号/抖音人物信息默认同源；仅明确平台合规差异允许过滤/改写敏感业务词。
- 固定合规尾部逐字、顺序、换行保持；营销员编号不得冒充执业证编号。
- V10 已撤销简介文本写权限，只保留合规 `?`、复制提醒和弹窗，禁止 render 后再次过滤正文。

## 5. 本轮审计发现并修复的遗漏

1. 昵称特殊符号 `卍` 因处于 CJK 范围未被普通正则清理。
2. 昵称同频真实称呼缺少二级自然度排序。
3. 长期英文名人物锚点来源遗漏；全英文被错误“一刀切”。
4. 成熟原昵称可能被万能尾缀扣分误伤。
5. 昵称理由无证据使用“长期兴趣”。
6. 简介机械数量上限在重写代码中复活。
7. `7年多 / 7年+` 被错误降级成 `7年`。
8. 简介跨行语义强弱去重未完整实现。
9. 简介行长再平衡/多行合法分区未完整实现。
10. 内容支线被错误直接当成本人兴趣。
11. Emoji 机械按行号分配而非语义匹配。
12. 本人明确 strengths/traits/personality 未完整进入简介资产。
13. headline fallback 未真正执行强事实竞争和目标上下文排序。
14. V10 曾在 render 后二次过滤简介，造成正文被删到只剩合规声明；已撤销文本写权限。
