# AIA Auto IP 最新有效需求总账（2026-08-25）

> **当前最高产品事实源。** 本总账不是把历史需求机械叠加，也不以当前代码倒推需求。
>
> 判定原则：**最新明确确认的需求覆盖冲突维度；新需求未修改的旧维度继续有效；专项规则负责被总账保留/委托的细节；已经正确实现的功能保持不动；曾正确实现后回归的效果迁回当前唯一 Owner；从未完整实现的有效需求必须补齐。**

## 0. 需求版本判定方法

事实源优先级：

1. 本文件 `CURRENT_EFFECTIVE_REQUIREMENTS_LEDGER_20260825.md`；
2. 本文件明确引用/委托的专项规则；
3. `CURRENT_PRODUCT_RULES_BASELINE_20260824.md` 中未被本总账覆盖的维度；
4. 更早产品设计中未被后续需求覆盖的维度；
5. 历史 Preview / 代码只能证明某效果曾实现，不能覆盖产品需求。

冲突处理：

- 后续明确意见覆盖相同维度，旧规则标记 `SUPERSEDED`；
- 后续意见只修改一个维度，其他旧维度继续有效；
- 专项规则若明确写“补充并更新某旧规则，冲突以本文件为准”，且后续总账/Baseline 未再次否定，则专项规则是该维度当前细节源；
- 只有无法通过时间、明确确认和覆盖维度判断时才提交产品负责人确认，不自行折中。

## 5. 推荐昵称

### 最新有效需求

- 每个最终昵称必须有且只有一个人物称呼主体。
- 称呼来源优先：客户反馈高频真实称呼 > 本人明确希望使用的称呼 > 已长期使用昵称中的稳定人物锚点 > 姓名自然亲和称呼 / 本名兜底。
- 客户反馈同频时按公开自然度、亲和力、记忆度、发音输入、真实姓名关联等排序。
- “无 / 暂无 / 没有”等识别为缺失值，绝不能建议保留。
- QS 前100、985/211、留学层级不得推断具体学校/国家。
- 真实人物资产可以来自身份/职业、经证实性格、地域、专业经历、学历层级、真实成就、中性内容方向。
- 人物资产不能变成标签墙：禁止机械 `成都+称呼`、`TOT+称呼`、`985+称呼`、`有温度+称呼`。
- 受控策略优先，AI 仅在受控候选不足时兜底，仍必须通过人物称呼、事实、合规和非机械拼接围栏。
- 原昵称先谨慎审查；自然、好记、合规、有稳定识别时优先建议保留；多个问题按 1/2/3 解释，不武断否定。
- 推荐通常给 3–5 个不同路线；保留“AI 推荐仅供参考，本人长期喜欢且有特殊含义的昵称可能更适合”的短提醒。

### 版本关系

- `rules/nickname-source-ranking-v1.md` 规定真实称呼来源排序；其中早期示例“成都涛哥”等机械地域拼接已被后续 Baseline 的明确禁令覆盖。
- `docs/昵称受控词库与模板-V1-20260824.md` 保留六类人物资产与证据规则；其机械模板示例受后续 Baseline 限制。

### 实现 / 测试状态

- `nickname-policy-v1.js` 已补齐高频称呼、本人称呼、原昵称人物锚点、职业/家庭身份、受控性格、地域、学历层级、成就、内容支线和受控 AI fallback。
- 已加入机械资产+称呼拒绝逻辑和无人物锚点空态。
- **状态：✅ 结构性缺口已补；🟡 需真实样本验证候选自然度、3–5 个路线质量与原昵称审查体验。**

## 7. 内容方向：保险主线 / 内容支线

### 最新有效需求

- 板块名称统一为“内容方向”。
- 保险主线与内容支线严格分开。
- 拓客保险主线只能来自受控保险业务主题；增员使用增员与职业发展主线。
- 健康养生、育儿、美食、读书、旅行、智能家居、运动等不得进入保险主线。
- 内容支线综合家庭/生活身份、过往职业、个人介绍、爱好、客户反馈、口头补充等真实证据。
- 未收录新方向不得因词库缺失直接丢弃，应进入统一评分。
- 多来源一致证据提高可信度和优先级；排序结合业务价值、客群、持续输出、真实性，并按拓客/增员调整。
- 最终优先保留一个真实、长期可讲、业务价值更高的内容支线。
- 展示保留：内容方向、合集推荐、对账号的作用、来源、内容聚焦提醒，并提供跳转推荐脚本入口。

### 实现 / 测试状态

- V14 已实现未知方向、证据累计、多来源 bonus、目标 bonus；Core 唯一写最终支线；V20 负责展示信息层。
- **状态：✅ 结构对齐；🟡 仍需固定真实样本检验业务排序质量。**

## 8. 推荐简介

### 最新有效需求

- 简介回答“我是谁 / 我有什么优势 / 我能带来什么”。
- 只使用 A/B/C 级真实证据：报名明确事实、本人自我介绍明确事实、多人客户反馈；AI 推断不得作为事实。
- 素材包括个人介绍、过往职业、家庭身份、学历、从业年限、真实荣誉、客户反馈、真实服务、标准化保险主内容方向；地域、1–2 个兴趣仅在有定位价值时使用。
- 从人物资产池选择 3–5 个最有价值信息形成自然语言，不是字段标签墙。
- 三个版本分别走：专业背书 / 人设记忆 / 价值服务；不能只替换少量词。
- 自动删减同义身份/性格、过多荣誉、过多兴趣、重复事实；服务最多 3–4 项并必须来自真实资料。
- 保险始终是主内容；生活兴趣只作次要人设。
- 保留成熟 Emoji 视觉锚点，但 Emoji 不能掩盖信息不足。
- 合规尾部只有 `complianceFooter` 一个 Owner：小红书固定个人意见声明；视频号/抖音按“个人意见声明 → 营销服务部 → 执业证编号”，每项一次；营销员编号不得冒充执业证编号。

### 实现 / 测试状态

- Core 已升级为人物资产池 → 价值排序 → 三策略 → 同义删减/次级资产控制 → 平台过滤 → 唯一 footer。
- 地域/兴趣只在更强资产不足或记忆策略中补位；服务仍从真实服务字段受控映射。
- Prompt 已取消固定 footer 生成权，只提供正文草稿素材。
- **状态：✅ 结构性缺口已补；🟡 需真实丰富资料验证信息密度、三版差异、自然度和平台合规效果。**

## 10. 脚本推荐

### 有 IP 方案

- 前台只分“保险主线 / 内容支线”两个板块，保险主线在前。
- 读取与 IP 方案相同的标准化主线/支线，不自行重算归属。
- 同批脚本不可重复，不为填满数量跨到明显无关脚本。
- 每个板块独立“换一批”；不足两批时禁用并说明。
- 展示用户本地当天日期 / 今日推荐。

### 无 IP 方案

- 可浏览完整脚本库，不能空白。
- 一级标签 → 对应二级标签；真实分页能遍历全部脚本。
- 电脑/平板两列、手机一列。
- 顶部提示完成 IP 可获得更精准推荐并可跳转。

### 更早设计中继续有效的未冲突维度

- 列表默认第一标题；热点有标识；一级/二级标签、字数、预计口播时长同一行。
- 推荐阶段显示脚本库原始内容，不偷偷改写。
- 行为记录：曝光、详情点击、点击脚本改写、点击小红书排版。

### 实现 / 测试状态

- `script-recommendation-v1.js` + V21 已覆盖两板块、去重、今日推荐、换一批、无 IP L1/L2 和真实分页。
- `impression / detail_click / rewrite_click / xhs_click` 四类行为均已有记录入口。
- **状态：✅ 静态结构对齐；🟡 需真实 API、空库、少量脚本、多页脚本动态测试。**

## 12. 智能脚本改写

### 最新有效需求

- 保留原文事实、知识点、数字、核心结论，不随意修改专业事实。
- 默认输出 3 篇明显不同的完整改写稿；多标题时分别处理。
- 人设代入不只是称呼，还包括真实定位、目标人群、优势、经历、荣誉及账号表达风格；仅在相关时自然代入，不强行编个人经历。
- “稿件处理说明”明确说明 IP / 账号表达风格代入情况。
- DeepSeek 格式异常自动重试/宽容解析，不把重新粘贴原文成本交给用户。
- 可复制正文不混入分析、版本说明、内部标签或 `#标签`；标签单独 10–15 个，前 5 个重点。
- 结果后给发布前人工微调提示。
- 用户明确“确认修改 / 按建议修改 / 重新改写”等，应立即触发新版本并继承本轮已确认修改意见。

### 实现 / 测试状态

- `backend/script_persona_rules.py` 读取 `contentTone/accountTone`，breakdown 明示账号表达风格，并有格式异常自动重试。

## 13. 小红书排版

### 最新有效需求

- 只做结构标记清理、换行、分段、Emoji 与风险提示，不修改、删除、替换正文真实文字和标点。
- 每段最多 2 个完整句子；长句按自然停顿换行；不得出现孤立标点/括号/引号。
- **Emoji 当前权威规则是 `rules/xhs-formatting-rules.md` V4（提交 2026-08-24 05:25）。该文件明确“补充并更新 `docs/脚本改写与小红书排版规则.md`，冲突以本文件为准”。因此旧文档中的 2–3 句节奏已经被替代。**
- 当前硬规则：整体目标平均每 1–2 句话至少一个表情锚点；任何连续 2 个完整句子中至少有 1 个表情；有明确语义时优先语义表情；并列结构可合理重复同一表情；避免表情墙。
- 等待态固定简洁为“正在排版，请稍候…”。
- 排版完成后给 10–15 个建议标签，正文外展示；风险检测只识别不改原文。
- 复制成功/失败反馈走公共 Clipboard。

### 版本关系

- `docs/脚本改写与小红书排版规则.md` 中“每 2–3 句话 1 个 Emoji / 最多连续 3 句”是较早规则。
- `rules/xhs-formatting-rules.md` V4 后续明确升级为“1–2 句 / 连续两句硬门槛”，因此前者在 **Emoji 密度维度** `SUPERSEDED`；原文保护、多段规则、标签、风险提示等未冲突部分继续有效。

### 实现 / 测试状态

- 后端原文字词保护继续存在。
- **状态：✅ 最新规则已纠正；🟡 需真实长文检查语义表情丰富度和并列结构体验。**

## 14. 通用 Composer / 多选 / 自动滚动

### 最新有效需求

- 聊天心智：问题 → 快捷项 → 同一输入框（已选标签 + 自由输入）→ 唯一发送按钮。
- 业务选择状态只能有一个真源。
- 视觉层不得维护第二套 `Set` 作为提交真源。
- 禁止隐藏确认按钮、延迟 `.click()`、DOM 文本回读模拟业务提交。
- 点击标签不主动拉起手机键盘；已选标签在输入框内部；上下取消同步。
- 多选 + 自由文本一次作为同一条用户消息提交；提交后清空并真实进入下一题。
- 桌面端选完标签可直接 Enter；手机端只有主动点击输入区才拉键盘。
