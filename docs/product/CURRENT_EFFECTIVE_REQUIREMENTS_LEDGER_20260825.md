## 0. 需求版本判定方法

事实源优先级：

1. 本文件 `CURRENT_EFFECTIVE_REQUIREMENTS_LEDGER_20260825.md`；
2. 本文件明确引用/委托的专项规则；
3. `CURRENT_PRODUCT_RULES_BASELINE_20260824.md` 中未被本总账覆盖的维度；
4. 更早产品设计中未被后续需求覆盖的维度；
5. 历史 Preview / 代码只能证明某效果曾实现，不能覆盖产品需求。

冲突处理：

- 后续明确意见覆盖相同维度，旧规则标记 `SUPERSEDED`；
- 后续意见只修改一个维度，其他旧维度继续有效；
- 专项规则若明确写“补充并更新某旧规则，冲突以本文件为准”，且后续总账/Baseline 未再次否定，则专项规则是该维度当前细节源；

## 5. 推荐昵称

### 最新有效需求（#104–#113）

- 每个最终昵称必须有且只有一个人物称呼主体。
- 称呼来源优先：**客户/身边人反馈高频真实称呼 > 本人明确希望使用的称呼 > 已长期使用昵称中的稳定人物锚点 > 本人长期英文名 > 本名/自然两字以上姓名片段兜底**。
- 客户反馈不仅用于称呼，也用于理解稳定人物印象、角色认知和内容方向；但评价词不得机械拼成“靠谱的XX”等昵称。
- **禁止随意截取姓名单字造昵称。** 没有真实称呼证据时，`张三→三`、`王一→一`、`李明→明` 均禁止；二字姓名默认使用全名兜底。
- 客户反馈同频时按公开自然度、亲和力、记忆度、发音输入、真实姓名关联等排序。
- “无 / 暂无 / 没有 / 0”等识别为缺失值，绝不能建议保留。
- QS 前100、985/211、留学层级不得推断具体学校/国家。
- **过往职业只进入简介、IP 一句话定位和内容理解，不进入新生成推荐昵称。** 禁止 `地产人成涛 / 财务人宋雨阳 / 精算人贾正佳 / 前广告人张蕊` 等把历史职业继续当当前昵称身份的路线。
- 当前仍持续成立、资料有明确证据的生活身份、兴趣、内容特点可以参与昵称，例如二孩爸爸、健身、八块腹肌、手帐、攀岩、滑雪、网球、读书等；不得为了网感编造。
- 昵称必须通过中文口语自然度门禁：禁止动作标题句（如 `yana打网球`）、同一人物主体重复（如 `王一的一一世界`）、事实正确但像字段拼接的名字。
- `XX的小世界 / XX的日常 / XX聊生活 / XX看世界` 等万能模板不作为批量默认路线；已有长期使用且自然的原昵称可以保留。
- 每人通常推荐 3–5 个真正不同路线；**纯姓名、真实称呼及其极简变体合计最多 2 个**。没有足够好的创意时宁缺毋滥，不用多个叫法或万能尾缀凑满 5 个。
- **#111 首选不默认本名/纯称呼。** 当前用户并非依靠公众知名度让本名天然形成记忆；如果存在真实鲜明、当前仍成立的兴趣/生活/内容特点，应优先推荐更有辨识度、有记忆点、有网感的自然昵称。
- **#112 有证据的鲜明修饰语可优先于裸称呼。** 修饰语优先来自客户/身边人反馈或本人资料中已经自然出现、能够真正增强辨识度的短表达；普通“靠谱 / 专业 / 真诚”等不能机械套成前缀。例如何靖真实称呼为“流火”，反馈里自然出现“有料有趣”时，`有料有趣的流火` 优先于单独 `流火`。
- **#113 中文可记忆、可搜索优先。** 新生成昵称默认不使用 Emoji、特殊符号、花体字符、繁体装饰字符或无意义数字尾缀；全英文昵称原则上不作为首选，普通中文用户难记、难输入、难搜索。中英混合可以保留，但中文部分必须承担人物记忆或语义识别，例如 `兔子Nici / 宽婷Kitty`。
- 已有全英文原昵称也要与中文可记忆性比较，优先给出中文或中英混合优化版。`TotoroFelix` 不再默认首选；如客户已有真实称呼“龙猫”，优先考虑 `咖啡龙猫 / 网球龙猫 / 龙猫Felix / 龙猫` 等更易记、易搜的路线。
- 特殊符号和装饰标点在推荐版本中去掉，例如 `洢萱卍 → 洢萱`、`奶里奶气霸王龙. → 奶里奶气霸王龙`。
- 首选优先级：`已有且自然合规、有特色、中文可记忆/可搜索、有用户记忆的原昵称 > 有证据的记忆点修饰语 + 真实称呼/本名 > 真实称呼/本名 + 有记忆点的当前兴趣或特点 > 其他有证据的自然差异化昵称 > 真实称呼极简版 > 单独本名 > 全英文昵称兜底`。
- 例如刘畅资料明确有“多年健身、八块腹肌”时，`八块腹肌刘畅 / 刘畅练起来` 优先于单独 `刘畅`；但 `飞行员刘畅` 仍禁止，因为飞行员是过往职业。
- 原昵称先谨慎审查；自然、好记、合规、有特色、有稳定识别时优先建议保留，但全英文、特殊符号、Emoji、品牌词、无意义数字等会降低保留优先级；多个问题按 1/2/3 解释，不武断否定。
- 受控策略优先，AI 仅在受控候选不足时兜底，仍必须通过人物称呼、事实、合规、自然度、非机械拼接、中文可记忆/可搜索和 #108–#113 围栏。
- 保留“AI 推荐仅供参考，本人长期喜欢且有特殊含义的昵称可能更适合”的短提醒。
- 详细规则委托 `rules/nickname-naturalness-rules-20260825.md` 与 `rules/nickname-source-ranking-v1.md`。

### 版本关系

- `SUPERSEDED`：没有真实称呼证据时从姓名中随意截一个字生成昵称。
- `SUPERSEDED`：把过往职业直接作为当前昵称身份，或加“前”继续作为默认昵称路线。
- `SUPERSEDED`：默认把纯本名/纯称呼作为首选，只因其最安全简洁。

- `SUPERSEDED`：推荐昵称保留特殊符号、Emoji、装饰字符或无意义数字尾缀。
- `rules/nickname-source-ranking-v1.md` 规定真实称呼来源排序；其中早期示例“成都涛哥”等机械地域拼接已被后续禁令覆盖。

## 6. 一句话 IP 定位 / Slogan

### 最新有效需求（#103）

- 这句话不是普通业务介绍或标签墙，而是**一句浓缩版自我介绍 / slogan**：用一句话说明“我最不一样、最有吸引力、最值得被记住的地方”。
- 生成逻辑是：**做账号的目的 × 我的不同之处 × 目标人群关注的内容 → 我的 IP**。
- 从报名资料、个人介绍、客户反馈等真实证据中竞争选择 **2–3 个最强记忆点**；候选可来自家庭/生活身份、明确职业经历、具体年限、学历/专业资质、真实荣誉、客户反馈、兴趣/生活特点、已证实内容能力、真实转型经历、账号目标与目标人群。
- 素材优先级：`稀缺且具体事实 > 有数字的经历 > 有证据的强反差/转型 > 专业资质/荣誉 > 多人反馈稳定特点 > 有记忆点生活身份 > 普通兴趣 > 泛化形容词`。
- 只使用 A/B/C 级真实证据；没有证据不得生成“0人脉 / 多年 / 擅长 / 懂XX / 专家 / 导师 / 顾问”等判断。
- 有明确数字时保留数字精度，不把强事实降级成“长期 / 多年”等模糊概括。
- 不要求把“我是谁 / 我的优势 / 我能提供什么价值”全部塞进一句话，只保留最强的 2–3 个点。
- 不包含人物姓名/昵称锚点；自然中文、响亮、可记忆，不使用“从XX跨界，用自己的经验讲清……”等机械模板。
- **禁止使用 `｜` 或 `|`。** 只使用自然中文标点，如 `，`、`、`、`！`，也可以在自然情况下不使用标点。
- 为保证 IP 方案顶部和两平台简介逐字一致，headline 必须是一份 canonical 单一事实源；**IP方案顶部 = 小红书简介合规声明前一句 = 视频号/抖音简介合规声明前三行之前的最后一句**。
- headline 在唯一 Owner 的生成/校验阶段统一控制；进入简介后不得再次截短、改写或重新生成。
- 因小红书简介同样要复用该 headline，运行态 headline 必须通过共同可用的合规围栏；平台业务主线仍可在 IP 方案其他字段中明确表达，不要求 slogan 必须出现“保险”等敏感词。
- 详细规则委托 `rules/ip-headline-slogan-rules.md`。

### 版本关系

- `SUPERSEDED`：固定“从XX跨界，用自己的经验讲清家庭保障与长期规划”等职业模板。
- `SUPERSEDED`：一句话定位必须机械塞入“最强差异点 + 保险主内容价值”并导致口号像业务说明；当前以最强记忆点和自然 slogan 为优先，保险主线仍由 IP 方案内容方向保证。
- `SUPERSEDED`：headline 与简介中的 slogan 分别生成或分别改写。

- `web/ip-policy-core.js::headline(profile,candidate)` 是唯一 Owner；优先校验 DeepSeek 基于真实资料生成的自然 slogan，不合规/含竖线/含未证实数字或敏感判断时回退到确定性事实组合。
- `enforceProposal()` 只生成/确认一次 canonical `proposal.headline`；两平台 `buildBios()` 均复用同一个 slogan，并固定插在人物正文与合规声明之间。

## 7. 内容方向：保险主线 / 内容支线

### 最新有效需求

- 板块名称统一为“内容方向”。
- 保险主线与内容支线严格分开。
- 拓客保险主线只能来自受控保险业务主题；增员使用增员与职业发展主线。
- 健康养生、育儿、美食、读书、旅行、智能家居、运动等不得进入保险主线。
- 内容支线综合家庭/生活身份、过往职业、个人介绍、爱好、客户反馈、口头补充等真实证据。
- 未收录新方向不得因词库缺失直接丢弃，应进入统一评分。
- 多来源一致证据提高可信度和优先级；排序结合业务价值、客群、持续输出、真实性，并按拓客/增员调整。
- 最终优先保留一个真实、长期可讲、业务价值更高的内容支线。
- 展示保留：内容方向、合集推荐、对账号的作用、来源、内容聚焦提醒，并提供跳转推荐脚本入口。
- “合集推荐”的合集名称前台统一使用中文书名号，例如 `《家庭保障》`、`《育儿手记》`。

## 8. 推荐简介

### 最新有效需求

- 简介始终围绕三个问题组织：**我是谁 / 我的优势 / 我能提供什么价值**；三个维度均可根据资料丰富程度使用 **1–3 行**，不要求平均分配。
- 简介不是口播脚本或自我介绍文章；表达必须高度概括、凝练、信息密度高。能用更短表达准确说明同一事实时优先更短表达，例如“硕士学历”优先写“硕士”。
- 只使用 A/B/C 级真实证据：报名明确事实、本人自我介绍明确事实、多人客户反馈；AI 推断不得作为事实。
- **自媒体运营经验仅作为内部背景信息，用于理解学员的运营基础，不属于面向客户展示的人设资产。账号运营时长、平台、粉丝量、播放量、作品量、咨询量、留资量，以及通过自媒体获得的客户转化、成交、增员等自媒体运营数据，均不得进入推荐昵称、一句话 IP、推荐简介，也不得参与这三类输出的强事实竞争；无论数据高低均按此规则执行。仅当“媒体/内容”本身是用户真实职业身份或明确职业经历（如主持人、记者、媒体从业者），而非账号运营成绩时，才可按职业事实规则参与一句话 IP / 简介；过往职业仍不得机械进入新昵称。**
- 必须区分 `原始字段 → 已确认事实 → 简介允许表达`。模糊关键词不得升级成人物经历；资料只有“法律”时不得写“曾从事法律工作 / 法律行业背景 / 法务工作经验 / 法律专业人士”，只有明确法务/法律相关工作经历和年限时才可写如“6年企业法务工作经验”。
- 客户评价最终只呈现结论，例如 `靠谱｜细致｜有耐心`；禁止“客户高频评价 / 客户都评价我 / 大家眼中的我 / 多位客户认为”等系统解释式前缀。
- 取消机械减法：不再强制荣誉只留 1–2 个、职业经历只留一个、兴趣最多 1–2 个、服务最多 3–4 项。真实、有价值、有辨识度、合规且平台空间允许的信息尽量保留；仍删除重复、无证据、AI 推断、AI 套话、明显低价值和不合规内容。
- 每位用户最终只推荐 **2 套平台简介**：小红书 1 套最终推荐版；视频号 / 抖音 1 套共用最终推荐版。
- **除固定合规声明和明确的平台合规差异外，两平台人物正文默认使用同一套真实人物信息。** 某条信息若两个平台都合规，不得无故只保留在其中一个平台。
- **人物正文默认至少 3 行。** 只有真实资料确实不足、继续增加会导致重复、空话或事实推断时才允许少于 3 行；不得为了凑 3 行自动补“家庭保障 / 育儿经验 / 长期陪伴 / 家庭成长”等无证据价值标签。
- **每一行必须保持同一语义维度。** 先保证“我是谁 / 我的优势 / 我能提供什么价值”之一的语义一致，再追求空间利用率。禁止 `二宝妈妈｜跑步｜阅读`、`MDRT｜家庭保障｜二宝妈妈` 等跨维度硬拼。
- 经历、学历、荣誉、客户评价等子维度原则上保持清晰；但若单项过短、独占一行会浪费空间，可与同属“我的优势”且语义自然的信息合并。`财务中级职称`、`法学本科`、`MDRT` 等不得在有可合并信息时机械独占一行。
- **整份简介必须跨行语义去重。** 高度重复的两条信息保留更具体、更量化、更可验证的一条；优先级为 `具体量化事实 > 明确身份/经历/资质 > 明确荣誉 > 模糊概括 > AI总结`。例如 `10年建筑行业财务经验` 优先于 `长期财务管理经验`；`财务中级职称` 与前者不重复，可同时保留。
- **时间精度不得降级。** 原始资料有 `7年多 / 7年+` 时优先写 `7年+保险从业经验`；只有原资料明确写“多年”才能写“多年保险行业经验”；没有时间证据不得创造“多年/长期”。
- 人物正文采用“语义规则 + 行长门禁”：**优先 12–20 个汉字等效宽度**；21–25 仅在保持语义完整、无法自然压缩时允许；**25 是绝对上限**。少于约12时优先寻找同维度真实信息合并，不得靠空话凑字。
- Emoji、英文缩写、数字和标点按视觉宽度折算，不能机械按 Unicode 字符数计算。
- 同一份简介人物正文各行长度应尽量接近，避免一行接近上限、另一行仅4–6字的明显失衡；生成后执行行长再平衡。
- 每一人物正文行使用不同 Emoji；`👤` 从简介中淘汰，同一份简介人物正文不重复 Emoji。
- **#103：人物正文之后、固定合规声明之前必须插入与 IP 方案顶部逐字一致的 `proposal.headline`。** 该 slogan 不属于普通人物正文行，不参与 12–20 推荐区间、25 字红线、Emoji 或行长均衡算法，也不得在简介阶段二次改写。
- 小红书固定声明必须逐字为：`本账号所述内容为个人意见，不代表任何官方意见。`，位于整个小红书简介最后一句，一个字和标点都不得修改。
- 视频号 / 抖音固定合规尾部必须连续位于简介末尾，并严格按三行显示、顺序不变：
  1. `本账号上所陈述或表达的内容仅为我个人意见，并不代表友邦人寿的意见`
  2. `营销服务部：XXX`
  3. `执业证编号：XXX`
- 固定合规声明由 `complianceFooter()` 唯一 Owner 追加，完全不受人物正文 12–20 推荐区间、25 字绝对上限、最低信息量或行长均衡规则限制；营销员编号不得冒充执业证编号，缺失字段不得由 AI 编造。
- 保险仍是主要业务内容；生活/兴趣只能在有真实证据且有助于人设时出现，不能挤掉更高价值人物信息。
- 详细表达边界以 `docs/简介受控词库与模板-V1-20260824.md` 的 2026-08-25 最新确认版本为准；headline 细节以 `rules/ip-headline-slogan-rules.md` 为准。
