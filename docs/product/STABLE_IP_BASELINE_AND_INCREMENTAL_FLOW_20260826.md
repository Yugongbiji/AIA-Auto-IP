# 57 人稳定底稿与增量更新机制（2026-08-26）

## 目标

把已经人工验收的 57 人“一句话 IP + 推荐简介”作为稳定底稿。以后用户补充资料时，不从零覆盖，而是在稳定稿基础上做新增事实合并、语义去重、重新组合、质量门禁；只有新版本明确更好才升级当前版本。

## 数据分层

- `agents`：报名原始资料。
- `saved_profiles`：用户后续确认过的事实资料；只存人物事实，不存“当前最好文案”。
- `conversation_messages`：后续沟通原文，作为新增事实追溯来源。
- `proposals`：不可变的推荐方案版本历史。
- `current_ip_outputs`：每个营销员当前正式稳定版本的指针与完整输出。

任何后续资料更新不得直接覆盖 `current_ip_outputs`。

## 初次 57 人导入

人工验收 Excel 是一次性审核入口，不提交 GitHub。导入脚本：

```bash
python3 scripts/import_approved_ip_baseline.py /tmp/AIA_Auto_IP_57人推荐简介.xlsx
```

默认只 dry-run，必须先看到：

- `rows = 57`
- `matched = 57`
- `missing = []`
- `duplicates = []`
- `invalid = []`

确认后：

```bash
python3 scripts/import_approved_ip_baseline.py /tmp/AIA_Auto_IP_57人推荐简介.xlsx --commit
```

脚本在一个数据库事务内写入：

1. `proposals` 新版本，保留完整历史；
2. `current_ip_outputs` 指向该人工批准版本。

## 运行时读取顺序

目标状态：

```text
current_ip_outputs 有正式版本
  → 直接展示稳定稿
  → 不重新调用 AI

current_ip_outputs 无正式版本
  → 按当前最高规则生成候选
  → 质量门禁
  → 通过后才可成为当前版本
```

## 用户后续补充资料

```text
用户沟通原文
→ 识别明确新增事实
→ 用户确认
→ 写入 saved_profiles + 保留 conversation_messages
→ 与现有事实做语义去重
→ 只把真正新增/更强事实进入候选资产池
→ 生成新候选
→ 全规则 + 平台合规门禁
→ 与当前稳定版本比较
→ 只有更好才 promote
```

### 去重原则

优先保留：

`具体量化事实 > 明确身份/经历/资质 > 明确荣誉 > 模糊概括 > AI 总结`

例如：

- `10年建筑财务经历` 优先于 `长期从事建筑财务`；
- 新增 `注册会计师` 与前者不是重复，应保留；
- 不允许因为换了几个词就重复占简介空间。

## 质量门禁

任何新候选必须先通过硬规则：

- 事实可追溯；
- 我是谁 / 我的优势 / 我能提供什么价值完整；
- 价值具体，不允许 `保险保障 / 风险保障 / 保险认知 / 孤立职业 / 泛化生活方式`；
- 一句话 IP canonical 单一事实源；
- 小红书整段平台合规；
- 两平台 headline 不漂移；
- 固定声明结构正确；
- 不因合规改写制造新事实；
- 不出现明显语义重复。

硬规则任一失败：不得覆盖当前稳定稿。

## 升级规则

- 人工批准的 57 人底稿允许建立初始稳定版本；
- 自动候选必须先通过全部硬门禁；
- 自动候选质量分必须严格高于当前版本；
- 未改善、仅换措辞、出现事实回归或合规风险时，当前版本保持不变；
- 所有旧版本永久保存在 `proposals`，支持回滚。

## 隐私与仓库边界

57 人完整真实资料、客户反馈、人工验收 Excel 不提交 GitHub。仓库只保存规则、导入程序、测试和数据结构。真实数据只在受控数据库 / ECS 临时导入文件中流转。
