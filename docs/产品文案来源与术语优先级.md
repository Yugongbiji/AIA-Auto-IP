# AIA Auto IP 产品文案来源与术语优先级

## 目的

所有直接呈现给营销员的页面文案，都必须先服从已经确认的产品定义和真实资料，再由 AI 补充表达。避免同一个概念在不同页面被写成“内容主线 / 表达方向 / 内容方向”等不同叫法，也避免 AI 为了语言自然擅自改变业务含义。

## 文案来源优先级

页面展示文案按以下顺序取值和判断：

1. **已确认产品文档 / 产品需求与回归验收清单**
2. **已固化业务规则、平台规则、合规规则**
3. **营销员真实资料、报名资料、客户反馈、已确认 IP 方案**
4. **结构化数据库字段和代码中的标准枚举 / canonical terms**
5. **AI 根据上下文生成的辅助表达**

AI 永远处于最后一层。上层已经明确的名称、固定次数、业务口径、产品概念，AI 不得改名、改义或创造同义替代词。

## 标准术语

当前产品必须优先使用以下名称：

- `IP 人设`
- `内容方向`
- `保险主线`
- `内容支线`
- `脚本推荐`
- `脚本改写`
- `小红书排版`
- `拓客`
- `增员`

其中：

- “内容方向”是对外统一名称，不使用“表达方向”替代。
- 已确认的新产品界面不再把最终板块称为“内容主线”。历史方法论中的“主线”可以作为内部解释词，但不能覆盖当前页面标题“内容方向”。
- “拓客 / 增员”是当前起号阶段的两个业务目标；在首次收束阶段必须二选一。

## AI 文案生成约束

AI 可以负责：

- 把已确认业务逻辑说得更自然；
- 根据不同上下文调整语气；
- 在不改变事实和产品定义的前提下生成解释、引导语、提示语。

AI 不可以：

- 把“内容方向”改成“表达方向”；
- 把固定平台次数、合规规则改成近似说法；
- 把单一阶段目标重新扩写成“拓客 + 增员都要”；
- 创造数据库和产品规则中不存在的新业务字段；
- 根据语言习惯覆盖已经确认的产品名词。

## 起号阶段目标规则

报名资料中的“做自媒体目的”属于已有真实资料，但如果同时包含“拓客”和“增员”，不能直接作为当前阶段目标使用。

处理顺序：

1. 只有拓客 → 直接带入，不重复问。
2. 只有增员 → 直接带入，不重复问。
3. 同时选择拓客 + 增员，或填写“两个都要 / 两者兼顾 / 同时做”等 → 必须重新询问。
4. 重新询问时只提供“拓客 / 增员”两个选项。
5. 引导说明：刚起号时先把一个方向做清楚，不要贪多；等账号运营成熟后，再扩展另一个方向。

## 开发验收

新增或修改页面文案时至少检查：

- 是否已有产品文档中的标准名称；
- 是否与同一概念在其他页面的名称一致；
- 是否把内部逻辑、技术术语或 AI 推理暴露给用户；
- 是否让 AI 覆盖了固定业务规则；
- 同一个重要术语是否有多个近义词同时存在。

阶段收口时，应通过文本回归或 E2E 抽查标准术语，避免旧词重新出现。
