# AIA Auto IP 脚本库导入规则 V1

> 对应 `docs/脚本推荐产品设计.md`。首批来源：`增员-重疾险-教育金-热点-养生.xlsx`。

## 1. 原则

- 原始脚本正文不因导入而改写；推荐阶段也不偷偷改写。
- Excel 是导入来源，不是长期数据库结构。
- 首次导入先 dry-run，再 Preview SQLite 验证；未经产品验收不得直接写正式 RDS。
- 后续批次复用同一导入器，不为每个 Excel 写临时代码。

## 2. 字段映射

| Excel | 数据库 |
|---|---|
| 批次 | `batch` |
| 一级标签 | `level1_tag` |
| 二级标签 | `level2_tag` |
| 标题 | 拆分为 `title_1/title_2/title_3` |
| 正文 | `body` |
| 过审时间 | `reviewed_at` |
| 字数自动计算 | 仅校验，不作为权威值 |

系统重新生成：`word_count`、`estimated_minutes`、`content_hash`、`is_hot`。

## 3. 标题解析

- 支持 1、/2、/3、，以及 `1.` / `1．` 等编号；编号可换行或同行。
- 无编号时按非空换行拆分。
- V1 列表页只使用 `title_1`。
- 原始资料只有 1～2 个标题时，剩余字段允许为空；不得让 AI 擅自补标题。

## 4. 清洗与去重

- 一级/二级标签去除异常空白，例如 `保险 ` 统一为 `保险`。
- 正文保留原文；仅在生成 hash 时忽略空白差异。
- `content_hash = SHA-256(去空白正文)`，数据库唯一约束阻止完全重复正文再次导入。
- 重复记录在 dry-run 报告中列出源 Excel 行号，不静默覆盖已有脚本。

## 5. 字数与口播时长

- V1 使用系统统一口径重新计算正文口播字符数。
- 标点和空白不计入口播字符。
- `estimated_minutes = word_count / 260`，前台显示一位小数。

## 6. 热点

- 首批 V1：`level1_tag == 热点` 时设 `is_hot = true`。
- “热点”是加权/展示属性，不直接作为用户 IP 内容方向。
- 后续应扩展热点有效期与热点主题字段，避免过期热点长期加权。

## 7. 数据表

`script_library` 至少包含：

`script_id, batch, level1_tag, level2_tag, title_1, title_2, title_3, body, word_count, estimated_minutes, is_hot, reviewed_at, status, content_hash, created_at, updated_at`

内容方向映射与用户行为埋点单独建模，不塞进脚本主表。

## 8. 导入流程

1. `python scripts/import_script_library.py <excel>`：dry-run，只输出体检结果。
2. 人工/自动检查异常与重复。
3. `--write --sqlite <preview.db>`：只写 Preview SQLite。
4. 完成推荐 API、页面和自动测试后进入 Preview 产品验收。
5. 产品负责人明确允许后，才开放正式 RDS 导入路径。

## 9. 首批已知数据特征

- 原始约 210 条；存在完全重复正文，应按 `content_hash` 去重。
- 标题格式不完全统一，不能只按换行拆分。
- 原 Excel 字数字段与统一口播字数口径可能不同，因此仅作为校验来源。
- 一级标签“热点”需要进一步映射到真正的内容方向，不能直接显示成 IP 主线。
