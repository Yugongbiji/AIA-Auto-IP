# AIA Auto IP 产品架构与账号内容规划方法论

## 1. 产品目标

帮助友邦红人基于真实资料、个人 IP 和合规规则，持续完成从账号定位、内容规划、脚本改写到小红书发布排版的创作闭环。工具不替代营销员的真实经验；所有人设、荣誉、服务经验和案例均以已确认资料为准。

## 2. 总体架构：一个工作台，四个独立能力

四个能力均可从功能大厅独立进入，但共用同一份营销员档案和“当前 IP 方案版本”。未匹配的访客可使用通用模式，但不保存长期档案。

```text
营销员档案（基础资料、客户反馈、补充信息）
                    ↓
当前 IP 方案版本（定位、目标客户、优势、表达风格、合规规则）
        ├── IP 人设
        ├── 账号内容规划
        ├── 脚本改写
        └── 小红书排版
```

### 2.1 功能大厅与工作台

- 首次进入或点击 Logo：进入功能大厅，展示“IP 人设、账号内容规划、脚本改写、小红书排版”四张功能卡片，以及最近一次使用记录。
- 进入任一能力后：顶部使用横向工具栏切换功能，不使用常驻的流程型左侧菜单。
- 中间区域：当前功能的对话、草稿和结果。
- 右侧区域：可收起的“当前 IP 上下文”卡片；手机端收为顶部按钮，避免挤占内容空间。
- 每个功能保留独立对话历史和草稿；跨功能共享的是营销员档案与所选 IP 方案版本，不把不同任务的聊天记录混在一起。

### 2.2 IP 上下文的使用规则

- IP 档案是默认上下文，不是使用其他功能的门槛。
- 账号内容规划默认使用当前 IP 方案；脚本改写先判断脚本是否需要体现个人 IP；小红书排版仅在内容与个人账号有关时带入人设风格和合规提示。
- 用户可以切换方案版本，或在通用任务中关闭“使用当前 IP”。
- 每份内容规划、脚本和排版草稿记录其使用的 IP 方案版本，方便回溯和重新生成。

## 3. 四个功能的职责与流转

| 功能 | 核心任务 | 主要输出 | 可流转到 |
|---|---|---|---|
| IP 人设 | 建立和持续更新真实的个人定位 | 定位、昵称、简介、目标客户、优势、表达风格 | 内容规划、脚本改写、小红书排版 |
| 账号内容规划 | 规划账号长期内容结构和作品合集 | 账号 1+1 定位、合集、选题库、发布比例 | 脚本改写 |
| 脚本改写 | 把一个明确选题或已有脚本改成可用成稿 | 多版本口播/图文脚本、合规修改建议 | 小红书排版 |
| 小红书排版 | 把成稿改成适合发布与复制的内容 | 标题、正文分段、表情、封面/首图文字建议、发布前提示 | 发布 |

推荐开发顺序：先完成账号内容规划，再完成脚本改写，最后完成小红书排版。

## 4. 账号内容规划：解决什么问题

账号不能像朋友圈一样随机混发带娃、旅行、风景、保险科普和公司海报。内容规划的目标是让受众清楚：为什么关注这个账号、为什么需要保险、该了解什么保险，以及为什么应该找这位营销员。

## 5. 账号内容规划的“保险 + 泛内容”模式

### 5.1 第一条主线：保险内容（必须是保险）

第一条主线一定是保险内容，不是泛内容。可以是：

- 广义保险内容：保障、财富相关的保险认知与规划；
- 保险细分领域：教育金、养老、家庭保障、传承等；
- 面向某一人群的保险问题：例如围绕宝妈家庭的教育金规划，或围绕中老年家庭的养老保障科普。

保险主线应由当前 IP 的目标客户、服务方向、从业经验与优势决定。

### 5.2 第二条主线：泛内容（保险以外的内容）

第二条主线是保险之外的泛内容，例如教育、理财、女性成长、职业经历、育儿、升学或高质量运动生活方式等。它不是为了“显得内容丰富”，而是为了吸引与目标客户或准增员对象一致的人群，并建立长期的价值连接。

选择泛内容必须同时通过三项判断：

1. **人群一致**：被内容吸引来的人，是否与准保险客户或准增员对象的画像一致；
2. **可持续输出**：营销员是否有真实积累，可结合既往职业、学历、生活经历、兴趣和服务经验判断；
3. **利他价值**：内容能否持续解决受众真实问题，而非单纯展示自己。

### 5.3 选择泛内容时的反例与筛选

- **保险 + 星座**：星座往往吸引年轻泛兴趣人群，未必是目标保险客户或准增员对象；同时“命中注定”的观念可能削弱主动风险规划意愿，因此不宜仅因话题热度选择。
- **保险 + 运动**：需要继续判断具体运动圈层。钓鱼可能吸引的人群与高价值保险客户不够匹配；骑行等相对高端的运动圈层，若与该营销员的目标客户和真实积累一致，可能更适合。
- 结论：不以“我喜欢讲什么”作为唯一标准，而以“谁会被吸引、其价值与转化可能性、我能否长期利他输出”共同判断。

## 6. 两条业务目标的内容递进

每一份规划必须先选择首要目标：拓客、增员，或两者兼顾。两者兼顾时必须设置主次比例，默认建议主目标 70%、次目标 30%，避免账号失焦。

### 6.1 拓客内容逻辑

| 受众依次要回答的问题 | 合集任务 | 常见内容来源 |
|---|---|---|
| 为什么看你 | 先提供值得关注的利他价值 | 泛内容主线、目标人群问题、个人视角 |
| 为什么需要保险 | 建立风险认知和保险理念 | 保障意义、家庭责任、风险教育 |
| 我要了解什么/怎么买 | 提供具体的保险科普与规划思路 | 家庭结构、人生阶段、保障组合 |
| 为什么找你买 | 建立个人专业与信任 | 个人故事、服务经验、理赔经验、真实专业积累 |

### 6.2 增员内容逻辑

| 准增员对象依次要回答的问题 | 合集任务 | 常见内容来源 |
|---|---|---|
| 为什么看你 | 提供与其人群一致的价值内容 | 职场、成长、家庭、生活方式等泛内容 |
| 为什么做保险 | 建立职业认知与行业价值 | 工作意义、职业机会、真实认知 |
| 我能不能做保险 | 降低尝试门槛并解释成长路径 | 能力要求、训练、成长故事、真实案例 |
| 为什么加入你的团队 | 建立团队与带教信任 | 团队文化、支持系统、带教经验、个人故事 |

## 7. 内容规划功能的对话与输出

### 7.1 最少补充信息

系统自动读取当前 IP 档案后，只补问缺少的关键内容：

1. 本次账号的首要目标与主次比例；
2. 保险主线：广义保险或具体细分领域；
3. 泛内容候选方向；
4. 与泛内容相关的真实经历、积累和可持续素材；
5. 目标受众能从中获得的具体帮助。

### 7.2 结果页应输出

- 账号“保险 + 泛内容”定位，以及每条主线的选择理由；
- 人群一致、可持续、利他价值三项评估；
- 不建议选择的方向及原因；
- 3 至 5 个作品合集，每个合集包含目标、受众问题、内容边界和选题来源；
- 每个合集的首批选题与优先级；
- 主次目标内容比例与建议发布节奏；
- 从某一选题一键进入“脚本改写”的入口。

## 8. 脚本改写的方法库

脚本改写承接内容规划中的具体选题，也可独立粘贴已有脚本。系统先判断脚本是否需要体现个人 IP；需要时带入人设、城市、专业方向、表达风格和合规规则，不需要时按通用脚本处理。

“转化型选题方法与脚本写作技巧”材料中的六种开头方法属于脚本层方法库，不替代账号合集规划：

1. 热点借势法：热点 + 知识点；
2. 悬念提问法：以“什么样的……需要……”“你知道吗”等问题引入；
3. 数据冲击法：用金额、概率等惊人数据建立注意力；
4. 危机制法：风险 + 严重后果；
5. 反常识颠覆法：大众认知与真实情况对比；
6. 痛点场景法：人群标签 + 高频痛点。

系统应根据选题、受众与合规边界推荐合适方法，而非为了吸引注意力夸大、恐吓或虚构内容。

## 9. 小红书排版功能

小红书排版承接已经确认的文案，也可以独立输入。若内容用于营销员个人账号，自动使用对应 IP 的表达风格、受众称呼与合规提示。

输出包括：标题备选、适合手机阅读的正文分段、表情与小标题建议、首图/封面文字建议、可复制文本框，以及发布前合规核对。排版功能不擅自添加联系方式、引流、敏感词、夸大承诺或未经确认的个人经历。

## 10. 数据与保存规则

- 已匹配营销员：资料、IP 方案、内容规划、脚本改写记录和排版草稿保存到 RDS；
- 访客：仅保留本次浏览器会话，不写入长期档案；
- 每项生成内容保存所使用的 IP 方案版本、创建时间和修改历史；
- 数据库密码、个人资料、对话、方案和草稿不上传 Git；Git 仅保存代码与不含隐私的规则文档。
