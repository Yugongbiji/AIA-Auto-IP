# AIA Auto IP 产品架构与内容主线方法论 V2

## 1. 产品目标

帮助友邦营销员基于真实资料、个人 IP 和合规规则，完成从账号定位到脚本改写、发布排版的创作闭环。

用户不需要理解内部筛选过程。产品应尽量把复杂判断放在系统里，把真正需要本人确认的业务信息留给用户。

## 2. 当前产品架构：三个用户可见能力

```text
营销员档案
    ↓
IP 人设方案
（定位 / 目标人群 / 优势 / 昵称 / 简介 / 表达风格 / 内容主线）
    ↓
脚本改写
    ↓
小红书排版
```

顶部只保留：

1. IP 人设；
2. 脚本改写；
3. 小红书排版。

原“内容规划”不再作为独立功能。它的核心价值被精简后合并到 IP 方案底部的“你的内容主线”。

## 3. 为什么合并内容规划

原流程存在重复决策：IP 已经采集“做自媒体目的”，进入内容规划后又重新询问拓客 / 增员，并再次经历候选、筛选、最终方向、内容方向等多个板块。

新的目标是让一份 IP 方案直接回答：

**我是谁 → 我服务谁 → 账号怎么称呼和介绍自己 → 接下来长期发什么。**

因此不再要求营销员完成第二套内容规划 onboarding。

## 4. “做自媒体目的”直接决定专业主线

使用 IP 字段 `purpose`：

- 拓客：保险专业主线 + 泛内容支线；
- 增员：增员内容主线 + 泛内容支线；
- 拓客和增员都要：拓客内容主线 + 增员内容主线 + 泛内容支线；
- 打造个人品牌：专业信任内容 + 泛内容支线，不自动增加增员主线。

拓客与增员边界见 `rules/content-goal-boundary-rules.md`。

## 5. 每条内容主线只回答三件事

### 内容方向

结合本人目标人群、服务能力、IP 标签、真实经历和已有资料，列出可以持续输出的方向。

### 合集推荐

合集由内容方向自然延伸，**名称不得超过 5 个汉字**。例如：

- 家庭保障方案 → 家庭保障
- 理赔案例 → 理赔案例
- 转型经历 → 转型日记
- 骑行 → 骑行日记

### 对账号的作用

不用长篇解释，直接做标签：

- 拓客：建立信任 / 吸引准客 / 推动咨询；
- 增员：展示职业 / 吸引同频 / 团队信任；
- 泛内容：扩大受众 / 增加活人感 / 打开流量。

## 6. 泛内容支线

泛内容必须是保险和直接招募以外的独立方向，例如育儿、升学、骑行、户外、运动、法律、职场成长等。

它的作用是扩大受众、增加活人感和打开更宽的话题入口，不要求每篇都转回保险。

泛内容必须有本人真实积累。没有真实证据时显示“暂未确定”，不要为了把页面填满而猜测。

## 7. 页面不再展示筛选过程

撤销以下用户可见结构：

- 内容规划独立入口；
- 独立欢迎 / 问答流程；
- 顶部红色总结板块；
- 候选方向；
- 旧内容方向大板块；
- 不建议混入方向；
- 单独“生成内容规划”按钮。

内部仍可以做筛选和校验，但结果页只给收束后的结论。

## 8. 内容聚焦提醒

“你的内容主线”底部保留内容聚焦提醒。

核心原则：

- 专业主线保持稳定；
- 泛内容长期只选一个真正能持续输出的方向；
- 拓客和增员都要时，同一阶段仍要有明显主次；
- 不要让账号在多个毫无关系的话题之间像朋友圈一样随机跳转。

## 9. 脚本改写的承接

脚本改写直接读取当前 IP 档案和表达风格。

表达风格只是长期偏好，还必须先判断题材是否适合。事故、死亡、重疾、家庭创伤等严肃题材优先尊重和克制，不机械套用幽默或犀利风格。

## 10. 旧内容规划的迁移策略

本轮只撤销用户入口，不做破坏性数据库清理：

- 旧内容规划 API 暂时保留；
- 旧内容规划历史表和方案历史暂时保留；
- 新用户不再进入旧流程；
- 等新结构稳定后，再单独决定是否清理旧后端逻辑。

详细产品规则以 `rules/ip-content-strategy-rules.md` 为准。
