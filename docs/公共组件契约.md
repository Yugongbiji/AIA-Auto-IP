# AIA Auto IP 公共组件契约 V1

本文件用于约束所有现有与未来功能的公共交互组件。目标是让产品负责人只关注功能、内容与业务规则；键盘、滚动、快捷选择、输入、错误态等基础交互由公共组件与自动测试统一保证。

## 1. 不可覆盖的品牌层

本契约不替代 `docs/界面设计规范.md`。现有 AIA 品牌视觉规则继续保留，包括但不限于：

- AIA Red `#D31145`
- 深红 `#AC0D38`
- 80% / 60% / 40% / 20% 红色层级
- 中性色、白底、克制留白、辅助文字弱化原则

公共组件新增能力时，优先复用上述品牌 Token，不私自建立冲突色板。

## 2. ChatWorkspace

职责：统一承载一个功能的对话历史、当前问题、快捷选项和输入区。

必须保证：

- 新问题、新回复和新结果在正常聊天状态下自动进入可视区域；
- 用户主动上滑查看历史时暂停自动跟随，并提供“回到最新”；
- 用户再次发送后恢复自动跟随；
- 顶部功能导航和底部输入区不被内容增长挤出布局；
- 手机端不得出现非预期页面级横向溢出；
- 手机软键盘弹出后，以 `visualViewport` 的真实可见高度为工作区边界，Composer、发送按钮和最新消息不得被键盘压出视口；
- URL、手机号、连续英文、模型异常长字符串等必须在消息自身宽度内断行，不能撑宽页面。

IP 人设、内容规划以及未来所有对话型功能必须复用同一套滚动与可视区判断逻辑。

## 3. Composer

职责：统一承载已选结构化答案、自由文本和唯一的发送动作。

必须保证：

- 已选标签与文本输入处于同一个视觉输入容器；
- 标签可自然换行，但输入区不无限增高；
- 只有用户主动点击可输入区域才允许主动获取文本焦点；
- 点击快捷标签、取消标签、点击删除 `×` 不得主动调用输入框 `focus()`；
- 页面只保留一个最终提交动作：发送；
- 发送时结构化选项与自由文本可分别保留，再组合提交；
- 键盘打开、视口缩小时，Composer 不得离开可见区域，也不得把发送按钮推到视口之外。

## 4. QuickChoices

职责：给用户提供低成本快捷回答，不作为独立表单。

必须保证：

- 多选项在手机端优先单行横向滑动；
- 空白选项不得渲染；
- 选中后使用浅红底 + AIA Red 文字/边框，不使用大面积实心红；
- 点击选项只更新选择状态，不主动弹出手机键盘；
- 与 Composer 内标签双向同步；
- 不允许再出现“确认已选”一类第二提交按钮。

## 5. WelcomeCard

职责：负责首次进入功能时的产品化介绍。

必须保证：

- 介绍完成后立即进入可执行下一步，不能停在“接下来会问几个问题”却没有问题；
- 已有资料时说明已自动带入，并直接定位到第一个缺失项；
- 无资料时自然进入第一问，不使用带失败感的提示；
- 再次进入已有历史时优先恢复工作，而不是重复完整新手介绍。

## 6. ProfileBar

职责：在 IP 人设中显示当前 IP 资料摘要。

必须保证：

- 只在 IP 人设功能页出现；
- 收起时只占一行；
- 展开时只负责展示资料；
- “如需修改，请在输入框告诉我”等辅助提示只在展开状态底部显示，并使用小字号灰色注释样式；
- 不自行增加与 ChatWorkspace 冲突的滚动或固定层。

## 7. 状态组件

所有功能必须复用一致的状态语义：

- Loading：明确告诉用户正在处理，避免“点击后没反应”的感受；
- Empty：解释当前为什么没有内容，并给出下一步；
- Error：说明失败发生在哪一层，并提供可执行的重试；
- Retry：重试必须走原业务提交入口，不复制一套旁路业务逻辑；
- Saved/Success：使用统一成功语义，不与品牌主按钮争夺视觉重点。

## 8. 自动化验收门槛

公共组件修改后，至少自动检查：

1. 360px 手机；
2. 390px 手机；
3. 1440px 桌面；
4. 首次进入能看到真实第一问；
5. 多选标签不主动聚焦文本输入；
6. 已选标签位于 Composer 内；
7. 上下选择状态双向同步；
8. 发送后下一题自动进入可视区域；
9. 无页面级非预期横向溢出；
10. 无 serious / critical 级自动可访问性问题；
11. 超长连续文本不能撑出工作区或页面；
12. 用户主动上翻历史后暂停自动跟随，并显示“回到最新”；
13. 点击“回到最新”后恢复自动跟随；
14. 视口高度缩小时 Composer 与发送按钮仍在可见区域；
15. AI 接口失败后必须退出 loading，并提供可执行“重试”；
16. 重试成功后能够恢复正常结果，不要求用户重新粘贴原内容。

若公共组件行为变化导致上述测试失败，应优先修复公共组件，而不是在单个功能内写例外 CSS/JS 绕过。
