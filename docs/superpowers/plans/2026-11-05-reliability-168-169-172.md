# Reliability Batch 168, 169, 172 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist eligible non-roster users, reliably recover generated IP-plan cards, and regenerate a plan after a confirmed conversational profile change.

**Architecture:** The existing `agents` table remains the single identity anchor for all saved records. A valid name plus agent ID that is absent from the roster creates a minimal guest agent row, allowing all existing profile, conversation, and proposal persistence paths to work unchanged. The browser treats saved proposals as the source of truth and restores the latest card even when the old “generated” chat event was not persisted.

**Tech Stack:** Python 3.12, SQLite/PostgreSQL via the existing database adapter, vanilla JavaScript, pytest, Playwright.

**Spec:** Product items 168, 169, 172 confirmed 2026-11-05.

## Global Constraints

- Do not change or delete imported registration data when saving conversation-derived profile values.
- Only name-plus-agent-ID sign-ins may create a persistent guest profile; the no-identity guest entry remains session-only.
- A confirmed conversational update with an existing IP proposal must create a new proposal version.
- Proposal recovery must not duplicate a card already restored from message history.
- No production database mutation during development or verification.

## Review Focus

- Unknown sign-in with a valid identity creates one reusable record and preserves it across a second lookup.
- Invalid or clearly placeholder identity is not persisted.
- Imported roster records remain matched and never get replaced by guest creation.
- A proposal saved before browser reload remains visible as a card even if its message save was interrupted.
- A confirmed profile change after V1 creates V2, while a first-time profile update does not prematurely generate twice.
