# 脚本搜索与详情页操作栏设计

## 目标

- 在“脚本推荐”页面增加完整脚本库搜索。
- 搜索范围覆盖后端脚本库，按关键词匹配标题、一级标签、二级标签和正文。
- 清空搜索后恢复原有个性化推荐或完整脚本库状态。
- 脚本详情页底部固定按钮只保留“脚本改写”和“小红书排版”。
- 两个按钮使用同等级、同风格的操作样式，不表达主次优先级。

## 非目标

- 不改变既有个性化推荐排序、去重、分页和详情打开逻辑。
- 不修改脚本正文或推荐规则。
- 不新增或保留详情页底部的上一篇/下一篇按钮；文章底部已有的上一篇/下一篇切换不受影响。

## 实现方案

- 后端扩展脚本库查询接口，接收可选关键词参数，由数据库统一执行完整库搜索。
- 前端在脚本推荐标题区增加搜索输入和按钮，提交后调用后端搜索接口并复用现有脚本卡片、分页和空状态渲染。
- 搜索状态与原推荐状态隔离；搜索中、无结果、清空恢复均有明确状态。
- 详情页 HTML 删除上一篇/下一篇固定按钮，保留两个同级 secondary button；脚本改写和小红书排版的 handoff 行为保持不变。
- 更新相关契约测试，覆盖搜索参数/结果、详情页按钮集合与统一样式约束。

## 验收标准

- 搜索一个只存在于非当前页脚本中的关键词，可以返回匹配结果。
- 搜索结果只包含匹配脚本，分页和详情打开仍可用。
- 清空搜索后恢复原页面数据。
- 详情页固定区域不存在上一篇/下一篇，只显示脚本改写和小红书排版。
- 两个固定按钮拥有相同样式等级，既有 handoff 流程不回归。
