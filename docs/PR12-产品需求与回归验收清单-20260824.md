# PR #12 产品需求与回归验收清单（2026-08-24）

> 目的：把本阶段所有已确认产品需求、修复项和不可回退行为固化为单一验收源。开发阶段可以集中修改，但任何后续改动都不能让已经验收通过的旧需求悄悄失效。

## 使用方式

1. 新反馈进入本文件后再实施，编号持续追加，不覆盖历史。
2. 每项需求必须同时记录：业务期望、当前实现、验收口径、回归保护。
3. 阶段性 Preview 更新后，先做与本轮改动相关的冒烟验收；阶段收口前再跑完整 Frontend QA。
4. 如果后续改动导致本清单中的已完成项重新失败，按“回归 Bug”处理，优先修公共组件/唯一真源，不允许在单页面叠补丁掩盖。
5. PR 合并 main 前必须至少完成一次本清单全量复核。

## 已确认基线需求

### A. IP 人设与资料

- 已有资料不重复询问，内部跳过逻辑不向营销员解释。
- “过往职业/长期经历”“家庭与生活身份”“个人爱好”进入内容支线候选；支持多选与自由输入。
- 所有询问快捷选项移除“其他 / 不希望填写 / 跳过 / 暂不填写”等逃生项；仍保留自由输入。
- “我的 IP 资料”和“最新 IP 方案”悬浮入口只在 IP 对话页出现；方案页及其他功能页隐藏；从方案返回对话后恢复。
- 展开资料必须有明确关闭方式，采用常见浮层交互（关闭按钮 / 点击外部关闭）。
- 身边人评价进入个人资料；称呼统计保留原始值与频次。
- 内容支线使用统一评分规则，不按选择顺序 first-match；育儿等与保险目标客群高度重合的方向应优先于普通连接型兴趣。

### B. 昵称与简介

- 昵称必须有“人的称呼主体”，城市、专业、荣誉、学历等只能作为修饰，禁止只出现“成都”“MDRT”等标签。
- 称呼来源优先级：身边人高频真实称呼 > 本人姓名衍生自然称呼 > 本名兜底。
- 身边人称呼同频时按公开自然、亲和、易记、顺口、与姓名关联、组合能力排序。
- 复制昵称和复制简介使用同一套固定平台修改次数提醒；平台固定次数不得交给 AI 改写。
- 小红书个人简介固定提醒包含：“7 天内最多修改 3 次，频繁修改也可能影响账号稳定。”

### C. 内容方向与脚本推荐

- IP 方案底部板块标题为“内容方向”。
- 内容方向只保留“保险主线 + 一个内容支线”；内容支线必须来自统一排序结果。
- IP 方案与脚本推荐必须读取同一个内容支线唯一真源，禁止一个页面显示“育儿”、另一个页面显示“家庭与生活身份”。
- IP 方案内容方向底部提供“查看推荐脚本”入口。
- 脚本推荐页面只显示“保险主线 / 内容支线”两个板块。
- 脚本推荐允许受控模糊映射；例如“宝妈 / 宝爸 / 家庭身份 / 亲子教育 / 带娃”等应归一或映射到“育儿”。
- 不允许为了填满推荐位跨到明显无关脚本。
- 保险主线、内容支线各自提供“换一批”；可匹配不足两批时按钮禁用并说明原因。
- 推荐页显示当天日期和“今日推荐”，日期必须动态取用户本地日期。
- 脚本详情移除“开头 / 正文1 / 正文2 / 脚本正文 / 结尾 / 结语 / 结束语”等内部结构标签，只保留真实正文。
- 脚本详情工具栏只保留“脚本改写 / 小红书排版”；上一篇在正文底部左侧，下一篇在右侧。

### D. 脚本改写与小红书排版

- 小红书排版不改原文字词，只做换行、分段、emoji 与已确认合规提示。
- 小红书等待状态只表达“正在排版，请稍候…”，不得展示“正在整理手机阅读节奏 / 断句 / 留白 / 表情”等内部处理说明。
- 脚本改写等待态与小红书排版等待态必须由统一状态组件管理，不在各功能散落自定义文案。
- 脚本改写结果和小红书排版结果点击复制后，必须有明确“复制成功”反馈；失败时提示“复制失败，请重试”。
- 复制反馈属于公共组件，不允许昵称、简介、脚本、小红书分别维护四套复制逻辑。

## 防回退机制

### 1. 单一需求源

本文件是 PR #12 产品需求和验收口径的主清单。PR 描述只做阶段摘要，不能替代本文件。

### 2. 公共组件优先

以下能力必须公共化：

- Toast / Success / Error
- Clipboard Copy
- Loading / Empty / Retry
- ChatWorkspace 滚动与可视区
- Composer / QuickChoices
- 浮层打开 / 关闭

发现两个以上页面出现同一种基础交互时，默认先检查是否应该抽公共组件，而不是继续复制代码。

### 3. 自动化回归

关键产品契约至少覆盖：

- 小红书 loading 不出现内部处理词；
- 所有创作工具复制有成功反馈；
- IP / 脚本推荐支线一致；
- 昵称始终有人称呼主体；
- 询问选项不含跳过类快捷项；
- 内容方向 → 推荐脚本跳转有效；
- 推荐页今日日期存在；
- 脚本详情无内部结构标记；
- 浮窗只在 IP 对话页显示并能正确恢复。

### 4. 阶段验收节奏

- 日常连续开发：只跑与当前修改直接相关的必要检查。
- 一批问题完成：更新 Preview，集中产品验收。
- 阶段收口：全量 Frontend QA + 本清单人工抽查。
- 任何回归：先定位共享状态、加载顺序、组件覆盖或唯一真源问题，不通过不断追加版本文件碰运气。

## 当前技术债提醒

目前前端通过 `product-rules-v5...v22` 多层覆盖原函数，短期便于在同一 PR 快速验收，但随着层数增加，后加载脚本覆盖前面行为的风险明显上升。阶段收口后应安排一次“不改变产品行为的前端收敛”：把已确认规则合并回稳定模块 / 公共组件，减少 monkey-patch 层数，并用本清单与 E2E 保证收敛过程中不回退。
