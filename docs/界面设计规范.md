# AIA Auto IP 界面设计规范

## 1. 设计目标

界面首先要让营销员感到专业、轻松、愿意持续创作；品牌色用于建立识别和引导操作，而不是把每一处内容都染成红色。整体参考友邦官网的克制留白、清晰信息层级和 AIA Red 品牌识别，遵循“先美观易读，再体现品牌”的原则。

参考页面：友邦中国官网“百年友邦 / 公益”页面 `https://www.aia.com.cn/zh-cn/aia/aia.gongyi`。参考其大标题与辅助信息之间的明显层级、较充足留白，以及辅助信息弱化处理的方式；不机械复制官网具体尺寸。

## 2. 视觉原则

1. **内容优先**：方案、脚本和对话是主角，容器、边框和装饰保持克制。
2. **一屏一个视觉重点**：每个区域只保留一个主要强调元素；大面积纯红仅用于方案封面、最关键主按钮等高优先级场景。
3. **品牌色有层级**：友邦红用于主操作、当前状态、关键信息和少量标签；辅助信息使用中性深灰、灰色与白色。
4. **轻而不飘**：卡片采用白底、细边框、柔和阴影与充足留白，不使用密集渐变、过多描边或大量红色文字。
5. **一致且可访问**：同一语义使用同一颜色；风险检测的绿色保留为独立语义色，不能用红色替代。

## 3. 色彩系统

### 3.1 品牌主色

| 名称 | 色值 | 使用范围 |
|---|---|---|
| AIA Red | `#D31145`（R211 G17 B69） | 主按钮、当前标签、关键数字、方案封面重点 |
| 深红 | `#AC0D38` | 主按钮悬停、少量深层强调 |
| 80% 红 | `#DC416A` | 状态边框、悬停点缀 |
| 60% 红 | `#E5708F` | 次级装饰、图表强调 |
| 40% 红 | `#EDA0B5` | 轻边框、弱提示 |
| 20% 红 | `#F6CFDA` | 选中底色、浅背景 |
| 极浅红 | `#FFF5F7` | 很小范围的 hover 或提示底色 |

### 3.2 中性色与语义色

- 标题与主文字：`#22252B`；避免使用红色作为大段正文颜色。
- 次级文字：`#667085`；说明文字可用 `#7A7278`。
- 页面底色：`#FBFAFB`；卡片底色：`#FFFFFF`；边框：`#E8E5E7`。
- 成功/已保存/低风险：`#0F9F6E` 与浅绿底 `#EAF8F1`。
- 有风险提示：只在风险模块使用浅红底和深红文字，不能和主操作抢视觉焦点。

## 4. 信息层级与排版

- 功能主标题使用深色粗体，建议桌面端 `28–36px`、移动端 `22–28px`；功能名称比副标题明显更大。
- 眉题、状态和小标签可使用 AIA Red，但字号宜为 `11–13px`。
- 副标题、说明、过程解释使用灰色，不使用紫色或大面积红色。
- 正文默认 `14–16px`，行高 `1.55–1.75`；一段文字保持短而易扫读。
- 采用 4px/8px 间距体系：组件内常用 8、12、16px；模块之间常用 20、24、32px。卡片之间必须留出呼吸感。
- 手机端页面与浮层左右安全边距原则上保留 `12–16px`；极窄屏可最低到 `10px`，但不能让正文、按钮或注释贴边。

### 辅助说明 / 注释文字

用于“如果想修改资料……”“阅读时间”“状态补充”“操作提醒”等非主任务信息时，必须明显弱于正文：

- 桌面端建议 `11–12px`；手机端建议 `10.5–11px`，不超过正文大小。
- 颜色统一优先使用 `#7A7278` 或 `#667085`，不使用大面积 AIA Red。
- 行高建议 `1.45–1.6`，允许自然换行，禁止单行硬撑导致溢出。
- 与主体内容之间至少留 `8px` 间距；位于卡片底部时可用很浅的分隔线与正文区分。
- 收起状态不展示“如何修改”“操作说明”这类辅助文字；只有用户主动展开后才显示。
- 注释信息不设置粗体主视觉，不使用与主按钮相同的字号、颜色或字重。

## 5. 组件规则

### 按钮与选择

- 实心 AIA Red 只用于当前页面的主行动，例如“开始改写”“生成方案”“发送”。
- 次级操作使用白底红色描边或文字按钮；不要与主按钮使用相同的红色填充。
- 多选标签默认白底细边框；选中后使用极浅红底、红色文字和红色边框。
- **多选题取消独立“确认已选”按钮。** 快捷选项只是帮助填写答案，最终统一由底部“发送”提交。
- 手机端多选项优先单行横向排列，超出屏幕宽度后左右滑动，不向下堆叠很多行。
- 空白选项必须删除。
- 点击快捷标签只改变选择状态，不得自动聚焦输入框、不得主动拉起手机输入法。
- 已选项必须真正嵌入底部输入框内部，与自由输入文字共用同一个边框、背景和圆角；不得悬在输入框上方另起一层。
- 输入框内标签建议字号 `12–13px`、高度 `28–32px`、间距 `5–6px`；多个标签允许自然换行。
- 上方取消选择或删除输入框内标签时，两处状态必须同步。
- 危险/风险检测维持独立绿色或风险红提示，不与普通选择按钮混用。

### 卡片与结果

- 常规卡片使用白底、`12–18px` 圆角、细中性边框和非常轻的阴影。
- 结果页的分析说明使用浅灰卡片；可复制正文使用纯白文本框，确保复制区安静、易读。
- 方案封面可以使用 AIA Red 渐变作为一个页面唯一的大色块，内部文字使用白色；其余卡片回归白底。
- 欢迎介绍卡、脚本处理说明、人工微调提示都应采用“深色标题 + 灰色说明 + 小范围红色强调”的结构，不使用满屏红字。
- IP 资料等悬浮摘要收起时只保留主信息；辅助说明只在展开状态最底部出现。

### 对话与输入

- 用户气泡使用 AIA Red；助手气泡使用白底深色文字；系统提示使用浅灰底。
- 顶部工具栏和底部输入框保持白底、细边框和轻微毛玻璃效果，滚动时仍稳定可见。
- 输入框聚焦时使用 AIA Red 外圈；不使用强烈阴影或跳色。
- 手机端输入编辑器建议最小高度 `44–48px`；已选标签和文字增多后最多自然增长约 3 行，超过后输入区内部滚动。
- 只有用户主动点击输入框中的可输入位置时才进入文字输入；点快捷标签或标签删除按钮不能主动拉起键盘。
- 新消息、新问题、新结果出现时，正常聊天状态下必须自动跟随到最新内容。
- 用户回答上一题后，下一题出现必须自动进入视野，这是问答流程的最高优先级滚动规则。
- 页面布局因快捷选项、输入区高度变化而变化时，应再次校正滚动位置，不能只在消息刚插入时滚一次。
- 用户主动向上阅读历史且离底部较远时，不强行拉回；显示轻量“回到最新 ↓”入口。
- 用户再次发送消息后恢复自动跟随。

## 6. 响应式规则

- 桌面、平板和手机共用同一颜色、层级和间距逻辑，不因屏幕变窄而堆叠大量装饰。
- 手机端保留 `12–16px` 页面边距；功能工具栏可横向滚动，底部输入区固定可见。
- 两栏内容在窄屏切换为单列；避免固定宽度导致标题、卡片或按钮溢出。
- 所有正文、标签、按钮必须通过自然换行或横向滚动安全展示，避免异常断字。
- 多选快捷项允许横向滑动；已选标签则直接在同一输入框内自然换行。
- 自动滚动必须保证最新问题、当前快捷选项和输入区能连续使用，不能让用户每答一题都手动向下滑。

## 7. 上线检查清单

- 是否只有一个最主要的红色主操作？
- 标题是否深色、说明是否灰色，而非大段红色？
- 常规卡片是否以白底和中性边框为主？
- 辅助说明是否控制在 `10.5–12px`、灰色、可自然换行，并且只在需要时出现？
- 多选题是否已经取消“确认已选”，只保留最终“发送”？
- 点击快捷标签时手机键盘是否保持不被主动拉起？
- 已选标签是否真正位于输入框内部，而不是输入框上方？
- 新问题出现后是否自动进入可视区域，并在布局变化后仍保持可见？
- 用户主动阅读历史时，自动滚动是否不会强行打断？
- 手机端标题、按钮、输入框和卡片是否保留足够边距与可点击面积？
- 本次视觉调整是否让内容更易读，而不只是增加颜色或装饰？

> 快捷选项、统一发送与自动滚动的具体行为以 `docs/通用交互规则.md` 为准。
