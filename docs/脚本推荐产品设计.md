# AIA Auto IP 脚本推荐产品设计 V1

> 状态：产品方案已确认，尚未进入开发实现。
> 当前开发分支：`agent/ip-copy-compliance`（PR #3）。
> 本文用于后续开发“脚本推荐”功能时作为产品与数据结构依据。

## 1. 功能定位

在顶部导航中新增 **脚本推荐**，放在 **IP 人设** 后面。

顶部结构：

`IP 人设 → 脚本推荐 → 脚本改写 → 小红书排版`

脚本推荐不是 AI 对话页，而是一个独立内容发现页面。

核心价值：

- 根据营销员的人设、内容主线、当前业务节奏和热点趋势，直接推荐更值得拍的现成脚本；
- 解决“今天拍什么”的问题；
- 推荐页保留脚本库原始内容，不在推荐阶段偷偷改写；
- 用户明确点击“脚本改写”后，才进入个性化改写流程。

产品职责区分：

- **脚本推荐**：解决“不知道拍什么”；
- **脚本改写**：解决“这篇内容怎么变成我的”；
- **小红书排版**：解决“这篇内容怎么更适合发布和阅读”。

## 2. 推荐依据

推荐逻辑分层建设：

### V1 必须

1. **内容主线匹配**
   - 直接读取 IP 方案底部已经确定的内容主线；
   - 前台板块名称必须与 IP 方案中的内容方向名称一致；
   - 数据库一级/二级标签只作为内部匹配依据，不直接替代前台内容方向。

2. **IP 人群与个人特点轻量加权**
   - 同一内容方向下，优先推荐更适合当前服务人群、专业积累和真实身份的脚本；
   - 不因为有标签就机械推荐与本人明显不匹配的内容。

### 后续逐步加入

3. **业务节奏权重**
   - 由运营后台设置阶段重点，如养老、医疗、个养、教育金、增员季、活动主题等；
   - 当前业务重点只用于加权排序，不改变 IP 主线。

4. **热点趋势权重**
   - 节日节点、政策、行业热点、平台热点等；
   - 热点只能加权合适脚本，不得为了追热点破坏人设或内容主线。

推荐优先级原则：

`IP / 内容主线 > 业务节奏 > 热点趋势`

## 3. 页面结构

页面顶部简要说明：

> 根据你的人设、内容主线、当前业务节奏和近期热点，为你挑选更值得拍的脚本。

页面按 **内容方向** 分板块展示，而不是按一级标签展示。

示例：

- 家庭保障
- 理赔案例
- 养老规划
- 育儿

每个内容方向默认推荐 **5 篇**，后续可通过“查看更多”扩展到 10 篇或进入该方向完整列表。

每个内容方向只展示 **一个推荐原因**，不为每篇脚本重复写推荐理由。

推荐原因示例：

- 和你的家庭保障主线最匹配；
- 当前业务阶段优先关注养老内容；
- 近期育儿话题热度较高，且与你的泛内容支线一致。

## 4. 脚本卡片

每张脚本卡片只保留必要信息。

### 标题

- 默认显示脚本库中的第一个标题 `title_1`；
- 第二、第三候选标题暂不在列表页展示；
- 标题可点击进入详情页。

### 热点标识

如果脚本属于热点类内容，在标题前显示醒目的 **“热点”** 标签。

示例：

`[热点] 个人养老金新政策到底影响谁？`

热点标识应高识别度，但不要喧宾夺主。

### 元信息

一级标签、二级标签、字数和预计口播时长放在 **同一行**。

示例：

`养老 · 政策 · 486字 · 1.9min`

不要拆成多行。

## 5. 同一批推荐去重

**同一次推荐结果中，同一篇脚本只能出现一次。**

即使一篇脚本同时符合多个内容方向，也不能在多个板块重复展示。

分配原则：

1. 先计算脚本与各内容方向的匹配度；
2. 将脚本分配给匹配度最高的一个方向；
3. 已被某方向占用后，本次推荐的其他方向不得再次使用；
4. 下一次“换一批”或新的推荐批次可以重新参与排序。

这样可以避免一个页面反复看到同一篇脚本。

## 6. 脚本详情页

点击标题后进入独立详情页。

详情页包括：

- 第一标题；
- 一级标签；
- 二级标签；
- 字数；
- 预计口播时长；
- 热点标识（如适用）；
- 完整原始脚本正文。

V1 不默认展示第二、第三候选标题。

## 7. 详情页固定底部工具栏

详情页底部固定工具栏，V1 先提供两个入口：

- `✍️ 脚本改写`
- `📱 小红书排版`

### 点击“脚本改写”

- 自动进入现有脚本改写页面；
- 自动带入当前脚本正文；
- 同时带入当前营销员 IP、账号表达风格、内容方向等上下文；
- 继续使用现有脚本改写规则和题材适配规则。

### 点击“小红书排版”

- 自动进入现有小红书排版页面；
- 自动带入当前脚本；
- 继续遵循“原文不改字，只做排版”的现有规则。

不要求营销员再次复制粘贴。

## 8. 脚本库数据结构

脚本库 Excel 作为首批导入来源。

V1 数据表建议至少包含：

| 字段 | 用途 |
| --- | --- |
| `script_id` | 唯一 ID |
| `level1_tag` | 一级标签 |
| `level2_tag` | 二级标签 |
| `title_1` | 第一标题，前台默认展示 |
| `title_2` | 第二候选标题 |
| `title_3` | 第三候选标题 |
| `body` | 完整正文 |
| `word_count` | 正文字数 |
| `estimated_minutes` | 预计口播时长 |
| `is_hot` | 是否热点脚本 |
| `status` | 是否启用 |
| `created_at` | 导入时间 |
| `updated_at` | 更新时间 |

三个标题应在导入时拆成独立字段，不长期存成一个大字符串。

## 9. 字数与时长

V1 统一采用 **260 字/分钟** 作为口播估算基准。

计算：

`estimated_minutes = word_count / 260`

前台显示一位小数：

- 260 字 → `1.0min`
- 390 字 → `1.5min`
- 520 字 → `2.0min`

后续如果积累了真实用户录制数据，可以升级为个性化语速估算。

## 10. 内容方向与脚本标签映射

前台内容方向与数据库标签不是一一等同。

推荐关系应为：

`IP 内容方向 → 标签映射 → 候选脚本 → 推荐排序`

例如：

`养老规划`
→ 一级标签：养老
→ 二级标签：方案规划 / 规划 / 养老科普 / 养老理念 / 政策

映射应做成可配置规则，不把大量标签散落硬编码在页面中。

一个脚本可以符合多个方向，但同一批推荐只能最终分配给一个方向。

## 11. 使用记录与埋点

脚本推荐要记录使用行为，用于判断哪些脚本更受欢迎，并为后续推荐排序提供数据。

V1 建议记录：

- 曝光（脚本出现在推荐页）；
- 点击详情；
- 点击脚本改写；
- 点击小红书排版；
- 后续如增加收藏，可记录收藏；
- 后续如能确认最终发布，可记录发布。

建议建立类似 `script_user_activity` 的行为表，至少包含：

- `user_id / agent_id`
- `script_id`
- `event_type`
- `content_direction`
- `occurred_at`
- 必要时记录推荐批次 `recommendation_batch_id`

这些数据可用于：

- 统计热门脚本；
- 判断哪些内容方向点击率更高；
- 已经多次使用过的脚本适当降权；
- 后续优化个性化推荐。

## 12. 换一批与重复控制

每个内容方向未来可提供“换一批”。

V1 即使暂不做复杂推荐算法，数据结构也应预留：

- 推荐批次；
- 本批次已占用 script_id；
- 用户近期已看 / 已用脚本；
- 脚本曝光次数与使用次数。

这样后续可以避免营销员每次打开都看到完全相同的 5 篇。

## 13. V1 范围

第一版只做：

1. 脚本 Excel 导入；
2. 正式脚本数据库表；
3. 内容主线与一级/二级标签映射；
4. 每个内容方向默认推荐 5 篇；
5. 同一批次跨方向去重；
6. 热点脚本醒目标识；
7. 脚本卡片：标题 + 同行元信息；
8. 内容方向级推荐原因；
9. 脚本详情页；
10. 固定底部“脚本改写 / 小红书排版”；
11. 自动带入原脚本进入现有工具；
12. 字数与预计时长；
13. 使用行为埋点。

V1 不一次性完成复杂热点抓取、复杂推荐模型或完整运营后台。

## 14. 长期产品原则

- 用户看到的是“内容方向”，不是数据库内部标签；
- 推荐页不改写原脚本；
- IP 主线优先于热点；
- 热点是加权因素，不是内容方向替代品；
- 同一推荐批次不重复脚本；
- 推荐逻辑要可解释，但不要给每篇脚本塞一段推荐理由；
- 标签映射、业务节奏和热点权重优先配置化；
- 使用行为持续沉淀，为后续排序和推荐优化提供真实依据。
