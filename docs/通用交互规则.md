# AIA Auto IP 通用交互规则 V3

本规则适用于 IP 人设、内容规划、脚本改写、小红书排版，以及未来新增的所有对话型功能。局部功能不得另做一套相互冲突的快捷选项、输入和页面跟随逻辑。

## 1. 核心原则

整个工作台优先呈现“聊天”体验，而不是“填表”体验。

- 快捷选项只是帮助用户快速填写答案，不是独立表单。
- 所有选择、自定义补充最终统一汇聚到底部同一个输入区。
- 每一轮回答只保留一个最终动作：**发送**。
- 点击快捷标签不得主动唤起手机输入法。
- 已选标签必须视觉上位于输入框内部，而不是悬在输入框上方。
- 新对话出现后，正常情况下用户应立即看到最新问题、快捷选项和输入区，不需要手动向下寻找。

## 2. 快捷选项与输入区统一规则

### 2.1 页面结构

从上到下固定为：

**问题 → 快捷选项 → 同一输入框（已选标签 + 自由输入）→ 发送按钮**

不得再出现“确认已选”之类的第二个提交按钮。

### 2.2 快捷选项

- 快捷选项放在底部输入区上方。
- 手机端优先保持单行横向排列，超出屏幕宽度后左右滑动，不向下堆叠很多行。
- 右侧可自然露出部分下一选项，让用户感知还能横向滑动，不额外添加冗长说明。
- 空白选项必须删除。
- 普通选项默认白底、细边框；选中后使用极浅红底、AIA Red 文字与边框。
- 选中状态不得使用大片实心红，避免多选时视觉过重。

### 2.3 点击标签不得唤起键盘

这是所有功能的强制规则：

- 点击未选标签：只负责选中并同步到底部输入区，不调用 `focus()`，不主动拉起手机键盘。
- 再次点击已选标签：只负责取消选择并同步移除输入区标签，不主动拉起键盘。
- 点击输入区已选标签的 `×`：只负责删除该标签，不主动拉起键盘。
- 手机键盘只有在用户**主动点击输入框中的可输入位置**时才出现。
- 如果用户本来已经在输入文字、键盘已打开，再点快捷标签时允许键盘保持当前状态，但不得额外触发一次聚焦或页面跳动。

### 2.4 已选标签必须嵌入输入框内部

输入区在视觉上必须是一个完整的编辑器，而不是“标签区 + 输入框”两个分离区域。

例如：

`[年轻家庭 ×] [新手爸妈 ×] 还可以补充其他情况……`

以上内容必须共享同一个边框、白色背景、圆角和聚焦状态。

- 已选项使用独立小标签，与自由输入文字视觉区分。
- 标签和文字可以在同一个输入容器内自然换行。
- 手机端输入区建议最小高度 `44–48px`，内容增多后最多自然增长约 3 行；超过后输入区内部滚动，不无限撑高页面。
- 已选标签建议字号 `12–13px`、高度约 `28–32px`、标签之间间距约 `5–6px`。

### 2.5 双向取消

上下状态必须同步：

- 再次点击上方已选选项：取消选择，输入框内对应标签同步消失。
- 点击输入框内标签的 `×`：标签消失，上方对应选项同步恢复未选中。

不得出现上下状态不一致。

### 2.6 自定义补充

- 用户始终可以直接在同一个输入框内补充其他内容。
- 不再生成空白“其他：____”输入项。
- “其他”如果保留为快捷项，也不得自动拉起键盘；真正进入文字输入只能由用户主动点击输入区。
- 输入框 placeholder 应尽量结合当前问题，例如“还可以补充其他情况…”。

### 2.7 提交

用户最终只点击底部 **发送**。

提交时，将结构化的已选项和自由文本一起作为本轮答案发送。程序内部如有需要，应继续分别保存：

- `selectedOptions`
- `customText`

避免后续统计、画像或规则判断失去结构。

## 3. 单选题兼容原则

单选题也尽量遵循同一心智：快捷项用于快速填写，底部发送用于最终提交。若现阶段某些单选题采用“点一下直接进入下一题”，后续优化时应优先统一为同一套输入心智，避免一个工作台出现多种完全不同的提交方式。

## 4. 新消息自动跟随规则

### 4.1 默认必须自动跟随

在正常连续对话中，只要产生新的用户消息、助手回复、新问题、生成状态或结果提示，对话区必须自动滚动，使最新内容进入可视区域。

尤其是以下场景：

- 首次进入功能，欢迎卡之后出现第一问；
- 用户发送答案之后出现下一道问题；
- AI 返回新回复或生成结果；
- 快捷选项出现、变化或输入区高度变化；
- 切换到某个功能后，该功能已有最新对话内容；

以上场景不得要求用户再手动向下滑动。

### 4.2 自动跟随的目标不是粗暴“滚到底”

自动滚动的体验目标是让用户在手机上能连续看到：

**最新问题 / 最新回复 → 当前快捷选项 → 底部输入区**

因此：

- 只滚动当前功能的对话容器，不滚动整个浏览器页面。
- 应在消息 DOM 更新、快捷选项更新和输入区高度变化后再次校正滚动位置，避免只滚一次但后续布局变化又把最新内容顶出视野。
- 固定顶部导航、IP 悬浮资料条和底部输入区不得遮挡最新消息。
- 对话过程优先使用平滑滚动；最终位置校正可使用无动画滚动，确保位置准确。

### 4.3 系统出现下一题时优先级最高

用户回答完上一题后，系统生成下一题，下一题必须自动出现在当前视野中。

这是 IP 人设、内容规划及未来所有问答功能的强制规则，不能依赖用户继续手动下滑。

### 4.4 尊重用户主动阅读历史

只有当用户主动向上滑动并距离底部超过约 `100px` 时，才视为正在阅读历史内容。

此时：

- 新消息到达后不要强行把页面拉到底部；
- 显示轻量的 `回到最新 ↓` 按钮；
- 用户点击按钮后平滑滚动到最新内容。

一旦用户主动发送新消息，应退出“阅读历史”状态并立即恢复自动跟随。

程序自身触发的滚动、DOM 高度变化或快捷选项更新不能误判成“用户正在阅读历史”。

## 5. 手机端优先规则

- 页面左右安全边距保持 `12–16px`。
- 快捷选项横向滑动，不因为选项多而显著压缩对话区域。
- 已选标签直接嵌入同一个输入容器，不能在输入框上方另起一层。
- 底部始终只保留一个主要提交按钮：**发送**。
- 可点击控件建议最小高度约 `40–44px`；小型已选标签的删除按钮除外，但需保留足够触控区域。
- 点击快捷标签不弹键盘；只有主动点击输入区才弹键盘。
- 新消息出现后，在正常聊天状态下第一时间把最新问题和回答入口带到用户眼前。

## 6. 适用范围

本规则是工作台级公共规则。当前以及未来所有功能，只要出现以下元素，就默认套用本规则：

- 对话消息；
- 快捷选项；
- 多选题；
- 自定义补充输入；
- 新回复 / 新问题；
- 历史消息滚动。

若单个功能确实需要例外，必须在该功能规则中明确说明例外原因，而不是自行形成另一套交互方式。
