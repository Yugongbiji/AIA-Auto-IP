# AIA-Auto-IP · 友邦 AI 内容工作台

面向友邦营销员培训与日常使用的 AI 网页工具。当前用户可见主要功能包括：

1. IP 人设（包含精简的内容主线建议）
2. 脚本改写
3. 小红书排版

项目同时沉淀方法论、Prompt、合规规则、业务规则、Web 实现、自动测试和部署流程。

## 当前技术形态

- 前端：`web/` 下原生 HTML / CSS / JavaScript
- 后端：Python `server.py`
- AI：DeepSeek API
- 数据库：正式环境使用阿里云 RDS；Preview 使用独立 SQLite 测试数据库
- 自动测试：Playwright + axe-core
- 部署：GitHub Actions → Preview / ECS

> 当前项目采用渐进式工程化，不为了局部需求强制重构到大型前端框架。通用工程能力优先复用成熟方案，AIA Auto IP 独有业务流程才重点自定义。

## 核心业务设计

### IP 人设

- 根据已有营销员资料自动跳过已知字段，只追问缺失信息；
- 直接进入且未预填身份时，从姓名开始，再询问 9 位营销员编号，并尝试匹配已有资料库；
- 营销员编号只用于身份识别与资料匹配，不得自动当成执业证编号；
- 不再主动询问个人介绍和生成偏好；
- “做自媒体目的”直接支持：拓客 / 增员 / 拓客和增员都要 / 打造个人品牌；
- “账号表达风格”直接参与脚本改写，并根据脚本题材自动调整强弱；
- 资料完整后直接生成 IP 方案；
- 昵称、简介与定位结果遵循合规规则；
- IP 方案底部直接包含“你的内容主线”，不再进入独立内容规划流程。

### IP 方案中的内容主线

- 拓客：保险专业主线 + 泛内容支线；
- 增员：增员内容主线 + 泛内容支线；
- 拓客和增员都要：拓客内容主线 + 增员内容主线 + 泛内容支线；
- 每条主线只展示：内容方向 / 合集推荐 / 对账号的作用；
- 合集名称不超过 5 个汉字；
- “对账号的作用”使用短标签；
- 泛内容必须来自本人真实兴趣、经历或积累，没有依据时显示“暂未确定”；
- 详细规则：`rules/ip-content-strategy-rules.md`。

> 旧内容规划 API、历史表和方案数据暂时保留兼容，但用户界面已经撤销独立“内容规划”入口。

### 脚本改写 / 小红书排版

具体内容逻辑与输出规则以对应规则和文档为准。

### 简介合规输出

- 小红书简介最后一句固定为个人意见声明；
- 视频号 / 抖音简介末尾连续固定为：个人意见声明 → 营销服务部 → 执业证编号；
- 营销员编号与执业证编号严格区分；真实执业证编号暂未采集时，预览使用 `000` 占位并提醒发布前替换。

## 开发与发布流程

默认流程：

`需求 → 读取当前任务看板 → Build vs Reuse → 开发分支 → 修改代码 → 自动测试 → Frontend QA → QA 通过 → Preview → 产品验收 → 明确允许上线 → 合并 main → main QA → 正式 ECS → 健康检查 → 更新任务看板/技术决策记录`

硬性规则：

- QA 全绿不等于允许正式上线；
- 未经明确授权，不自行合并 main；
- 普通需求不直接在正式 ECS 上试错；
- Preview 与正式数据保持隔离；
- 正式部署保留健康检查和失败回滚。
