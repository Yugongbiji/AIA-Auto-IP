# 小红书排版规则 V4

> 本文件补充并更新 `docs/脚本改写与小红书排版规则.md` 中的小红书排版部分。发生冲突时，以本文件为准。

## 0. 排版前先清理“脚本库结构标记”

有些输入来自脚本库，里面会带为了内部管理而加的结构标记。这些标记不是正文内容，进入小红书排版前应先删除。

### 0.1 多个候选标题

如果开头有 1 / 2 / 3 三个候选标题：

- 只保留第一个标题；
- 第一个标题前的 `1.`、`1、`、`标题1：` 等序号/标签全部删除；
- 第二、第三个标题整行删除；
- 不把“标题1 / 标题2 / 标题3”带进最终排版。

### 0.2 章节结构标记

`开头`、`正文`、`正文1 / 正文2 / 正文3 ...`、`结尾`、`脚本正文`、`文案正文` 等内部结构标签全部删除标签本身；同一行有真实正文时保留正文。

### 0.3 边界

- 只删除确定的脚本库元数据/结构标签；
- 除明确结构标签外不得擅自删除正文；
- 无法确认时宁可保留。

## 1. 不改正文

完成结构清理后，小红书排版只允许增加换行、空行和与语义匹配的表情符号，不得修改、删除、替换、调换正文任何文字或标点，不新增观点、事实、承诺或营销引导。

## 2. 段落与阅读节奏

- 每段最多 2 个完整句子；
- 长句优先在逗号、分号、冒号等自然停顿处换行；
- 标题独立成行；
- 不使用 Markdown 井号、星号等 AI 式排版符号；
- 目标是手机端扫读时一眼能抓住重点，不出现连续大段文字墙。

### 2.1 禁止孤立标点和拆散成对符号（硬规则）

排版后的任何非空行都不能只剩标点、括号或引号。以下情况一律判定为不合格并在展示前修复：

- `【`、`】`、`（`、`）`、`“`、`”`、`，`、`。`、`！`、`？`、`：`、`；` 等单独占一行；
- `】。`、`。”`、`！】` 等只有标点/闭合符号而没有正文字符的一整行；
- 换行把 `【……】`、`（……）`、`“……”` 等成对符号与其正文拆开，导致开符号或闭符号悬空；
- 句末标点被换到下一行，与所属正文分离。

换行只能发生在语义单元之间。程序化质量检查应在最终展示前扫描并合并上述孤立符号行，不能只依赖模型自行遵守。

## 3. 表情符号不是装饰，而是视觉锚点

表情的任务是帮助读者快速识别关键词、场景和段落作用。

### 3.1 语义表情库

- 理赔 / 赔付：✅
- 合同 / 条款 / 责任：📄
- 风险 / 提醒 / 注意：⚠️
- 健康：❤️
- 医疗 / 医院：🏥
- 教育 / 升学：🎓
- 育儿 / 孩子：🧸
- 养老 / 银发：🌿
- 家庭 / 父母：👪
- 保障 / 保单 / 保险：🛡️
- 投保：📝
- 预算 / 保费 / 税务：🧾
- 财富 / 资产：💰
- 社保 / 医保 / 政策：🏛️
- 法律：⚖️
- 骑行：🚴
- 跑步：🏃
- 游泳：🏊
- 运动：🏅
- 户外：🏕️
- 旅行：✈️
- 企业主：🏢
- 创业：🚀
- 职场：💼
- 团队 / 服务 / 沟通：🤝 / 💬
- 数据 / 比例 / 金额：📊
- 案例 / 选择：🔎
- 故事：📖
- 重点 / 核心：📌
- 方法 / 建议：💡
- 清单：📋
- 步骤 / 计划：🧭

有明确语义时优先使用语义表情，不应大量退化成 📌 / 💡 / ✨ / ✅ 等通用表情。

### 3.2 密度与重复规则

- 整体目标：平均每 1～2 句话至少出现 1 个表情锚点；
- 任何连续 2 个完整句子中，至少有 1 个表情；
- 一句话内通常最多增加 1～2 个表情，避免表情墙；
- 同一篇文章不要机械重复同一种通用表情，应根据语义尽量丰富；
- **并列内容是明确例外**：同一组并列项、同级清单、连续步骤为了建立一致视觉结构，可以重复使用同一个表情。例如五个并列注意事项都用 `⚠️`、三个并列步骤都用 `✅`，这是合格排版，不应被“重复率”规则误判；
- 重复率检查必须识别“并列结构”和“非并列正文”：只限制非并列正文中无语义理由的机械重复。

## 4. 关键词强调规则

1. 优先识别标题、段落中心词、专业关键词、场景关键词、结论词；
2. 同一句中多个关键词时，只选择最重要的 1～2 个做视觉强调；
3. 同一关键词在短距离内重复出现时，不必每次重复加相同表情；
4. 表情不得插入产品名称、数字、固定专有名词内部；
5. 加表情后必须保持原文字符顺序完全不变。

## 5. 输出质量检查（展示前执行）

小红书排版完成后至少检查：

- 多标题输入是否只保留第一个标题，且序号已去掉；
- 内部脚本结构标记是否已清理；
- 正文文字和标点是否完整保留；
- 是否存在孤立标点、孤立括号、孤立引号、句末标点单独成行；
- 成对符号是否被换行错误拆散；
- 每段是否不超过 2 个完整句子；
- 是否存在连续 2 句话完全没有表情；
- 核心词附近是否有合适的语义表情；
- 非并列正文是否机械重复 📌 / ✨ / 💡 / ✅ 等通用表情；
- 并列内容使用相同表情时不得误判为单调；
- 是否存在过度堆叠、影响阅读的表情；
- 长文整体是否形成稳定的“文字—视觉锚点—留白”节奏。

硬规则失败时，不直接把不合格结果展示给用户，应先进行确定性修复；无法安全修复时再重新生成。
