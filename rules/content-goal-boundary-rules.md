# AIA Auto IP 拓客 / 增员内容边界与分类规则 V3（当前版）

> 当前最高事实源：`docs/product/CURRENT_EFFECTIVE_REQUIREMENTS_LEDGER_20260825.md`。
> 页面结构与主线/支线细节同时服从 `rules/ip-content-strategy-rules.md`。

## 1. 目标来源：只读标准化 `primaryGoal`

原始报名字段 `purpose` 只作为目标判断输入，**不是最终业务目标真源**。

最终 `primaryGoal` 只能是：

- `customer_acquisition`：拓客；
- `recruitment`：增员。

以下历史值不能直接驱动内容策略，必须重新询问并二选一：

- 拓客和增员都要；
- 两者兼顾 / 同时做；
- 打造个人品牌；
- 打造专业形象；
- 其他不能唯一判断拓客/增员的描述。

`SUPERSEDED`：旧“purpose 是唯一业务目标来源”“拓客和增员都要同时生成两条专业主线”“打造个人品牌默认走专业信任内容”“不得再次询问目标”等规则。

## 2. 拓客保险主线

当 `primaryGoal = customer_acquisition` 时，保险主线只能来自受控保险业务主题，例如：

- 保险科普 / 保险知识；
- 家庭保障；
- 医疗保障；
- 重疾保障；
- 意外保障；
- 理赔知识；
- 养老规划；
- 财富规划；
- 教育规划 / 教育金；
- 税优 / 个人养老金等客户需求相关主题。

禁止把招聘、加入团队、职业机会、转型招募等纯增员内容作为拓客保险主线。

## 3. 增员主线

当 `primaryGoal = recruitment` 时，专业主线统一属于“增员与职业发展”，可向下匹配：

- 转型经历；
- 行业发展；
- 公司与团队；
- 个人成长；
- 从业日常；
- 职业价值。

禁止把重疾险、医疗险、意外险、教育金、家庭保障方案、理赔知识、保单配置等纯拓客内容作为增员主线。

## 4. 内容支线

内容支线与拓客/增员主线是不同维度。它来自本人真实身份、经历、兴趣、客户反馈等，用于增加真实感、打开专业内容之外的长期话题入口。

可以包括：

- 育儿 / 升学；
- 健康养生（非保险保障主题）；
- 骑行 / 跑步 / 户外 / 运动；
- 法律常识；
- 职场成长；
- 创业经营；
- 旅行 / 摄影 / 读书 / 美食；
- 其他有本人真实积累且可持续的生活/专业支线。

硬边界：

- 生活兴趣不得因为脚本库标签叫“健康 / 教育 / 养老 / 财富”就升级为保险主线；
- 泛健康知识/养生 ≠ 医疗保障；
- 育儿/升学经验 ≠ 教育金保险；
- 泛养老生活 ≠ 养老保险规划；
- 一般职场成长 ≠ 增员招募。

内容支线必须有真实证据；未知方向不能只因词库未收录而丢弃，应进入统一评分。

## 5. 脚本库标签只是内部匹配层

脚本库一级/二级标签不能直接决定前台主线归属。

内部匹配示例：

- 保险 / 医疗险 / 重疾险 / 理赔 / 教育金 / 养老 / 保险财富 → 可作为拓客保险主线候选脚本标签；
- 增员相关标签 → 增员主线候选脚本；
- 育儿、健康、运动、旅行等 → 只有与当前内容支线一致时进入内容支线区域。

具体脚本正文内容优先于标签名称。标签映射应配置化，不能让标签名称反向修改 IP 内容方向。

## 6. 主目标硬过滤

### `primaryGoal = customer_acquisition`

- 只允许受控保险业务主题成为专业主线；
- 纯增员/招聘/团队招募内容不得成为专业主线；
- 真实生活/兴趣内容仍可作为一条内容支线。

### `primaryGoal = recruitment`

- 专业主线只使用增员与职业发展；
- 纯保险产品/保障配置内容不得成为增员专业主线；
- 真实生活/兴趣内容仍可作为一条内容支线。

不存在第三种“双主线”最终状态。

## 7. 展示前校验

无论候选来自程序还是 AI，最终展示前必须检查：

1. 是否读取标准化 `primaryGoal`，而不是重新读取 raw purpose 猜目标；
2. 拓客主线是否混入纯增员主题；
3. 增员主线是否混入纯保险产品主题；
4. 健康养生、育儿、旅行等是否被误升级成保险主线；
5. 内容支线是否有本人真实资料依据；
6. IP 方案与脚本推荐是否读取同一 canonical 主线/支线；
7. 任何历史内容规划、旧 purpose 或旧 Vxx 是否再次覆盖结果。

任一失败都不直接展示。
