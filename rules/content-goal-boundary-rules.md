# AIA Auto IP 拓客 / 增员内容边界与分类规则 V1

> 本文件定义内容规划中“拓客为主 / 增员为主”的硬边界。它与 `content-planning-rules.md` 配合使用：本文件决定专业内容主线服务什么目标；后者决定泛内容支线如何选择。

## 1. 总原则

营销员在内容规划第一步选择主目标后，**专业内容主线必须严格服从这个主目标**：

- 选择 **拓客为主**：专业内容只能围绕寻找保险准客户、建立保险相关专业信任和激发保障/规划需求展开；
- 选择 **增员为主**：专业内容只能围绕吸引潜在新人了解行业、职业、公司、团队和个人成长展开；
- 不允许因为营销员本身是保险从业者，就把所有保险专业内容同时塞进“增员”方案；
- 主目标不是内容标签，而是后续专业内容筛选的硬过滤条件。

## 2. 拓客内容

### 2.1 目标

让潜在保险客户产生以下一种或多种结果：

- 认识风险；
- 理解保障或规划问题；
- 建立对营销员专业能力的信任；
- 产生保险、养老、医疗、财富、教育金、税优等相关咨询需求。

### 2.2 当前脚本库中可归入拓客专业内容的标签

根据现有脚本库一级/二级标签，第一版映射如下：

| 一级标签 | 二级标签 | 分类 |
| --- | --- | --- |
| 保险 | 总计、财富、方案、方案规划、风险理念、理赔、养老 | 拓客专业内容 |
| 财富 | 总计、财富、财经 | 拓客专业内容 |
| 健康 | 总计、疾病医疗、情感、养生、医疗险、意外险、政策、重疾险 | 原则上归拓客；其中非保险生活健康话题需结合具体脚本再判断是否泛内容 |
| 教育 | 教育金 | 拓客专业内容 |
| 税优 | 总计、报税、个养、税法 | 原则上归拓客专业内容 |
| 养老 | 总计、方案规划、规划、税优系列、养老科普、养老理念、政策 | 拓客专业内容 |

说明：标签映射用于第一轮筛选，**具体脚本内容优先于标签名称**。例如“健康-情感”如果实际完全不涉及保险、保障或专业服务，应重新归为泛内容，而不是因为一级标签是“健康”就强行算拓客。

### 2.3 拓客典型方向

包括但不限于：

- 保险科普；
- 风险理念；
- 家庭保障；
- 医疗 / 重疾 / 意外保障；
- 理赔知识；
- 养老规划；
- 财富规划；
- 教育金规划；
- 税优与个人养老金等与客户规划需求直接相关的内容。

## 3. 增员内容

### 3.1 目标

让潜在新人产生以下一种或多种结果：

- 对保险行业和职业产生兴趣；
- 理解这份工作的真实状态和发展空间；
- 认同营销员本人、团队或公司平台；
- 愿意进一步了解加入团队或职业转型的可能性。

### 3.2 增员专业内容方向

增员内容优先从以下方向选择：

1. **转型经历**：为什么转行、原职业痛点、转型过程、转型前后变化、真实从业感受；
2. **行业与职业发展**：行业变化、职业路径、成长空间、工作方式、职业前景；
3. **公司与团队**：团队氛围、培养体系、学习机制、团队活动、公司平台、工作文化；
4. **个人成长**：专业能力、沟通能力、自我管理、学习成长、从业后的变化；
5. **从业日常**：一天的工作、学习培训、团队会议、客户沟通、真实工作场景；
6. **职业价值**：帮助他人的价值感、长期事业感、个人影响力、资源与能力积累。

### 3.3 当前脚本库标签

当前标签表中明确存在：

| 一级标签 | 二级标签 | 分类 |
| --- | --- | --- |
| 增员 | 总计、增员 | 增员专业内容 |

当前增员标签颗粒度明显低于拓客。后续整理脚本库时，建议逐步细分为：`转型经历 / 行业发展 / 公司团队 / 个人成长 / 从业日常 / 职业价值`，但本次规则不要求为了分类立即重做整个脚本库。

## 4. 泛内容支线

泛内容支线与“拓客 / 增员专业主线”是两个维度。

泛内容的目标是：

- 增加账号的活人感和丰富度；
- 打开保险专业内容以外、更宽的受众和流量入口；
- 展示营销员真实兴趣、经历、知识和生活身份。

因此：

- 拓客账号可以选择育儿、升学、骑行、户外、法律、运动等泛内容；
- 增员账号也可以选择这些泛内容；
- 泛内容不因为主目标是增员，就必须改写成“职业机会”；
- 泛内容也不因为主目标是拓客，就必须强行转回保险。

当前脚本库中，以下标签优先作为泛内容候选：

| 一级标签 | 二级标签 | 默认分类 |
| --- | --- | --- |
| 教育 | 育儿 | 泛内容支线 |
| 热点 | 总计、节日节点、节日热点、营销热点 | 泛内容素材/支线，需结合本人定位判断 |

其他如升学规划、户外、骑行、运动、法律、职场、生活方式等，只要符合 `content-planning-rules.md` 的泛内容硬边界，也可以作为泛内容候选。

## 5. 主目标硬过滤

### 当 `primaryGoal = 拓客`

专业内容允许出现：保险、保障、风险、理赔、养老、医疗、财富、教育金、税优等客户需求相关方向。

专业内容不得把以下内容作为主方向：招聘、加入团队、职业机会、转型招募、团队扩张等纯增员内容。

### 当 `primaryGoal = 增员`

专业内容允许出现：转型经历、行业发展、公司团队、个人成长、从业日常、职业价值等增员方向。

专业内容不得把以下内容作为主方向：重疾险、医疗险、意外险、教育金、保险产品、家庭保障方案、理赔知识、保单配置等纯拓客内容。

注意：营销员在增员内容中可以自然提及自己服务客户、学习保险专业知识等真实工作背景，但**不能因此把客户保险科普当成增员专业方向**。

## 6. 生成后的二次校验

AI 生成内容规划后必须再做目标一致性检查，不能只依赖 Prompt 自觉遵守。

至少检查：

1. `primaryGoal` 是否明确；
2. 专业内容方向是否全部属于该目标；
3. 是否混入另一目标的明显关键词或主题；
4. 泛内容是否被错误归类成专业内容；
5. 泛内容是否又被强行改写成保险内容；
6. 如果出现越界，优先重新生成或过滤越界方向，不直接把冲突方案展示给营销员。

## 7. 内容规划结果结构

推荐的逻辑结构为：

- **主目标**：拓客为主 / 增员为主（二选一）；
- **专业内容主线**：严格由主目标决定；
- **泛内容支线**：从本人真实积累中选择一个长期方向；
- **候选方向**：仅用于比较泛内容候选，最终只能推荐一个；
- 专业内容和泛内容的边界必须清晰。

## 8. 后续脚本库标签接入原则

当脚本库完整一级/二级标签可供程序读取后，应建立可配置映射，而不是把大量标签散落硬编码在 Prompt 中。

建议至少保存：

- 一级标签；
- 二级标签；
- `content_goal`：`acquisition / recruitment / general`；
- `content_type`：`professional / general`；
- 必要时增加人工复核状态。

以后新增标签先更新映射，再进入内容推荐。这样脚本库、内容规划和 AI 生成使用同一套分类标准。
