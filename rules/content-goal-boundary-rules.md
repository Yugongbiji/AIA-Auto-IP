# AIA Auto IP 拓客 / 增员内容边界与分类规则 V2

> 本文件定义专业内容主线中“拓客 / 增员”的硬边界。自 V2 起不再通过独立内容规划提问选择主目标，而是直接读取 IP 档案 `purpose`。页面结构以 `rules/ip-content-strategy-rules.md` 为准。

## 1. 目标来源

`purpose` 是唯一业务目标来源：

- `拓客`：只生成拓客专业内容主线；
- `增员`：只生成增员内容主线；
- `拓客和增员都要`：同时生成拓客与增员两条专业主线；
- `打造个人品牌`：默认以专业信任内容为主，不自动增加增员方向。

不得在后续流程再次询问“拓客为主还是增员为主”。

## 2. 拓客内容

### 目标

拓客的目标是寻找保险准客户、建立保险相关专业信任、推动保障或规划需求产生。

典型内容包括：

- 保险科普；
- 风险理念；
- 家庭保障方案；
- 医疗 / 重疾 / 意外保障；
- 理赔案例与理赔知识；
- 养老规划；
- 财富规划；
- 教育金规划；
- 税优与个人养老金等客户需求相关内容。

### 当前脚本库第一版映射

| 一级标签 | 二级标签 | 分类 |
| --- | --- | --- |
| 保险 | 总计、财富、方案、方案规划、风险理念、理赔、养老 | 拓客专业内容 |
| 财富 | 总计、财富、财经 | 拓客专业内容 |
| 健康 | 疾病医疗、医疗险、意外险、重疾险及相关政策 | 拓客专业内容 |
| 教育 | 教育金 | 拓客专业内容 |
| 税优 | 报税、个养、税法 | 原则上归拓客专业内容 |
| 养老 | 方案规划、规划、税优系列、养老科普、养老理念、政策 | 拓客专业内容 |

具体脚本内容优先于标签名称。例如“健康-情感”如果完全不涉及保险、保障或专业服务，应重新判断是否属于泛内容。

## 3. 增员内容

### 目标

增员的目标是让潜在新人了解行业、职业、公司和团队，建立对本人及团队的信任，并愿意进一步了解职业转型或加入团队的可能性。

典型内容：

1. **转型经历**：为什么转行、转型过程、前后变化、真实从业感受；
2. **行业发展**：行业变化、职业路径、成长空间、工作方式；
3. **公司与团队**：团队氛围、培养体系、学习机制、公司平台；
4. **个人成长**：沟通、专业、自我管理、学习成长；
5. **从业日常**：工作一天、客户沟通、培训、团队会议；
6. **职业价值**：帮助他人的价值感、长期事业感、个人影响力。

当前脚本库中一级/二级标签“增员”默认归增员专业内容。后续标签库建议逐步细分为：`转型经历 / 行业发展 / 公司团队 / 个人成长 / 从业日常 / 职业价值`。

## 4. 泛内容支线

泛内容与拓客 / 增员专业主线是不同维度。它用于扩大受众、增加活人感和打开新的话题流量入口。

可以包括：育儿、升学、骑行、户外、运动、法律、职场、女性成长、旅行等，但必须来自本人真实经历或积累。

当前脚本库中：

- 教育 → 育儿：优先视为泛内容；
- 热点 → 节日节点 / 节日热点 / 营销热点：可作为泛内容素材，但需结合本人定位判断。

泛内容不能因为主目标是拓客就强行拐回保险，也不能因为主目标是增员就强行变成招聘内容。

## 5. 主目标硬过滤

### purpose = 拓客

允许：保险、保障、风险、理赔、养老、医疗、财富、教育金、税优等客户需求相关方向。

禁止把招聘、加入团队、职业机会、转型招募等纯增员内容作为专业主线。

### purpose = 增员

允许：转型经历、行业发展、公司团队、个人成长、从业日常、职业价值。

禁止把重疾险、医疗险、意外险、教育金、家庭保障方案、理赔知识、保单配置等纯拓客内容作为增员专业主线。

### purpose = 拓客和增员都要

两类专业主线可以同时存在，但必须分开呈现，不能把“保险科普”和“职业招募”混成同一条方向。账号同一阶段仍建议有明显主次。

## 6. 生成后的校验

无论内容策略来自程序规则还是 AI，展示前都要检查：

1. 是否读取了正确 `purpose`；
2. 拓客专业方向是否混入纯增员主题；
3. 增员专业方向是否混入纯保险科普；
4. 泛内容是否被错误归成保险或招募；
5. 泛内容是否有本人真实资料依据；
6. 发现越界时过滤或重新生成，不直接展示冲突结果。

## 7. 后续脚本库标签接入

脚本库完整标签接入后优先做成可配置映射，至少保存：

- 一级标签；
- 二级标签；
- `content_goal`：`acquisition / recruitment / general`；
- `content_type`：`professional / general`；
- 必要时增加人工复核状态。

新增标签先更新映射，再进入推荐，不把大量标签散落硬编码在 Prompt 中。
