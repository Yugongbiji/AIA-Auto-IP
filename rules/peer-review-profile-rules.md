# 身边人评价资料并入个人档案规则 V1

## 目标

把“营销员身边的人对 TA 的评价”作为 IP 基础信息的一部分，但必须与营销员本人填写、报名表事实资料严格区分。

评价数据用于帮助识别：别人实际感受到的人设特征、愿意向 TA 咨询的话题、自然形成的社会角色和真实口碑表达。它可以参与 IP 定位、昵称/简介角度、内容支线判断和脚本表达参考，但不得把第三方评价自动升级为本人已确认的执业能力、专业资质、服务范围或事实经历。

## 数据关系

采用“一名营销员 → 多条评价”的一对多结构。

- 营销员主键：9 位营销员编号 `agentId`；
- 每位评价者保留一条原始记录；
- 不把多位评价者强行摊平到个人表的一行；
- 原始评价永久保留，个人档案只保存聚合摘要；
- 重新导入同一份最新完整 Excel 时，以该 Excel 作为当前快照重新聚合。

## 推荐 Excel 格式

保持当前问卷导出的 7 列即可，不需要人工整理成一人一行：

1. 你平时怎么称呼 TA？
2. 你和 TA 的关系？
3. 如果只能选 3 个词形容 TA，你会选？
4. 遇到什么事情，你比较愿意找 TA 聊聊？
5. 如果把 TA 介绍给朋友，你觉得 TA 更像哪种人？
6. 如果只能用一句话把 TA 介绍给一个不认识的人，你会怎么说？
7. 请输入分享给你问卷的营销员信息（9 位营销员编号）

最重要的稳定字段是第 7 列营销员编号。后续如果问卷平台允许，建议列标题尽量固定，不要频繁改字；选项可增加，但不要改变营销员编号字段的含义。

## 原始明细

每条评价至少保留：

- `agent_id`
- 评价者称呼
- 与营销员关系
- 三个词/形容词
- 愿意咨询的话题
- 朋友介绍角色
- 一句话介绍
- 导入时间

## 聚合摘要

按营销员编号聚合生成：

- 评价人数；
- 高频关系类型；
- 高频人物印象；
- 高频咨询话题；
- 高频角色认知；
- 代表性自然语言评价（少量原句）；
- 面向前端的简短关键词摘要。

## 使用边界

### 可以使用

- IP 人设特征：例如多人都选择“靠谱、专业、行动派”；
- 表达气质参考：例如多人认为本人“暖心、有梗、人间清醒”；
- 社会角色：例如“专业顾问、靠谱搭子、暖心树洞”；
- 内容支线线索：例如大量身边人愿意找 TA 聊育儿、生活方式、职业转型；
- 简介和昵称的角度参考；
- 脚本改写时判断“别人眼中的 TA”是否与本人选择的表达风格一致。

### 不可以自动当成事实

- 资质、证书、荣誉；
- 实际可提供的保险/财富/养老等服务；
- 本人的职业经历、教育经历；
- 本人的真实兴趣爱好；
- 任何需要本人确认的业务能力。

例如：朋友勾选“财富规划”，只能说明“身边人愿意就财富规划话题找 TA 聊”，不能自动写入“本人提供财富规划服务”。

## 与个人档案的关系

个人档案中保留独立字段：

- `peerReviewSummary`：结构化聚合数据；
- `peerReviewKeywords`：可直接展示的简短摘要。

它们属于“第三方评价来源”，不覆盖 `services`、`education`、`previousCareer`、`hobbies` 等本人事实字段。

## 导入方式

仓库提供 `peer_review_import.py`。最终 Excel 导出后，可直接运行：

`python peer_review_import.py <评价Excel路径>`

脚本会按营销员编号识别一人多条评价、保留原始明细并把聚合摘要合并进现有个人档案。未能匹配当前营销员主表的编号必须报告，不静默编造或新建营销员。
