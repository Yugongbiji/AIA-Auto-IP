# 字段来源与采集规范（v8）

> 当前字段语义必须服从 `docs/product/CURRENT_EFFECTIVE_REQUIREMENTS_LEDGER_20260825.md` 与 `rules/product-rule-ownership.md`。
> 代码化 schema 只负责字段来源/类型，不得覆盖当前产品业务规则。

字段分三类来源：
- **questionnaire**：已收回问卷；
- **backendExcel**：后台 Excel 可批量获取；
- **toCollect**：建议补充收集。

## A. 问卷字段（questionnaire）

| 字段 | 说明 | 工具用途 |
|---|---|---|
| 姓名 `name` | 身份识别 / 资料匹配；也是无法获得更自然称呼时的人物称呼兜底 | 昵称必须始终保留“人”的主体 |
| 营销员编号 `agentId` | 9 位数字，仅用于身份识别、资料库匹配和历史资料恢复 | **不得当成执业证编号输出** |
| 日常称呼 `preferredName` | 本人明确希望使用的称呼；如果有客户反馈高频真实称呼，后者优先 | 昵称人物锚点之一 |
| 简单自我介绍 `selfIntro` | 已有资料直接复用，不主动重复询问；必须在“我的资料”中展示，并参与语义提取 | 职业、生活身份、兴趣等事实线索 |
| 微信视频号昵称 / 小红书昵称 | 现有账号参考；长期自然、合规、有稳定识别度时谨慎保留 | 原昵称审查 |
| 自媒体成效 | 事实型成就线索 | 仅有真实记录时参与优势判断 |
| 做自媒体主要目的 `purpose` | 历史原始字段，只作为 raw source | 由 `ip-policy-core.js` 标准化为 `primaryGoal`；若为双目标/个人品牌/模糊值必须重新询问 |

## B. 后台 Excel 字段（backendExcel）

| 字段 | 说明 | 工具用途 |
|---|---|---|
| 年龄 | 后台如有则读取，不作为昵称自动加“哥/姐”的依据 | — |
| 城市 `city` | 真实地域 | 可参与优势/简介/昵称素材，但不得机械生成“城市+称呼”标签式昵称 |

## C. 建议收集字段（toCollect）

| 字段 | 取值示例 | 工具用途 |
|---|---|---|
| 学历 `education` | 大专 / 本科 / 硕士 / 博士 | 学历维度判定；快捷项不得含“跳过/不希望填写” |
| 最高学校背景 `schoolTier` | 985 / 211 / QS 前 100 等 | 只能按原始层级使用，不得反推具体学校 |
| 留学背景 `overseas` | 有 / 没有 + 已明确事实 | 不得反推国家或院校 |
| 保险从业时间 `insuranceYears` | 9 年 | 专业背书事实 |
| 荣誉 `honors` | MDRT / TOT / COT / 五星会员 | 成就维度；不得机械拼昵称 |
| 过往职业/长期经历 `previousCareer` | 教师 / 医生 / 工程师 / 创业等 | 真实差异化身份；支持多选/自由输入 |
| 家庭与生活身份 `lifeRoles` | 宝妈 / 宝爸 / 其他长期身份 | 内容支线、人设表达线索 |
| 爱好 `hobbies` | 骑行 / 跑步 / 读书等 | 内容支线与简介补充；只用真实长期积累 |
| 擅长领域 / 可提供服务 `services` 等 | 养老规划 / 保障规划 | 服务型简介；只能来自本人真实资料 |
| 账号表达风格 `contentTone` | 专业理性 / 亲和温暖 / 风趣幽默 / 干练直接 / 自然真实 / 观点鲜明 / 沉稳可信 / 犀利敢说 | 脚本改写长期风格偏好；每篇仍先做题材适配 |
| 营销服务部 `department` | 成都一部 | 视频号 / 抖音合规尾部 |
| 执业证编号 `licenseNumber` 等 | 真实执业证编号 | 视频号 / 抖音合规尾部；无真实值时仅预览占位 `000` |

## D. 客户反馈字段

- 原始明细按营销员编号一对多保存；
- 聚合摘要放在 `peerReviewSummary`；
- 称呼、关系、人物印象、愿意聊的话题、角色认知、代表性评价分问题展示；
- 高频真实称呼优先于本人 `preferredName` 作为昵称人物锚点；
- 客户反馈只能证明“别人怎么看/怎么称呼/愿意聊什么”，不得升级为本人资质、服务能力、教育经历或真实兴趣。

## 账号表达风格的数据边界

- `contentTone` 面向用户统一叫“账号表达风格”。
- 可选 1～2 个，也允许本人自由输入。
- 旧值兼容：`生活化真诚` → `自然真实`；`轻松有梗` → `风趣幽默`。
- 必须参与脚本改写的人设代入，但只是长期偏好，不是绝对命令。
- 高敏感题材优先尊重、克制、清楚；专业严肃题材优先准确；普通题材才正常释放幽默/犀利等风格。
- 风格不得改变原稿事实、数字、产品责任、核心观点或合规边界。

## 昵称的数据边界

- 最终昵称必须有且只有一个明确人物称呼主体。
- 称呼来源优先级：客户反馈高频真实称呼 > 本人明确希望称呼 > 姓名自然称呼 > 本名兜底。
- 没有可用称呼时不得生成不含人物主体的“定位型昵称”；应提示称呼资料不足或使用本名兜底。
- 不根据年龄/性别机械生成“X哥/X姐”；不根据学历层级推断学校；不根据留学反推国家。
- 地域、学历、荣誉、性格、职业等只能作为受控修饰素材，不能机械拼成 `成都+称呼 / TOT+称呼 / 985+称呼 / 有温度+称呼`。

## 服务型简介的数据边界

- 服务能力只能来自本人已提交、已确认的 `services/serviceAreas/serviceCapabilities/expertise/specialties` 等字段。
- 不从身份、客户反馈、内容方向或营销员职业自动反推服务能力。
- 服务短词建议 2～4 个汉字，最多 3～4 项；不能可靠压缩时宁可少写。
- 小红书需经过平台敏感词过滤；视频号 / 抖音合规尾部由 `ip-policy-core.js:complianceFooter()` 唯一追加。

## 身份字段与合规字段边界

- `agentId`：9 位营销员编号，仅做匹配/恢复/身份识别。
- `licenseNumber/licenseId/practiceLicense`：执业证编号，视频号/抖音合规输出使用。
- 两者语义不同，**禁止用 `agentId` 自动填充执业证编号**。

## 判断轮维度映射

| 维度 | 数据来源 |
|---|---|
| 身份/职位 | 真实职业、生活身份、报名角色 |
| 性格特质 | 本人明确自述 + 客户反馈高频印象 |
| 地域 | 城市 |
| 专业 | 从业时间 + 真实服务 + 资质 |
| 学历 | 学历层级 + 学校层级 + 留学事实 |
| 成就/荣誉 | MDRT/TOT/COT/五星等真实荣誉 + 已确认自媒体成效 |

学历只能按真实层级表达：博士/硕士/985/211/QS 等可视情况突出；不得由层级反推出具体学校。普通本科/大专/未知默认不作为强差异化资产，但仍是正常真实资料，不得当成“短板”展示。

## 当前业务目标字段

最终业务目标只有 `primaryGoal`：
- `customer_acquisition`
- `recruitment`

`purpose` 只是历史/报名 raw source。只有明确单目标时可映射；`拓客和增员都要 / 两者兼顾 / 同时 / 打造个人品牌 / 专业形象` 等必须重新询问，不能直接成为最终状态。
