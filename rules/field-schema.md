# 字段来源与采集规范（v6）

> 代码化版本见 `../src/fields-schema.js`。前端按 `source` 分组渲染表单。

字段分三类来源：
- **questionnaire**：已收回问卷（57 人，持续补充）
- **backendExcel**：后台 Excel 可批量获取
- **toCollect**：建议补充收集（决定人设深度，优先收集）

## A. 问卷字段（questionnaire）

| 字段 | 说明 | 工具用途 |
|------|------|----------|
| 姓名 | 与后台 Excel 交叉校验 | 身份识别 / 资料匹配；不默认直接用于公开昵称 |
| 营销员编号 | 9 位数字；仅用于身份识别、资料库匹配和历史资料恢复 | **不得当成执业证编号输出** |
| 日常称呼 `preferredName` | 别人平时怎么称呼本人，例如“芳姐”“小宇”“老周”；必须来自本人提交或已确认资料 | 昵称生成优先使用，比直接使用全名更自然、有亲和力 |
| 培训确认 | 全勤线下培训 + 社群陪跑要求 | — |
| 简单自我介绍（自媒体优势） | 已有问卷数据可继续作为 AI 内部参考，但不再主动向用户询问 | 喂「人设优势判断轮」 |
| 微信视频号昵称 / ID / 粉丝数 | — | 现状参考；ID 禁含友邦拼音 |
| 小红书号 / 粉丝数 / 主页链接 | — | 现状参考；号禁含友邦拼音 |
| 自媒体成效（缘故/转介绍·公域咨询·业绩转化） | — | 喂「成就」维度 |
| 做自媒体主要目的 | ★ | 内容规划参考 |
| 当前账号运营状态 | — | — |
| 运营卡点（可多选） | — | Phase2 内容规划 |
| 每周愿投入时间 | — | — |
| 未达预期打算 | — | — |

## C. 建议收集字段（toCollect）

| 字段 | 取值示例 | 工具用途 |
|------|----------|----------|
| 学历 | 本科 / 硕士 / 博士 | 学历维度判定 |
| 最高学校背景 | 985 / 211 / QS50 / QS100 / 校名 | 学历维度关键依据 |
| 是否有留学背景 | 是/否 + 留学院校 | 留学=学历可突出 |
| 保险从业时间 | 9 年 | 喂「专业」维度 |
| 荣誉 | MDRT / TOT / COT / 五星会员 | 喂「成就」维度 |
| 擅长领域 / 可提供服务 | 建议按 2～4 个汉字记录标准短词，例如养老规划 / 保障规划 / 资产传承 | 喂「专业」维度；可生成“服务能力型”简介，多个服务用 `｜` 分隔 |
| 账号表达风格 `contentTone` | 专业理性 / 亲和温暖 / 风趣幽默 / 干练直接 / 生活化真诚 / 观点鲜明 / 沉稳可信 / 轻松有梗；建议选 1～2 个 | 直接参与脚本改写，决定口吻、节奏、幽默度与表达方式；详见 `expression-style-rules.md` |
| 营销服务部 | 成都一部 | 视频号 / 抖音简介合规末尾 |
| 执业证编号 | 真实执业证编号 | 视频号 / 抖音简介合规末尾；若暂未采集，生成预览使用 `000` 占位并提醒发布前替换 |

## 昵称与服务型简介的数据边界

### 日常称呼

- `preferredName` 必须来自本人填写、报名资料或已经确认的档案。
- 有 `preferredName` 时，昵称优先使用该称呼，而不是机械使用完整姓名。
- 没有 `preferredName` 时，不得由 AI 猜测“小X、X姐、X哥、老X”等亲昵称呼；可以使用不依赖姓名的定位型昵称。
- 姓名仍用于身份识别、资料匹配和内部档案，不等于公开账号昵称。

### 可提供服务

- 服务能力只能来自本人已提交、已确认的“擅长领域 / 可提供服务”等真实字段。
- 服务短词建议控制在 4 个汉字以内，方便简介横向组合；数据采集阶段优先使用标准短词。
- 如果原始资料无法可靠压缩到 4 个字以内，宁可不放入该版简介，也不允许 AI 擅自改写成一个未经本人确认的新服务能力。
- 服务型简介可使用 `养老规划｜保障规划｜资产传承` 这类结构；不得为了显得丰富补充本人资料中没有的服务。

## 账号表达风格的数据边界

- `contentTone` 的用户可见名称统一为“账号表达风格”，不再称“希望呈现的气质”。
- 该字段描述“内容应该怎么说”，不是对用户真实人格下结论。
- 可以多选，建议 1～2 个；允许本人自由补充未列出的风格描述。
- 脚本改写时由程序派生内部 `scriptStyleGuide`，把所选风格转为可执行写作指令。
- `scriptStyleGuide` 不展示、不主动询问，不作为新的用户字段。
- 风格只能改变表达方式，不能改变原稿事实、数字、产品责任、核心观点和合规边界。

## 身份字段与合规字段边界

- `agentId`（营销员编号）：9 位，用于匹配资料库、恢复历史资料、内部身份识别。
- `licenseId`（执业证编号）：用于视频号 / 抖音简介合规声明。
- 两个字段语义不同，**禁止用 `agentId` 自动填充 `licenseId`**。

## 判断轮维度映射

| 六维度 | 数据来源 |
|--------|----------|
| 身份/职位 | 荣誉职级、培训确认角色、问卷 |
| 性格特质 | 已有自我介绍自述、客户反馈（不再主动要求填写自我介绍） |
| 地域 | **城市**（后台 Excel） |
| 专业 | 保险从业时间 + 擅长领域/可提供服务 + 资质 |
| 学历 | 学历 + 最高学校背景 + 留学背景 |
| 成就/荣誉 | 荣誉（MDRT等）+ 自媒体成效 + 粉丝量 |

> **学历维度铁律**：仅当名校(985/211/QS)/硕士及以上/有留学背景/博士 任一满足才值得突出；
> 普通本科、大专、未知 → 不突出，绝不暴露短板。
> C 类字段缺失 → 标记「信息不足·暂不突出」，绝不臆造。
