# 内容规划首次进入互动规则 V3

## 目标
内容规划第一次进入时，不直接丢问题。先用产品化欢迎卡解释价值，再带入已有 IP 信息，只补决定内容方向的关键问题。

内容规划最终形成两条长期主线：**专业内容主线 + 一个泛内容支线**。泛内容必须是保险专业内容以外的独立话题方向，详细边界以 `rules/content-planning-rules.md` 为准。

## 首次进入结构
1. 功能欢迎卡
2. 已有 IP / 营销员信息确认
3. 第一个未完成的内容规划问题

## 功能欢迎卡
采用与“脚本改写”欢迎卡一致的卡片样式，不使用纯文字说明。

核心包装：
- 把“今天发什么”变成一套能长期积累的内容主线；
- 先把专业内容主线定清；
- 再从真实经历、兴趣、职业背景和生活积累中比较多个泛内容候选；
- 最终只确认一个长期泛内容方向；
- 最后落到内容方向、合集思路和可持续选题框架。

面向营销员的界面和结果不得出现“保险 + N”“保险 + 1”“1 + 1”等内部理解词。

首次提示：接下来只需要回答 3 个关键问题。

## 已有信息带入
如果已有 IP 方案或报名资料，优先展示 2～4 个代表性信息，例如：
- IP 定位
- 服务人群
- 个人优势
- 做自媒体目的

明确说明这些信息会自动带入，不需要重复回答。

## 问题顺序
固定按以下顺序检查：
1. `primaryGoal`：账号主目标，只允许 **拓客为主 / 增员为主** 二选一；
2. `insuranceFocus`：专业内容主线；
3. `secondaryMaterials`：本人真实经历、兴趣和积累，用来判断保险以外的泛内容候选方向。

每次只问第一个未完成问题。

## 泛内容候选提示原则

候选示例可以包括育儿、升学规划、户外、骑行、运动、法律、财商、职场成长等，但必须结合本人真实积累动态生成。

以下内容属于专业主线，不得混入泛内容候选：保险、保障、保单、理赔、投保、保费、保险产品、教育金保险、养老保险等。

系统可以展示多个候选方向，但最终只能推荐一个。结果页的“推荐”候选名称必须与顶部最终泛内容方向名称一致。

## 首次无可带入信息
不要出现“没有资料”“没找到资料”等失败式表达。
欢迎卡后直接说明：会问 3 个关键问题，再根据回答把专业主线、泛内容方向和选题框架收束出来。

## 历史用户
- 已有内容规划方案：不重复播放欢迎卡，直接恢复最新方案，可继续提出调整要求；
- 有未完成的内容规划对话：恢复历史，并从未完成问题继续，不重复从第一题开始。

## 体验原则
- 少问：已有信息不重复问；
- 先讲价值再提问；
- 每屏只推进一个关键决策；
- 主目标必须明确，不用“两者兼顾”回避选择；
- 泛内容必须真正脱离保险专业内容独立成立；
- 不使用“系统没找到”“资料不足”等让用户产生失败感的表达。
