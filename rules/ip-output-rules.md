# IP 方案输出规则 V2

## 1. 昵称

目标：昵称要像真实账号称呼，而不是身份证姓名 + 职业标签的机械组合。

### 日常称呼优先

- 如果档案中已有 `preferredName`（别人平时怎么称呼本人），昵称优先使用该称呼。
- 示例：真实姓名“张晓芳”，日常称呼“芳姐”，可以生成“芳姐聊养老”“芳姐的家庭规划笔记”等方向。
- 不建议直接使用完整姓名，例如“张晓芳养老规划”“张晓芳家庭保障”，除非本人明确要求保留全名。
- 如果没有日常称呼，不得擅自猜测“X姐 / X哥 / 小X / 老X”等亲昵称呼；优先生成不依赖姓名也能成立的定位型昵称。
- 不把英文、拼音作为默认方案；不为了网感生造难记的词。

### 真实性

- 日常称呼必须来自报名资料、本人补充或已确认档案。
- 不根据年龄、性别、职位自行推导称呼。
- 昵称只能使用已确认的地域、荣誉、学历、专业能力等信息。

## 2. 简介

每个平台可以给出不同侧重点的简介版本。除专业背书、温暖陪伴等版本外，当资料中存在明确的“可提供服务 / 擅长领域”时，应增加一个“服务能力型”版本。

### 服务能力型简介

形式参考：

`养老规划｜保障规划｜资产传承`

若有确认的日常称呼，也可以自然组合：

`芳姐｜养老规划｜保障规划`

规则：

- 每个服务短词建议 2～4 个汉字；
- 多个服务之间统一使用中文竖线 `｜`；
- 最多展示 3～5 个服务，避免堆砌；
- 服务必须来自本人已提交、已确认的资料，例如“擅长领域 / 可提供服务”；
- 不从“服务人群”“性格优势”“内容方向”反推服务能力；
- 不允许 AI 为了让简介丰富，自行补充养老、传承、税务、法律等本人没有确认的能力；
- 如果原始服务描述过长且无法无歧义压缩成 4 个字以内，宁可跳过，不自行改写成新服务。

### 合规尾部

合规声明仍遵循 `rules/compliance-rules.md`：

- 小红书：个人意见声明放在简介最后一句；
- 视频号 / 抖音：最后连续保持“个人意见声明 → 营销服务部 → 执业证编号”的固定顺序；
- 服务能力内容只能出现在合规尾部之前，不能把固定合规尾部拆散。

## 3. 首次复制提醒

昵称和简介都属于“改完以后可能受平台修改次数限制”的内容，因此提醒应放在用户真正准备使用它的时刻，而不是长期占据方案页面。

规则：

- 用户本次进入方案后，**第一次复制昵称**时弹出修改次数提醒；
- 用户本次进入方案后，**第一次复制简介**时也弹出修改次数提醒；
- 昵称和简介分别记一次，互不替代；
- 同一页面会话中，已经看过对应提醒后，后续复制不再重复弹窗；
- 弹窗必须允许“先不复制”和“知道了，继续复制”；
- 点击“继续复制”后才真正写入剪贴板；
- 提醒语言要简短，不把用户从创作流程里打断太久。

当前固定提醒口径：

- 微信视频号昵称：每年最多可修改 5 次；
- 小红书个人简介：7 天内最多修改 3 次；
- 微信视频号简介：暂无明确修改次数限制；
- 平台规则可能调整，最终以平台实时提示为准。

## 4. 合规信息展示

方案页的合规信息必须保留，但不应长期占用大块首屏或正文空间。

- “合规提示”和“平台修改机会提醒”合并为一个折叠板块；
- 默认收起，只显示一行“合规与修改提醒”；
- 用户需要时点击展开查看完整规则；
- 复制昵称或简介时，再通过首次复制弹窗主动提醒与当前动作最相关的修改次数；
- 合规折叠只改变呈现方式，不删除任何合规内容。

## 5. 输出一致性

- 页面展示前应做确定性校验：完整姓名不得因为模型惯性重新进入昵称；未确认服务不得进入服务型简介。
- AI 输出只负责候选生成，真实资料边界由程序和规则共同兜底。
- 首次复制提醒与合规折叠属于公共 IP 方案交互规则，不能在单个简介卡片上重复实现。
