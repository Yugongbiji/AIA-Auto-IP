# IP 方案输出规则 V3（当前版）

> 当前最高产品事实源：`docs/product/CURRENT_EFFECTIVE_REQUIREMENTS_LEDGER_20260825.md`。
> 昵称、简介、合规尾部等最终业务输出必须服从唯一 Owner，不允许旧模板或 AI 原始结果直接覆盖。

## 1. 推荐昵称

### 人物称呼是硬前提

- 每个最终昵称必须包含一个真实人物称呼主体，且只能出现一次；
- 称呼优先读取客户反馈高频真实称呼，再读取本人明确希望称呼、已有稳定昵称人物锚点、姓名自然称呼/本名；
- 没有真实人物称呼时不得编造人名，也不得退化成只有城市、荣誉、学历或抽象标签的昵称；应提示称呼信息不足。

### 真实性与受控人物资产

可参与昵称的真实资产包括身份/职业、经证实性格、地域、专业经历、学历层级、成就和中性内容方向，但：

- QS 前100 / 985 / 211 / 海外留学只按真实层级表达，不得推断学校或国家；
- 不根据年龄、性别、职位机械推导“哥 / 姐”；
- 不默认英文/拼音；
- 不创造客户未使用过的绰号；
- 禁止 `成都+称呼`、`TOT+称呼`、`985+称呼`、`有温度+称呼` 等机械标签拼接；资产只有形成自然、像真实账号昵称的表达时才可使用。

### 原昵称

- 原视频号/小红书昵称先谨慎审查；自然、合规、好记且有稳定识别时优先建议保留；
- “无 / 暂无 / 没有 / 未设置”等是缺失值，不得评价为好昵称；
- 两个平台昵称不一致时可建议逐步统一，但不武断要求立即改；
- 多个问题按 1/2/3 给出可解释理由。

### 推荐数量与 AI 边界

- 推荐通常 3–5 个不同路线；至少保留一个最真实、最自然的人物称呼/本名方向；
- 受控策略优先；只有受控候选不足时 AI 才能补充；
- AI 补充仍必须经过人物称呼、事实、合规、非机械拼接校验。

旧“没有称呼时优先生成不依赖姓名的定位型昵称”已经 `SUPERSEDED`，因为当前昵称必须有明确人物主体。

## 2. 推荐简介

### 三套策略

每个平台固定提供三套：

1. 方案 A · 专业背书；
2. 方案 B · 人设记忆；
3. 方案 C · 价值服务。

不是两个版本，也不能只是换几个词。

### 人物资产与信息密度

简介从真实人物资产池选择 3–5 个最有价值信息点：

- 个人介绍明确事实；
- 过往职业/长期经历；
- 家庭/生活身份；
- 真实学历层级；
- 从业年限；
- 真实荣誉；
- 多人客户反馈；
- 本人明确填写的真实服务；
- 标准化后的主要内容价值；
- 有定位价值时可使用地域、1–2 个真实兴趣。

优先稀缺事实，删除同义身份、同义性格、过多荣誉、过多兴趣、重复事实。不能出现“靠谱”单独一行、纯兴趣凑一行、无语义关系的标签墙。

### 服务能力型

- 服务只允许从 `services / serviceAreas / serviceCapabilities / expertise / specialties` 等本人真实资料提取；
- 没有证据不自动补养老/保障/财富/教育等服务；
- 最多 3–4 项，尽量简短；
- 可用 `｜` 分隔，但只作为一个版本中的服务行；
- 小红书不得强行使用敏感保险/金融/医疗/教育服务词。

## 3. 简介合规尾部唯一 Owner

固定尾部只能由 `ip-policy-core.js::complianceFooter()` 输出一次：

### 小红书

正文 → `本账号所述内容为个人意见，不代表任何官方意见。`

不得追加营销服务部或执业证编号。

### 视频号 / 抖音

正文后连续固定：

1. `本账号上所陈述或表达的内容仅为我个人意见，并不代表友邦人寿的意见`
2. `营销服务部：XXX`
3. `执业证编号：XXX`

- 营销员编号只用于资料匹配，绝不能冒充执业证编号；
- 没有真实执业证编号时预览使用 `000` 并提醒发布前替换；
- AI、旧 Vxx、简介模板不得再次生成/追加以上固定尾部。

## 4. 首次复制提醒

昵称和简介的首次复制提醒继续有效，但以最新 UI 为准：

- 本次页面会话第一次复制昵称时展示固定修改次数提醒，再进入昵称合规提示；
- 第一次复制简介时独立展示一次；
- 同一类型看过后，本会话后续复制不重复弹；
- 真正 Clipboard 写入只由公共 `aiaClipboard` 执行，成功/失败有明确反馈；
- 当前合规流程只保留确认后继续复制，不恢复旧“返回检查 / 大块折叠合规窗口”。

固定平台提醒：

- 微信视频号昵称：每年最多修改 5 次；
- 小红书个人简介：7 天内最多修改 3 次；
- 微信视频号简介：暂无明确修改次数限制。

## 5. 合规信息展示

旧“方案页长期保留一个合规与修改提醒折叠大板块”已经 `SUPERSEDED`。

当前方式：

- 昵称、简介各自在板块标题同行提供 `?` 合规入口；
- 第一次复制时主动展示与当前动作相关的提醒；
- `?` 只能改变标题行，不能把整张卡片改成横排；
- 合规提示遵循成熟两栏样式“可以说 / 不可以说”。

## 6. 输出一致性硬门槛

- 最终昵称由 `nickname-policy-v1.js` 唯一写入；
- 最终简介正文与合规尾部由 `ip-policy-core.js` 唯一写入；
- AI 原始 nickname/bio 只是草稿素材，不是最终事实源；
- 服务真实性、人物称呼、QS/学历、执业编号等必须通过确定性校验；
- 已经正确的版式、字段完整性、Emoji 视觉锚点不能因为修改其他业务逻辑而意外消失。
