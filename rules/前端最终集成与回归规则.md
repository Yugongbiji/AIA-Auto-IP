# 前端最终集成与回归规则

## 目的

解决同一函数被多个 `product-rules-v*.js` / 组件脚本重复包装或重定义，导致“前面已经实现、后加载脚本又覆盖”的问题。

## 强制规则

1. **最终页面行为只有一个收口层**：`web/product-integration-v30.js` 必须作为 `index.html` 最后加载的业务脚本。涉及资料最终展示、悬浮入口、昵称板块位置等跨模块行为，统一在最终集成层收口。
2. **禁止后续脚本再次覆盖核心全局函数**：不得在最终集成层之后重新赋值 `startWorkspace`、`renderProfile`、`renderProposal`、`selectTool` 等核心函数。
3. **新增功能优先改唯一真源，不叠补丁**：如果旧组件本身仍在输出错误 DOM，优先修改旧组件或在最终集成层替换其输出；禁止只在更早加载的规则文件里“修一次”。
4. **回归测试必须验证最终 DOM / 真实交互**：不能只验证辅助函数存在或返回值正确。悬浮按钮要检查真实按钮文字；复制要真实点击复制按钮；客户反馈要检查旧单字段消失且新板块存在；昵称位置要检查实际 DOM 顺序。
5. **规则冲突先查加载顺序**：同一需求第二次出现未生效时，第一步检查是否有后加载脚本重定义/覆盖，而不是继续新增版本文件。
6. **语义资料预处理只填缺失字段**：自我介绍语义分析只能使用原文明确事实；已有资料永不覆盖；AI 必须能回指原文证据，否则保持为空并继续询问。
7. **自然验收节点统一 Preview**：同一批修复完成前不因单个小修改反复发布；批次收口后统一跑最终 DOM 回归和 Preview。

## 回归底线

- `product-integration-v30.js` 是最后一个业务脚本。
- “我的 / 资料”“IP / 方案”必须检查真实组件，而不是测试模拟节点。
- 自我介绍明确包含的信息进入标准资料后，相应缺失问题不再重复询问。
- 客户反馈不能回退为单一“身边人评价”字段。
- 旧昵称评估默认保守：只有充分、可解释的问题才建议修改；所有建议列理由；AI 推荐必须声明仅供参考。
