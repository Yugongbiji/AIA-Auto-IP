# 前端最终集成与回归规则（当前版）

## 目的

防止同一函数、字段或 DOM 被多个 `product-rules-v*.js` / 集成脚本重复包装或重定义，造成“前面已经实现，后加载脚本又覆盖”的回归。

## 当前强制规则

1. **不再存在“最后加载的万能集成层”。** `product-integration-v30.js / v31 / v33` 已退役，当前页面不得加载，也不得由其他脚本动态注入。
2. **每个最终业务输出只有一个 Owner。** 当前 Owner 以 `rules/product-rule-ownership.md` 为准；`primaryGoal / headline / clientPortrait / advantages / contentMainline / secondaryContent / bios` 等核心 IP 输出由 `web/ip-policy-core.js` 收口；昵称由 `nickname-policy-v1.js` 收口。
3. **禁止依靠脚本加载顺序保证业务正确。** 如果必须“最后再覆盖一次”才能满足需求，视为治理失败；先查第二写入点并收回旧 Owner 权限。
4. **新增功能优先修改唯一真源。** 兼容层可以做 UI/旧数据迁移，但不得重新获得最终业务字段写权限。
5. **回归测试必须验证最终 DOM / 真实交互。** 不能只检查辅助函数存在。至少要覆盖：悬浮按钮真实可见性与纯图标、客户反馈结构化展示、个人介绍存在、昵称/简介布局、复制反馈、推荐脚本非空/去重、分页、前后篇、多选发送、手机键盘与自动滚动。
6. **语义资料预处理只填缺失且与当前目标语义一致的字段。** 自我介绍语义分析只能使用原文明确事实；已有资料不覆盖；客户画像不能在增员场景误当准增员画像。
7. **canonical 结果必须在下游使用前完成。** 不允许只在 `renderProposal()` 后改 DOM；脚本推荐、历史方案、数据库持久化都必须读取同一标准化结果。
8. **自然验收节点统一 Preview。** 同一阶段连续修复，不因单个小修改反复发布；阶段收口后统一跑 contract / regression / browser smoke，再部署一次 Preview。
9. **最新产品事实源优先。** 先读 `docs/product/CURRENT_EFFECTIVE_REQUIREMENTS_LEDGER_*.md`，再读对应专项规则；测试不得继续验证已 `SUPERSEDED` 的 UI 或业务需求。

## 已废弃的旧规则

以下旧要求全部 `SUPERSEDED`：

- “`product-integration-v30.js` 必须作为最后一个业务脚本”；
- “最终行为统一交给 V30 收口”；
- “悬浮按钮必须显示‘我的/资料’‘IP/方案’两行文字”；
- 任何依赖 V30/V31/V33 后加载覆盖当前 Owner 的测试或实现。

## 当前回归底线

- 退役 V30/V31/V33 不在 `index.html`，也不被运行时脚本动态加载；
- 悬浮入口为纯图标、无版本号、只在 IP 对话页显示；
- 个人介绍与客户反馈结构不回退；
- 昵称必须有且只有一个真实人物称呼，机械地域/学历/荣誉拼接不复活；
- 简介三策略、信息密度与唯一合规尾部不回退；
- 健康养生/育儿等不进入保险主线；
- IP 方案与推荐脚本读取同一 canonical 主线/支线；
- 无 IP 时脚本库仍可完整分页浏览；
- 多选 Composer 不维护第二套业务状态、不通过隐藏按钮模拟提交；
- 已正确实现但本轮没有修改的版式、字段完整性、成熟交互必须保持不变。

**任何基础回归都应由工程侧在 Preview 前发现，不再依赖产品负责人逐页捡漏。**
