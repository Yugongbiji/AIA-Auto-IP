# 对话语气与表情规则 V2

## 目标

四个功能的对话都应该像一个自然、轻松但专业的助手，而不是连续的后台表单提示。适量 emoji 可以增加节奏和亲和力，但不能每句话都加，也不能影响信息读取。

## 使用范围

适用于：

- IP 人设问答；
- 内容规划问答；
- 脚本改写过程中的提示、确认、反馈；
- 小红书排版过程中的提示、确认、反馈；
- Loading / 处理中 / 已完成 / 重试等用户可见状态文案。

不用于：

- 用户自己的消息；
- 可复制的正式文案正文；
- 固定合规声明；
- 数据、编号、错误详情等必须精确呈现的内容。

## 用户可见文案：说人话，不暴露内部实现语言

产品负责人为了说明业务逻辑时，可能会使用“手机阅读节奏、结构化解析、上下文、风险检测、字段匹配、生成链路”等工程或方法论表达。这些词可以用于规则、代码和内部文档，**不能默认原样出现在给营销员看的对话提示里**。

这条规则适用于所有功能，不只是小红书排版。以后新增 AI 功能时，处理中提示也必须先过这一层检查，不能把开发者为了理解逻辑写下来的技术描述直接复制给用户。

处理中提示应该满足：

1. 简单直白，一眼知道“系统正在做事”；
2. 可以轻松、可爱一点，但不要幼稚、油腻或夸张营销；
3. 不需要解释内部如何实现；
4. 尽量控制在 1～2 句；
5. 允许适量 emoji，通常 1 个即可；
6. 具体功能可以有自己的语气，但整体仍像同一个产品。

推荐风格示例：

- 小红书排版：`见证奇迹的时刻到啦！✨ 我正在努力排版，稍等一下哦～`
- 脚本改写：`收到啦！✍️ 我正在认真改写，马上给你三版～`
- IP 方案：`✨ 正在把你的资料变成专属 IP 方案，很快就好～`
- 资料完成：`资料齐啦 ✅ 接下来看看你的专属 IP 方案～`
- 正在理解用户补充：`我在认真看你刚刚说的内容 👀`

不推荐：

- `正在整理手机阅读节奏，并做初步风险检测。`
- `正在执行结构化解析。`
- `正在调用模型生成。`
- `正在对字段做二次匹配。`

这些属于内部实现说明，不应直接暴露给普通用户。

## 密度

- 不要求每条助手消息都有 emoji；
- 建议约每 2～4 条普通助手消息出现一次视觉点缀；
- 对“生成完成、匹配成功、下一步、提醒、内容方向”等关键节点可以优先使用；
- 同一条普通消息原则上最多 1 个 emoji，避免像营销话术或表情墙。

## 语义匹配

优先使用和语义对应的常见表情，例如：

- 资料 / 填写 / 补充：📋
- 匹配成功 / 已完成：✅
- 下一步 / 继续：🧭
- 方案 / 生成结果：✨
- 内容 / 方向 / 选题：💡
- 提醒 / 合规 / 风险：📌
- 普通轻松互动：🙂 / 👀

不使用夸张、暧昧、庆功感过强或容易造成不专业感的表情组合。

## 实现原则

- 表情属于表现层增强，不应改变业务状态或触发逻辑；
- 不为了加 emoji 修改用户原文或 AI 正式结果；
- 如果原消息已经有合适 emoji，不重复添加；
- Loading/处理中提示优先由统一产品文案规则管理，不在多个页面各写一套技术术语；
- 自动化测试重点验证“不影响交互与内容”，不要求每一条具体文案必须出现某个表情。
