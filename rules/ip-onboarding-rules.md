# IP 人设首次进入互动规则 V2

## 目标

第一次进入 IP 人设时，不直接用普通聊天文字开场。先用一张产品化欢迎卡说明功能价值，让营销员理解“为什么值得回答接下来的问题”，再根据已有资料决定从哪里开始询问。

## 三段式体验

首次进入固定采用：**功能介绍 → 已有资料确认 → 第一个缺失问题**。

### 1. 功能介绍

欢迎卡样式参考“脚本改写”的功能欢迎卡，不使用普通聊天气泡堆一段说明文字。

欢迎卡文案结构：

- 标题：把“你是谁”，变成别人记得住的账号
- 一句话价值：从真实经历、客户方向和个人优势中，找到适合长期经营的 IP 主线
- 三个功能亮点：
  - 人设定位：找到最值得被记住的那一面
  - 直接可用：生成昵称、账号简介和表达方向
  - 合规护航：自动避开常见平台和行业风险
- 行动引导：接下来回答几个简单问题，一起把第一版 IP 搭出来

不强调 AI、模型或技术能力，重点包装用户可直接感知的价值。

### 2. 已匹配到营销员资料

系统先扫描已有档案，只展示 3～4 个有代表性的已知字段，例如城市、服务人群、从业时间、荣誉、学历、优势。

提示语原则：

> 你的部分资料我已经带进来了。已有的信息不用重复填，我们只补还缺的部分。

随后按照问题顺序找到**第一个没有有效值的字段**开始询问。已经存在的数据绝不重复提问。

### 3. 没有匹配到资料 / 直接进入

欢迎卡之后，不出现“没有找到你的历史资料”“没关系”等失败感表达。

使用自然的行动引导：

> 接下来我会问你几个很简单的问题。按真实情况回答就好，我会边聊边把你的 IP 轮廓拼出来。

然后从问题列表第一个问题开始。

## 固定问题顺序

1. 所在城市 `city`
2. 服务人群 `customerGroups`
3. 客户年龄段 `customerAges`
4. 保险从业时间 `insuranceYears`
5. 你的优势 `strengths`
6. 荣誉 `honors`
7. 学历 `education`
8. 学校背景 `schoolTier`
9. 留学背景 `overseas`
10. 希望呈现的气质 `contentTone`
11. 营销服务部 `department`

前端不是机械记录“第几题”，而是每次从上述顺序里寻找第一个缺失项。

## 跳过规则

用户明确选择“跳过”或“不希望填写”时，视为该字段已经处理，不得在后续进入时反复追问。

## 资料完整

如果匹配到的档案已经覆盖全部需要字段，不为了制造互动而继续提问。欢迎卡和资料确认后，直接进入方案生成。

## 历史用户再次进入

如果已有 IP 对话历史，则不重复播放完整的新手欢迎卡，直接恢复历史对话并继续未完成流程。

如果已经有 IP 方案但没有可恢复对话，则简短提示“已载入你的 IP 档案和已有方案”，不要重新播放新手介绍。

## 核心原则

**尽量少问，而不是尽量多问。** 数据库已有的信息不重复问；用户明确跳过的信息不重复问；资料足够完整时直接生成方案。
