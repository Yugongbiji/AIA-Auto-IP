# IP 人设首次进入互动规则 V7（当前版）

> 当前最高产品事实源：`docs/product/CURRENT_EFFECTIVE_REQUIREMENTS_LEDGER_20260825.md`。
> 本文件只负责 IP onboarding 的详细交互；昵称、简介、内容方向、悬浮入口等最终输出分别服从对应 Owner / 专项规则。

## 1. 核心目标

首次进入 IP 人设时采用产品化欢迎卡，但欢迎说明不能挡住真正业务流程。同一次初始化必须完成：

**功能介绍 → 合并已有资料 → 标准化业务目标 → 找到第一个真正缺失字段 → 立即提问。**

核心原则：**已有资料不重复问；个人介绍先做语义提取；客户反馈只作为对应证据来源；目标先标准化；只补缺失项。**

## 2. 欢迎体验

欢迎卡继续强调用户可感知价值，不强调模型技术：

- 人设定位：找到最值得被记住的真实差异点；
- 直接可用：生成昵称、账号简介、内容方向；
- 合规护航：自动避开常见平台/行业风险。

欢迎卡之后必须立即进入资料确认或第一个缺失问题，不能停在“接下来会问几个问题”。

## 3. 已匹配资料

系统先扫描并标准化完整 profile：报名表、后台导入、历史保存、个人介绍语义提取、客户反馈摘要都属于可用输入，但证据等级不同。

提示原则：

> 你的部分资料我已经带进来了。已有的信息不用重复填，我们只补还缺的部分。

随后按当前问题顺序寻找第一个缺失字段。已有有效值绝不重复提问。

### 个人介绍复用

- `selfIntro` 不作为首次 onboarding 的重复必问题；
- 如果报名资料里已有个人介绍，先语义提取过往职业、长期身份、真实爱好等明确事实，再判断哪些题已经有答案；
- 个人介绍**必须在“我的资料”最后一栏展示**，不得再隐藏；
- 语义提取只填缺失字段，不覆盖已有真实资料，不把推断当事实。

### 客户反馈边界

客户反馈可提供：真实高频称呼、多人重复性格评价、愿意聊的话题、社会角色等；不得自动写成本人职业、学历、兴趣、资质或真实服务能力。

## 4. 没有匹配到资料 / 直接进入

不使用“没有找到历史资料”“失败”等负面表达。欢迎卡后直接行动：

> 接下来我会问你几个很简单的问题。按真实情况回答就好，我会边聊边把你的 IP 轮廓拼出来。

随后立即进入第一题。

营销员编号：

- 9 位数字；
- 只用于尝试匹配已有资料库/历史报名；
- 匹配成功后立即合并已有资料并跳过已知字段；
- **营销员编号绝不能当执业证编号。**

## 5. `primaryGoal` 目标门禁

历史 `purpose` 不再直接作为最终目标。

当前规则：

- 明确只有拓客 → 标准化 `customer_acquisition`；
- 明确只有增员 → 标准化 `recruitment`；
- “拓客和增员都要 / 两者兼顾 / 同时 / 打造个人品牌 / 打造专业形象”等非唯一值 → 必须重新询问；
- 用户最终只能在“吸引潜在客户 / 吸引潜在增员对象”中确定一个当前主目标；
- 提示刚起号阶段先聚焦一个方向，成熟后再扩展。

后续目标人群、方案、内容方向、脚本推荐全部读取这一个标准化 `primaryGoal`。

## 6. 目标人群题目随目标切换

### 拓客

- 服务人群 `customerGroups`；
- 客户年龄段 `customerAges`。

### 增员

- 准增员对象 `recruitmentGroups`；
- 准增员年龄段 `recruitmentAges`；
- 不使用“有转型意愿的人群”等非具体特征；
- 年龄选项不含 55 岁以上。

语义预填也必须读取 `primaryGoal`，不能把自我介绍里的“我主要服务企业主”误当成“我希望招募企业主”。

## 7. 当前需要收集/复用的核心资料

当前问题链应覆盖并按缺失跳过：

- 姓名 / 营销员编号；
- `primaryGoal`；
- 城市；
- 当前目标对应的人群和年龄；
- 保险从业时间；
- 优势；
- 荣誉；
- 学历（大专 / 本科 / 硕士 / 博士）；
- 学校背景层级；
- 留学背景；
- 账号表达风格 `contentTone`（可选 1–2 项，并提示会影响后续脚本改写）；
- 过往职业/长期经历（多选）；
- 家庭/生活身份（多选）；
- 真实爱好（多选）；
- 真实可提供服务（如已有资料则复用）；
- 营销服务部。

具体顺序可由当前 `questions` 配置维护，但任何顺序调整都必须遵守“已有不问、前置关键目标先标准化、下游不自行猜”的原则。

## 8. 快捷选项与跳过规则

- 快捷项不得出现“其他 / 不希望填写 / 跳过 / 暂不填写”等逃逸选项；
- 用户仍可在统一 Composer 里自由输入补充；
- 多选题由同一个业务状态管理，底部“发送”是唯一提交动作；
- 点击快捷标签不主动拉起手机键盘；
- 已选标签显示在输入框内部。

旧“用户选择跳过即标记已处理”的规则已经 `SUPERSEDED`。

## 9. 我的资料与悬浮入口

资料展示：

- “我的资料”保留标准化字段；
- 客户反馈独立分问题展示；
- 个人介绍在最后一栏整行展示；
- 生成偏好等已退役内部字段不展示。

悬浮入口由 `profile-float.js` 唯一负责，当前规则：

- “我的资料 / IP 方案”均为纯图标按钮；
- 不显示“我的/资料”“IP/方案”文字，也不显示 V1/V2；
- 只在 IP 对话页显示；
- 展开资料后提供明确关闭/收起；
- 修改资料统一通过 IP 对话输入，不做逐字段表单编辑。

旧“顶部一行 `✨ 我的 IP 信息 · 42% · 点击展开`”样式已经 `SUPERSEDED`。

## 10. 资料完整 / 历史用户

- 所有当前必需资料已足够时，不为了制造互动继续提问；可进入方案生成。
- 有可恢复历史对话时，不重复完整欢迎卡；恢复当前进度。
- 已有方案没有对话时，载入档案和方案，不要求普通刷新重新填写。
- 历史独立内容规划数据不得决定当前默认导航或覆盖当前 IP 内容方向。

## 11. 验收硬项

- 模糊目的必问拓客/增员二选一；
- 增员人群题语义正确；
- 已有报名资料/个人介绍明确事实不重复问；
- 个人介绍仍在资料最后展示；
- 快捷项无逃逸选项；
- 学历含大专；
- `contentTone` 可选 1–2 项；
- 多选标签 + 自由文本能一次发送并进入下一题；
- 手机点击标签不主动弹键盘；
- 资料悬浮按钮纯图标且只在 IP 对话页出现。
