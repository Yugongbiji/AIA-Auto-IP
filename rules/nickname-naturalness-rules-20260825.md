# 昵称自然度与真实称呼补充规则（2026-08-25）

> 适用范围：AIA Auto IP 推荐昵称。与 `docs/昵称受控词库与模板-V1-20260824.md`、`rules/nickname-source-ranking-v1.md` 联合使用；冲突维度以本文件最新规则为准。

## 1. 真实称呼优先于姓名自动简称

昵称人物锚点按以下顺序使用：

1. 客户/身边人反馈中的高频真实称呼；
2. 本人明确希望使用的称呼；
3. 已长期使用且合规的原昵称中的稳定人物称呼；
4. 本人长期使用的英文名；
5. 本名或自然的两字以上姓名片段兜底。

客户反馈不仅用于“怎么称呼我”，还可以辅助判断人物性格、他人角色认知和适合的内容方向；但反馈中的形容词、角色、话题只能作为创意依据，不得机械拼成昵称。

## 2. #104 禁止随意截取姓名单字造昵称

没有真实称呼证据时，禁止把姓名中的单个字自动当昵称。

- `张三 → 三`：禁止；
- `王一 → 一`：禁止；
- `李明 → 明`：禁止。

只有本人明确使用、客户/身边人反馈真实出现、或已有账号长期使用时，单字称呼才可作为人物锚点。

二字姓名没有真实简称证据时，优先使用全名，不自动截取第二个字。三字及以上姓名可考虑自然的两字片段，但仍低于真实称呼和原昵称人物锚点。

## 3. #105 昵称必须使用完整人物事实源

昵称推荐的输入至少包括：

`原昵称 + 本人自我介绍/基础资料 + 客户/身边人真实称呼 + 高频评价 + 他人角色认知 + 愿意咨询的话题 + 人物身份/经历/兴趣 + 账号目标/目标人群 + 合规规则`。

优先使用真实称呼，不因某个评价高频就自动生成“靠谱的XX”“专业的XX”。

## 4. #106 增加中文口语自然度门禁

每个候选生成后必须按“一个真实用户会不会自然把它当作昵称”重新检查。

禁止：

- 动作句或标题句，例如 `yana打网球`；
- 同一人物主体重复，例如 `王一的一一世界`；
- 事实虽然正确但读起来像字段拼接的名称；
- 为了体现兴趣、职业、学历或荣誉而牺牲顺口程度。

人物称呼本身已经足够自然时，不要求额外增加标签。

## 5. #107 降低万能模板和重复结构

`XX的小世界`、`XX的日常`、`XX聊生活`、`XX看世界` 等属于常见万能模板，不作为系统批量生成的默认路线。

规则：

- 已经长期使用且自然的原昵称可以保留，例如原昵称本来就是 `何艳的小世界`；
- 新生成候选不得因为“安全”而反复使用同一个万能尾缀；
- 同一人的 3–5 个候选应体现真正不同的命名路线，而不是只换尾词；
- 若只有 2–3 个真正好的候选，宁缺毋滥，不为凑满 5 个制造低质量昵称。

## 6. #108 过往职业只进入简介，不进入推荐昵称

当前名单里的用户现在均为保险营销员。过往职业是重要的人物资产，但在昵称中继续写成“地产人XX”“财务人XX”“教师XX”“会计XX”“精算人XX”等，会让外部用户误以为这是其当前职业身份。

因此：

- **过往职业只能用于简介、IP 一句话定位、内容方向等人物理解，不得用于新生成推荐昵称。**
- 即使加“前”能够语义上说明过去经历，系统也默认不使用“前广告人XX”“前教师XX”等前职业昵称；前职业不作为昵称生成路线。
- 原昵称如果历史上已经含职业词，也不能仅因为“原来就在用”自动判定为优先保留，仍需按当前身份与合规重新判断。
- 当前真实、持续存在的非过往生活身份（如二孩爸爸、宝妈）可在自然且有证据时参与昵称，但不能与过往职业混淆。

示例：

- `地产人成涛`：禁止；
- `财务人宋雨阳`：禁止；
- `地产人陈春`：禁止；
- `精算人贾正佳`：禁止；
- `前广告人张蕊`：默认不推荐，前广告经历放简介或一句话 IP 定位。

## 7. #109 纯姓名/真实称呼型候选最多两个

每个人的推荐列表不能只是把多个真实称呼轮流摆出来。真实称呼用于确定人物锚点，不等于所有称呼都应该占一个推荐名额。

规则：

- 每人 3–5 个候选中，纯姓名、真实称呼及其极简变体合计最多 **2 个**；
- 原昵称保留/优化型可以单独作为一条路线；其余候选应尽量体现不同、真实且自然的命名思路；
- 不允许 `郭局 / 东哥 / 郭老师 / 郭旭东` 这种四个名额都只是换称呼；
- 不允许为了满足“不同路线”重新引入过往职业、万能尾缀、机械地域、机械荣誉或无证据标签；
- 如果除 1–2 个称呼型之外没有足够好的创意，宁可只推荐 2–3 个，不凑满 5 个。

## 8. #111 首选优先有记忆点、有网感，不默认首选本名/纯称呼

昵称不是实名通讯录。当前用户并非依靠公众知名度让本名天然形成记忆，因此“安全、简洁”不能成为把本名或纯称呼默认排第一的理由。

首选排序：

1. **已有且自然、合规、有特色、有用户记忆的原昵称**；
2. **真实人物称呼/本名 + 当前仍成立的鲜明兴趣、生活特点、内容特点或其他非职业记忆点**；
3. 有证据、自然、有网感的其他差异化人物昵称；
4. 真实称呼极简版；
5. 单独本名兜底。

规则：

- 当前持续存在且有证据的兴趣/特点可以进入昵称，例如健身、八块腹肌、手帐、攀岩、滑雪、网球、读书等；这些不是 #108 所禁止的“过往职业”。
- 示例：刘畅真实资料明确有“多年健身、八块腹肌”时，`八块腹肌刘畅`、`刘畅练起来` 的首选优先级高于单独 `刘畅`。
- 不因有特色就放宽事实门禁：兴趣/特点必须来自本人资料或可靠反馈，不得编造。
- 不因追求网感重新引入前职业。`飞行员刘畅`、`地产人成涛` 仍禁止；前职业只进入简介/IP 定位。
- 不机械把所有兴趣都写成 `爱XX的称呼`。候选仍必须通过中文口语自然度检查，并在 3–5 个候选中提供真正不同的命名路线。
- 单独本名/称呼可以保留为稳妥备选，但除非资料确实没有更好的真实记忆点，否则不默认作为首选。

## 9. 原昵称保留判断

原昵称应独立给出“建议保留 / 建议优化 / 不建议保留”及稳定、具体的理由。理由优先来自：

1. 是否合规；
2. 是否已有稳定人物称呼和用户记忆；
3. 是否自然、顺口、好记；
4. 是否像真实人物账号，而不是业务栏目或标签墙；
5. 是否存在明显可优化项，如品牌词、数字尾缀、重复主体或机械标签。

不得让 DeepSeek 每次自由编写不同风格的保留理由；预设名单进入数据库后，应优先读取人工确认的固定结论与固定理由。

## 10. 最终候选质量顺序

`已有且有特色的好昵称 > 真实称呼/本名 + 有记忆点的当前兴趣或特点 > 其他有证据的自然差异化昵称 > 真实称呼极简版 > 单独本名 > 受控模板 > AI 兜底`。

过往职业不属于昵称候选资产。资产只负责提供灵感，不强制进入名字。最终昵称的第一目标是：**像一个真实的人、顺口、好记、有稳定识别；首选还要尽量有记忆点和网感。**
