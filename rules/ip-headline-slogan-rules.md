# 一句话 IP 定位 / Slogan 规则（#103 / #119）

> 状态：2026-08-25 已确认。适用于 IP 方案顶部与推荐简介中的同一句 IP 定位。

## 1. 产品目的

一句话 IP 定位不是标签列表，也不是普通业务介绍。它是一句浓缩版自我介绍 / slogan：从真实基本资料、个人介绍和多人客户反馈中，挑选最有吸引力、最有辨识度、最容易记住的 2–3 个特点，用自然、响亮的一句话说明“这个人有什么不同、为什么值得关注”。

定位逻辑参考：**做账号的目的 × 我的不同之处 × 目标人群关注的内容 → 我的 IP**。

## 2. 事实与素材优先级

只允许使用已有 A/B/C 级真实证据，不得创造事实。候选素材可来自：家庭/生活身份、明确职业经历、具体年限、学历/专业资质、真实荣誉、客户反馈、兴趣/生活特点、已证实的内容能力、真实转型经历、账号目标与目标人群。

优先级：**稀缺且具体的事实 > 有数字的经历 > 有证据的强反差/转型 > 专业资质/荣誉 > 多人反馈形成的稳定特点 > 有记忆点的生活身份 > 普通兴趣 > 泛化形容词。**

有明确数字时保留数字精度；没有证据不得生成“0人脉”“多年”“擅长”“懂XX”“专家/导师/顾问”等判断。

## 3. 表达规则

- 只挑 2–3 个最有吸引力的特点，不要求把“我是谁 / 我的优势 / 我能提供什么价值”全部塞进一句话。
- 优先形成记忆点、反差、具体事实或真实人格感，不写成“从XX跨界，用自己的经验讲清……”这类机械模板。
- **#119：泛化评价词不能单独与普通身份机械拼成 slogan。** `宝妈，靠谱是我的标签`、`XX，真诚是我的标签`、`XX是我的专业底色`、`做一个让人记得住的人` 等模板直接判为不自然，不得作为 AI 候选，也不得作为 fallback。
- 如果只有“宝妈/爸爸/硕士”等普通身份 + “靠谱/真诚/细致”等泛化评价，不能为了凑 2–3 个点强行造句；优先继续寻找明确职业经历、量化事实、荣誉、当前兴趣/生活特点等更有信息量的真实素材。确实没有更强素材时，宁可退回更简单、自然的事实表达，也不要批量生成“XX是我的标签”。
- 不包含人物昵称/姓名锚点。
- 不做“职业 + 转型 + 行业 + 荣誉”的标签墙。
- **禁止使用 `｜` 或 `|` 竖线分隔符。** 必须使用自然中文标点，例如 `，`、`、`、`！`，也可以在自然情况下不用标点。
- 这句话是自然 slogan，不参与简介普通正文的 `｜` 标签组合规则。
- 长度要凝练、适合放在 IP 方案顶部；长度控制在 headline 生成阶段完成，简介不得二次截短、改写或重新断句。

示例仅说明结构，不代表可以脱离事实生成：
- `7年教培，0人脉转行，擅长自媒体的保险人`（只有三个事实都有明确证据时才允许）
- `懂你、懂财、懂保险的男闺蜜`（只有“懂你/懂财/懂保险/男闺蜜”均有真实证据时才允许）

## 4. 单一事实源 / 唯一 Owner

`web/ip-policy-core.js::headline(profile)` 是一句话 IP 定位的唯一运行态 Owner，最终 canonical 字段为 `proposal.headline`。

**IP 方案顶部 = 小红书简介固定声明前一句 = 视频号/抖音简介固定声明前三行之前的最后一句。三处必须逐字一致，读取同一个 `proposal.headline`，不得分别生成。**

简介结构：

`人物正文 → proposal.headline → 平台固定合规声明`

小红书与视频号/抖音都使用同一个 headline；若 headline 本身触发某平台合规限制，应在 headline 的 canonical 生成阶段解决，不能让简介自行生成第二句话造成漂移。

## 5. 防回归门禁

必须测试：
1. headline 不使用人物姓名/昵称作为锚点；
2. headline 不含 `｜` / `|`；
3. headline 优先具体、量化、差异化真实事实，禁止无证据升级；
4. `proposal.headline` 由唯一 Owner 写入；
5. 两个平台简介都在固定合规声明之前插入同一个 `proposal.headline`；
6. 简介不得对 headline 二次改写、截断或重新生成；
7. 固定合规声明的原文、顺序和换行继续保持不变；
8. AI 候选与 fallback 都不得输出 `XX是我的标签 / XX是我的专业底色 / 做一个让人记得住的人` 等 #119 机械句式。
