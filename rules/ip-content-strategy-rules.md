# AIA Auto IP · IP 方案内内容主线规则 V1

> 本文件是“内容规划合并进 IP 方案”后的权威产品规则。原独立内容规划流程进入兼容状态，不再作为用户入口。

## 1. 产品结构

用户可见主功能调整为：

1. IP 人设（包含精简内容主线）；
2. 脚本改写；
3. 小红书排版。

独立“内容规划”入口撤销。内容建议直接放在 IP 方案底部，形成完整链路：

**我是谁 → 我服务谁 → 账号怎么称呼/介绍 → 接下来发什么。**

旧内容规划 API、历史表和历史记录暂时保留，只做兼容，不做破坏性删除。

## 2. 不再重复询问拓客 / 增员

内容主线直接读取 IP 档案中的 `purpose`（做自媒体目的），不再新增第二轮主目标提问。

推荐标准值：

- `拓客`
- `增员`
- `拓客和增员都要`
- `打造个人品牌`

映射规则：

- 拓客 → 保险专业主线 + 泛内容支线；
- 增员 → 增员内容主线 + 泛内容支线；
- 拓客和增员都要 → 拓客内容主线 + 增员内容主线 + 泛内容支线；
- 打造个人品牌 → 默认以专业内容建立信任，同时给泛内容支线；不自动加入增员主线。

拓客 / 增员的内容边界继续遵循 `rules/content-goal-boundary-rules.md`。

## 3. 结果页只保留“你的内容主线”

不再展示旧内容规划中的：

- 顶部红色总结板块；
- 候选方向 / 候选筛选；
- 独立“内容方向”大板块；
- 不建议混入的方向；
- 独立内容规划问答和“生成内容规划”动作。

复杂筛选可以留在系统内部，但用户只看收束后的结论。

## 4. 每条主线固定三部分

每一条主线只回答三件事：

### 4.1 内容方向

列 1～4 个可以持续输出的具体方向，必须结合现有档案、目标人群、服务能力、真实经历、IP 标签和已确认资料。

拓客示例：

- 家庭保障方案
- 理赔案例
- 保险科普
- 养老规划
- 医疗保障
- 教育金规划

增员示例：

- 转型经历
- 行业发展
- 团队日常
- 个人成长
- 从业经验

泛内容示例：

- 育儿
- 升学规划
- 骑行
- 户外
- 运动
- 法律
- 职场成长

泛内容必须有本人真实证据。**没有真实兴趣、经历或积累时宁可显示“暂未确定”，不得根据保险标签或客户人群硬猜。**

## 5. 合集推荐硬规则

合集名称直接由上面的内容方向延伸，目的是让用户一眼理解这个系列长期讲什么。

硬规则：

- 每个合集名称 **不超过 5 个汉字**；
- 简短、口语、容易记；
- 尽量直接表达主题，不写长标题；
- 不为了“高级感”造生僻词；
- 同一方向可给 1 个合集名即可，不堆很多相似版本；
- 代码层必须做长度兜底，AI / 规则生成超长时也不能原样展示。

示例：

- 家庭保障方案 → `家庭保障`
- 理赔案例 → `理赔案例`
- 养老规划 → `养老规划`
- 转型经历 → `转型日记`
- 行业发展 → `行业观察`
- 育儿 → `育儿手记`
- 骑行 → `骑行日记`
- 升学规划 → `升学攻略`

## 6. 对账号的作用

不要写成长段解释，统一使用直观标签。

推荐口径：

### 拓客 / 保险专业内容

`建立信任` / `吸引准客` / `推动咨询`

### 增员内容

`展示职业` / `吸引同频` / `团队信任`

### 泛内容

`扩大受众` / `增加活人感` / `打开流量`

作用标签表达的是“站在账号主理人的角度，这类内容为什么值得长期做”，不是内容摘要。

## 7. 内容聚焦提醒

保留在整个“你的内容主线”板块最底部。

普通情况：专业主线保持稳定，泛内容只保留一个能长期讲的真实方向。持续做深，比频繁更换主题更容易形成清晰账号标签。

如果同时选择拓客和增员：两类都可以做，但同一阶段要有明显主次；不要在客户保险内容和招募内容之间高频来回跳。泛内容也只保留一个长期方向。

## 8. 泛内容边界

泛内容必须：

- 脱离保险 / 保障可以独立成立；
- 不是直接招聘、招募或团队宣传；
- 来自本人真实兴趣、经历、职业背景或长期积累；
- 有更宽的话题受众；
- 能持续提供知识、经验、观点或生活价值。

保险、保障、保单、理赔、投保、保费、保险产品、教育金保险、养老保险等不能作为泛内容。

## 9. 渐进式迁移

第一阶段只撤用户入口并把精简内容策略并入 IP 方案：

- 旧 `/api/content-plan/*` 接口暂留；
- 旧内容规划历史表暂留；
- 已有历史不做破坏性清理；
- 新用户不再走独立内容规划流程。

等新结构稳定后，再单独评估是否清理旧后端和历史结构。
