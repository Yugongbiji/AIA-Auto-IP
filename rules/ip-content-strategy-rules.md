# AIA Auto IP · IP 方案内容方向规则 V3

> 本文件已按 `docs/product/CURRENT_PRODUCT_RULES_BASELINE_20260824.md` 更新。发生冲突时，以后者及后续明确产品决策为准。

## 1. 产品结构

用户可见核心功能：IP 人设、脚本推荐、脚本改写、小红书排版。内容建议直接放在 IP 方案底部，形成“我是谁 → 我服务/吸引谁 → 账号怎么称呼/介绍 → 接下来发什么”的完整链路。

## 2. 主线 / 支线最高层边界（硬规则）

保险主线必须来自**受控保险业务主题**，并由标准化后的 `primaryGoal` 决定：

- 拓客：可使用保险科普、家庭保障、重疾保障、医疗保障、养老规划、财富规划、教育规划、保险知识等受控业务主题；
- 增员：统一使用增员与职业发展相关主线。

由个人身份、经历、兴趣、专业背景、生活方式、客户反馈等产生的泛内容，一律归入**内容支线**。健康养生、育儿、美食、读书、旅行、智能家居、运动等不得因为脚本库标签名称而升级为保险主线。

必须按**内容性质**而不是单个关键词判断。例如：

- 医疗险 / 重疾险 → 保险主线；疾病知识 / 健康管理 / 养生 → 内容支线；
- 养老保险 / 养老金保险规划 → 保险主线；泛养老生活 / 老年健康 → 内容支线；
- 教育金保险 → 保险主线；育儿 / 升学经验 → 内容支线；
- 保险从业转型 → 增员主线；一般职场成长 / 原职业经验 → 内容支线。

## 3. 目标收束

刚起号阶段只选择一个主目标：拓客或增员。报名资料若明确只有一个目标则直接带入；如果资料显示“两个都要 / 同时做 / 兼顾 / 打造专业形象 / 个人品牌”等非唯一答案，必须重新询问并二选一。

- 拓客 → 受控保险业务主线 + 一个内容支线；
- 增员 → 增员与职业发展主线 + 一个内容支线。

后续目标人群问题、IP 方案、内容方向与脚本推荐全部读取同一份标准化 `primaryGoal`。

## 4. 内容支线证据池

支线不能只读取“家庭与生活身份”。应综合：家庭/生活身份、过往工作与长期经历、报名自我介绍、用户在对话中的口头补充、个人优势与专业积累、服务资料、兴趣爱好、身边人/客户反馈等真实资料。

先统一形成候选证据池，再按 `rules/content-branch-ranking-v1.md` 的业务价值、客群匹配、持续输出能力、真实性等规则排序。支持模糊语义映射，例如宝妈/宝爸/带娃/亲子→育儿，教师/学校/教培→升学教育，骑自行车→骑行。

未知方向不能因为词库未收录就直接丢弃，应进入统一评分框架；多来源一致证据应提高可信度与优先级。内容支线必须有本人真实证据；没有真实兴趣、经历或积累时宁可暂未确定，不得根据保险标签硬猜。

## 5. 脚本推荐映射

主线归属和脚本库标签是两个层级，不能混为一谈：

- 前台保险主线可以向下匹配脚本库的保险、医疗险、重疾险、意外险、理赔、教育金、养老、保险财富等具体标签；
- 增员主线匹配增员相关标签；
- 内容支线按个人方向做受控模糊映射，例如育儿可匹配教育/育儿，健康养生可匹配健康/养生，但这些脚本仍显示在内容支线区域。

**脚本库一级标签“健康 / 教育 / 养老 / 财富”本身不能决定前台主线归属。**

## 6. 结果展示

内容方向板块展示：保险主线 + 内容支线。每条方向给出可以持续输出的具体主题、合集建议、对账号的作用和来源；合集名保持简短、口语、易记。

内容聚焦提醒放在板块底部：专业主线保持稳定，内容支线优先保留一个真实、能长期讲且业务价值更高的方向。持续做深比频繁换主题更容易形成清晰账号标签。

## 7. 回归验收硬项

- 健康养生不得进入保险主线；
- 育儿不得进入保险主线；
- 拓客主线只能来自受控保险业务主题；
- 增员主线只能来自增员与职业发展主题；
- 支线必须来自真实证据池并支持模糊匹配与未知方向评分；
- IP 方案和脚本推荐页面必须使用同一份标准化主线/支线归属结果；
- 任何旧 Vxx 或旧内容规划数据不得重新覆盖上述结果。
