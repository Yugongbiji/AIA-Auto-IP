# Change Spec — 正式版验收问题 152–157

状态：Spec
日期：2026-09-01
范围：IP 人设询问、IP 输出、客户反馈证据、简介、脚本推荐

## 背景

正式版业务验收发现 152–157 六项问题。它们不得作为六个孤立补丁处理，而应作为同一稳定性 change，优先保证最高有效规则真正成为运行时唯一事实源，并补齐自动回归测试。

## 152 城市选项

IP 询问中的城市选项必须至少包含以下友邦已收集分公司城市：

北京、常州、成都、东莞、佛山、广州、杭州、合肥、淮安、惠州、济南、江门、揭阳、廊坊、泸州、茂名、梅州、南京、南通、清远、汕头、上海、韶关、深圳、石家庄、苏州、泰州、唐山、天津、无锡、武汉、襄阳、徐州、盐城、扬州、宜昌、湛江、肇庆、镇江、郑州、中山、重庆、珠海。

Acceptance:
- 城市列表只维护一份 canonical config。
- UI 与数据保存均使用该 canonical config。
- 不因新增城市破坏已有 profile 数据。

## 153 一句话 IP 必须执行最高规则

必须严格执行 `docs/product/FINAL_OUTPUT_RULE_AUDIT_20260826.md` 及更高优先级总账。

Acceptance:
- 禁止类似“财务，生活里喜欢跑步”的字段拼接式输出。
- 候选必须基于真实证据，并执行强事实竞争：数字经历 > 转型/跨界 > 荣誉 > 学历/资质 > 稳定评价 > 生活身份 > 兴趣。
- 禁止无证据的擅长、专家、导师、顾问、长期、多年等。
- 最终 `proposal.headline` 只有 `web/ip-policy-core.js` 有写权限。

## 154 客户反馈证据不得污染

当当前 agent 的 `peer_reviews` 为 0 时，任何输出不得出现：
- “多人反馈提到”
- “客户都说”
- “大家评价”
- 或其他暗示多人/客户真实评价存在的措辞。

Acceptance:
- 评价证据必须严格按当前 agent_id 查询。
- 禁止读取其他用户评价、默认样本、缓存残留或全局聚合结果。
- 0 条评价必须稳定地产生“无评价证据”的分支。
- 有评价时，只允许基于真实记录提炼，不夸大人数或频率。

## 155 推荐简介正文

最高规则：围绕三个维度组织人物正文：
1. 我是谁
2. 我的优势
3. 我能提供什么价值

各维度允许 1–3 行。

Acceptance:
- 当真实素材足够时，除 `proposal.headline` 和固定合规声明之外，人物正文至少 3 行。
- 素材不足时允许少于 3 行，但不得编造空话凑行数。
- 同一行只合并同一核心维度。
- 单行有效宽度优先 12–20，21–25 只在语义完整时允许，25 为绝对上限。
- headline 位于人物正文之后、固定声明之前。
- 最终 bios 只有 `web/ip-policy-core.js` 有写权限，兼容/UI 层不得二次裁剪。

## 156 推荐脚本加载失败

Acceptance:
- 已存在脚本库数据时，推荐脚本入口必须可正常加载。
- 必须覆盖接口、数据库读取、推荐逻辑、前端渲染完整链路。
- 无 IP 方案与有 IP 方案两种路径均有明确可用行为。
- 错误态必须可诊断，不能只显示无上下文的“刷新后重试”。
- Production 当前 `script_library` 有数据时不得误判为空库。

## 157 IP 询问缺失问题

建立唯一的 `IP Profile Question Contract`。

规则：
- 已存在有效答案的字段可以跳过。
- 没有有效答案的必填/应收集字段必须逐个询问。
- 不得因为历史流程、代码分支或缓存而静默跳过。
- 用户可选“跳过/暂不回答”的字段必须显式记录缺失状态，不能伪装为已回答。

必须包含并验证表达风格问题：

“你希望自己的内容说起话来是什么感觉？可以选 1～2 个最像你的风格，也可以自己补充。这个选择会影响后续的脚本改写风格。”

Acceptance:
- 未收集过 `contentTone/scriptStyleGuide` 时必须询问。
- 答案保存到 canonical profile 字段。
- IP 资料中可查看。
- 脚本改写实际读取并使用该风格信息。
- 对所有 IP 问题做一次字段级审计，凡当前 profile 缺失且规则要求收集的字段都进入询问队列。

## 回归保护

必须新增自动测试覆盖：
- 城市 canonical 列表；
- 0 客户反馈不得生成多人反馈；
- 一句话 IP 禁止字段墙；
- 素材足够时简介正文 >= 3 行；
- 推荐脚本完整链路；
- 缺失 contentTone 必问、已有 contentTone 可跳过；
- 固定测试账号 `111111111` 的完整 Playwright 用户旅程。

## 非目标

- 本 change 不修改 Production 数据。
- 不重新设计已验收视觉风格。
- 不以某个测试账号的固定期望文本硬编码产品输出。
