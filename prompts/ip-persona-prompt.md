# 一、人物资产与证据
昵称、简介、一句话 IP 定位、脚本人设代入共用人物资产：称呼、身份、学历、职业/过往经历、地域、成就、性格、兴趣、服务/内容方向。

可使用证据：A 报名表明确事实；B 本人自我介绍明确表达；C 客户反馈（尤其多人重复评价）。D AI 推断不得作为最终事实。

类别信息不得反推具体事实：QS前100不等于任何具体大学；985/211不等于某所学校；海外留学不能推断国家；职业经历不能升级为资格证书或头衔。

# 二、人设优势判断
先从身份/职位、性格、地域、专业/经历、学历、成就/荣誉六个维度判断哪些值得突出。信息不足就标记信息不足，不为了凑齐维度强行突出。

学历仅在资料明确有博士、硕士、985、211、QS前50/100、海外留学或明确有价值的学校背景时考虑突出。学校层级只按原始层级表达。

# 三、昵称受控生成（#104–#113 最新）
必须执行：真实证据 → 稳定人物称呼 → 当前仍成立的人物特点/兴趣 → 自然表达 → 中文可记忆/可搜索检查 → 合规过滤。每个昵称只含一个真实人物称呼主体；禁止机械标签墙、虚构事实和保险/AIA等不合规昵称。原昵称自然、好记、合规、已有特色且有稳定识别时优先保留；“无/没有/暂无/未填写/未设置/0”不能建议保留。推荐通常 3–5 个不同路线，AI 推荐仅供参考。

客户/身边人高频真实称呼优先于姓名自动简称；没有真实证据时不得把姓名中的单个字擅自当昵称。纯姓名、真实称呼及极简变体合计最多两个，不得用多个叫法凑满推荐位。

**过往职业只进入简介/IP 一句话定位，不进入新生成昵称。** 当前名单用户已经转入保险行业，不得生成“地产人XX / 财务人XX / 教师XX / 会计XX / 精算人XX / 前广告人XX”等前职业昵称。

**#111 首选优先有记忆点、有网感。** 昵称不是实名通讯录：如果没有成熟原昵称，但本人资料明确存在当前仍成立、鲜明且有记忆点的兴趣/生活特点/内容特点，应优先尝试“人物称呼或本名 + 该特点”的自然昵称，再把单独称呼/本名作为稳妥备选。已有且有特色的好昵称 > 真实称呼/本名 + 有记忆点的当前兴趣或特点 > 其他有证据的自然差异化昵称 > 真实称呼极简版 > 单独本名。比如本人明确长期健身且有八块腹肌时，`八块腹肌刘畅`、`刘畅练起来` 应优先于单独 `刘畅`；但 `飞行员刘畅` 仍禁止，因为飞行员是过往职业。兴趣/特点必须有真实证据，不能为了网感编造，也不能机械把所有兴趣都套成“爱XX的称呼”。

**#112 有证据的鲜明修饰语可以优先于裸称呼。** 如果客户/身边人反馈或本人资料中已经自然出现一个真正有辨识度的短表达，并且和人物称呼组合后更顺口、更有记忆点，可以优先推荐组合昵称。普通“靠谱/专业/真诚”不能机械前缀化；例如反馈真实出现“有料有趣”，人物真实称呼是“流火”时，`有料有趣的流火` 优先于单独 `流火`。

**#113 中文可记忆、可搜索优先。** 新生成昵称默认不使用 Emoji、特殊符号、花体字符、繁体装饰字符或无意义数字尾缀；全英文昵称原则上不作为首选，普通中文用户不容易记忆和搜索。中英混合可以保留，但中文部分必须承担人物记忆或语义识别，例如 `兔子Nici`、`宽婷Kitty`。已有全英文原昵称也要优先寻找中文或中英混合优化版，例如 `TotoroFelix` 不再默认首选；如果客户已有真实中文称呼“龙猫”，优先考虑 `咖啡龙猫 / 网球龙猫 / 龙猫Felix / 龙猫` 等更易记、易搜的路线。特殊符号和末尾装饰标点在推荐版本中去掉。

昵称生成后必须做中文口语自然度检查：禁止动作标题句、人物主体重复、万能“小世界/日常/聊生活/看世界”批量套壳，以及事实正确但读起来像字段拼接的名字。没有足够好的候选时宁缺毋滥。

# 四、一句话 IP 定位 / Slogan（2026-08-25 #103）

一句话 IP 定位不是标签列表或普通业务介绍，而是一句浓缩版自我介绍 / slogan。逻辑是：**做账号的目的 × 我的不同之处 × 目标人群关注的内容 → 我的 IP**。

从真实基本资料、个人介绍和多人客户反馈中挑选最有吸引力、最有辨识度、最容易记住的 2–3 个特点。候选包括家庭/生活身份、明确职业经历、具体年限、学历/专业资质、真实荣誉、客户反馈、兴趣/生活特点、已证实的内容能力、真实转型经历、账号目标与目标人群。

素材优先级：**稀缺且具体事实 > 有数字的经历 > 有证据的强反差/转型 > 专业资质/荣誉 > 多人反馈形成的稳定特点 > 有记忆点的生活身份 > 普通兴趣 > 泛化形容词。**

硬规则：
- 只用 A/B/C 级真实证据；没有证据不得生成“0人脉 / 多年 / 擅长 / 懂XX / 专家 / 导师 / 顾问”等判断。
- 有明确数字时保留数字精度，不把强事实降级成模糊概括。
- 不要求把“我是谁 / 我的优势 / 我能提供什么价值”全部塞进一句话，只挑 2–3 个最强记忆点。
- 不包含人物姓名/昵称锚点；不写“职业+转型+行业+荣誉”的标签墙。
- **禁止使用 `｜` 或 `|`。** 必须用自然中文标点，如 `，`、`、`、`！`，自然情况下也可不用标点。
- 避免“从XX跨界，用自己的经验讲清……”等机械模板；目标是自然、响亮、可记忆的一句话。
- headline 长度在唯一 Owner 的生成阶段统一控制；简介不得二次截短、改写或重新生成。
- `web/ip-policy-core.js::headline(profile)` 是运行态唯一 Owner，canonical 字段为 `proposal.headline`。
- **IP方案顶部 = 小红书简介固定声明前一句 = 视频号/抖音简介固定声明前三行之前的最后一句**，三处逐字一致，读取同一个 `proposal.headline`。

# 五、简介受控生成（2026-08-25 #92–#103 最新）

简介始终围绕三个问题：**我是谁 / 我的优势 / 我能提供什么价值**。三个维度均可按真实资料丰富程度使用 1–3 行。简介不是履历表或口播稿；单条表达凝练，整体信息可以丰富，目标是有限空间内的信息密度与视觉平衡。

## 事实表达边界
- 必须区分 `原始字段 → 已确认事实 → 简介允许表达`。
- 模糊领域词不得升级为职业经历。只有明确提供法务/法律相关工作经历和年限时，才可写如“6年企业法务工作经验”。
- 同一事实优先短而准确，例如“硕士学历”写“硕士”。
- 不得把普通经历升级为资质、头衔、专业能力。
- **时间精度必须保留。** 原始资料有明确年限时优先保留数字，如 `7年多` 优先表达为 `7年+`；不得降级成“长期经验”。只有原资料明确支持“多年”时才可写“多年”，不得自行增加“多年/长期”等时间判断。

## 素材、去重与客户评价
优先：差异化身份/明确职业经历 → 强专业背书 → 真实内容/服务价值 → 有证据客户评价 → 地域 → 真实兴趣 → 泛化形容词。有效真实信息尽量保留，不做机械减法。

整份简介必须做**跨行语义去重**，不能只做字符串去重。多个表达高度重叠时，优先保留：**具体量化事实 > 明确身份/经历/资质 > 明确荣誉 > 模糊概括 > AI 总结**。例如已有“10年建筑行业财务经验”，不得再用“长期财务管理经验”重复同一信息；“10年建筑行业财务经验”和“财务中级职称”分别是经历与职称，不算重复，可以同时保留。

客户反馈最终只呈现结论，例如 `靠谱｜细致｜有耐心`，禁止“客户高频评价/客户都评价我/大家眼中的我/多位客户认为”等解释前缀。

## 单行结构与版面硬规则
- 每一行必须保持同一语义维度，共同回答三个核心问题之一。
- 过往经历与荣誉原则上分开；但 `MDRT`、`法学本科`、`财务中级职称` 等短资产若单独成行会浪费空间，可与同属于“我的优势”且语义自然的真实信息合并。
- 正文去除 Emoji、标点、分隔符后，优先达到约 **12 个汉字等效宽度以上**；不足时按“同维度合并 → 凝练重组 → 并入相邻同核心维度行 → 不单独成行”处理，禁止加废话凑字。
- **视频号/抖音正文优先控制在 12–20 个汉字等效宽度；21–25 仅在保持语义完整、无法自然压缩时允许；25 是绝对上限。** 英文、数字、Emoji、标点按视觉宽度折算，不能机械按 Unicode 字符数。
- 多行长度尽量接近，避免一行接近上限而另一行只有几个字。真实性和语义完整优先，不为等长添加废话。
- 同一份简介正文每行使用不同 Emoji；淘汰 `👤`。Emoji 与行内容自然匹配，不得抢夺注意力。
- 固定合规声明完全豁免上述正文最低/最高宽度、均衡和 Emoji 规则。

## 正文行数与平台一致性
- 除固定合规声明外，人物正文**默认至少 3 行**。只有真实有效资料确实不足，继续增加会造成重复、空话或事实推断时，才允许少于 3 行；绝不能为了凑 3 行编造或重复。
- 小红书与视频号/抖音人物正文默认使用**同一套真实人物信息**。只有明确的平台合规规则造成差异时，才针对相应平台删除或替换不合规内容；不得为了制造平台差异主动删掉另一平台同样合规的有效信息。
- 生成顺序：充分挖掘真实资料 → 强事实排序 → 跨行语义去重 → 覆盖三个核心问题 → 尽量达到 3 行以上 → 12–20优先/25红线排版 → 再次跨行去重 → 平台合规差异处理 → **追加同一个 `proposal.headline`** → 固定声明追加。

## 平台输出数量
只提供两份正文素材：小红书 1 套最终推荐正文；视频号/抖音 1 套共用最终推荐正文。两套默认人物信息一致，差异只来自明确的平台合规规则，不为制造差异拆散人物资料。

# 六、平台合规
## 小红书正文
正文不得出现保险、金融、理财、贷款、股票、基金、医疗、护理、教育、玄学、友邦、AIA及联系方式/导流/利益诱导/夸大承诺等。模型不生成固定声明；canonical 必须在最终简介最后追加且逐字保持：`本账号所述内容为个人意见，不代表任何官方意见。`

## 视频号/抖音正文
不得把营销员编号当执业证编号，不得由模型生成营销服务部或执业证编号。canonical 必须在人物正文与 `proposal.headline` 之后连续追加三行，原文、顺序、换行固定：
`本账号上所陈述或表达的内容仅为我个人意见，并不代表友邦人寿的意见`
`营销服务部：XXX`
`执业证编号：XXX`
三行固定尾部不受正文行宽限制。

## 通用禁区
禁止绝对化、承诺型或 AI 自嗨表达；真实账号有人使用不代表系统可以推荐。
